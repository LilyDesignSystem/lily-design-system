医疗用户界面

拨用 Lily 构建临床软件个团队看个指南：临床门户、检验结果搭报告、处方搭给药管理、决策支持搭医院仪表板。

搿个页面个翻译是呒没经过审校个机器翻译草稿。英文页面才是权威版本。

Lily 做啥，勿做啥

Lily 提供个是显示契约：对临床界面里向一直重复出现个物事，提供语义化标记、ARIA、键盘行为搭类名钩子。伊勿提供临床逻辑、临床内容或者监管声明。

监管。计算评分、生长百分位、剂量或者药物相互作用个软件，一般属于医疗器械。Lily 特意勿计算其中任何一样。要是侬个产品受监管，伊个可用性工程文档（IEC 62366-1、FDA 个人因指南、EU MDR）由侬负责。Lily 个测试、自家评估个无障碍符合性报告搭屏幕阅读器矩阵好当作搿份文档里向个证据；但是呒没一样是符合性声明，而且搿个矩阵现在还呒没结果。

警报：只对危急个情况再打断用户

警报疲劳是安全问题：要是每条警报侪打断用户，大家就会拿伊拉全部关脱。AHRQ 个指南是按严重程度拿警报分级，只让严重个警报打断用户。

  • 信息（indicator="info"）：内联显示辣任务旁边，是页面里向个决策支持卡片。
  • 警告（indicator="warning"）：看得见但是勿阻断操作，用同样一张卡片，样式更加醒目；勿用模态框。
  • 危急（indicator="critical"）：拿卡片放进警报对话框，并且提供 overrideReasons，介样关闭个辰光就会要求填写原因。
  • 决策支持卡片本身从来勿是实时区域。新个危急卡片是靠拿焦点移进对话框来通知，而勿是靠 aria-live。
  • 当卡片所回应个事件再次发生，就拿卡片移脱，并且记录每一次结果（已接受，或者附原因被覆盖）。

认错病人个差错：要核对，勿要限制

  • 凡是显示病人数据个地方，侪要显示两个标识：姓名加出生日期，以及用对应 view 组件显示个国民身份标识（The Joint Commission, Quick Safety 45）。
  • 辣每一个针对某位病人记录操作个界面上侪用病人横幅，并且保持伊一直看得见。
  • 辣对横幅所示记录以外个另一份记录执行操作之前，要用姓名、出生日期搭标识确认。
  • 关于患者以外之人个条目（父母个病史、胎儿、捐献者）先用文字说明是啥人个：为记录项设置 subjectLabel （“母亲”），迭样亲属个诊断绝勿会被读成患者个诊断（openEHR PARTY_RELATED，FHIR FamilyMemberHistory).
  • 勿要限制临床医生好打开几化记录：一项牵涉 3,356 名临床医生个随机试验（JAMA，2019）发现，介样做并呒没减少认错病人个医嘱，而且大家会想办法绕过限制。
  • 针对一条记录个操作菜单先说出迭条记录，在 subjectLabel 上使用 context-menu 或 dropdown-menu （“Ada Lovelace，血压 11月3日”）：一个勿可交互个首部分，同时也是菜单个无障碍名称。
  • 按操作个作用拨每个操作分级，并在执行前让级别可见。 常规 （查看、打印）立即执行。 记录型 说明伊将写入记录个内容（“为本次就诊添加一条备注”）。 临床型 （停用、取消医嘱）再次确认，放在 alert-dialog 中，其确认按钮是动词（“停用”），绝勿是“确定”或“是”。 披露型 （紧急访问、在诊疗团队之外共享）先要求填写理由并记录下来。
  • 同时打开多份记录时（标签页、窗口、分屏），每个标签页个可见文字搭无障碍名称都包含患者姓名搭第二个标识符，活动面板重复显示横幅，任何操作都勿会作用于其面板之外个患者。
  • 把记录将归属个地点（登录时选择个病区、门诊或机构）以文字显示在页眉中，并把更改伊设为一个明确个操作。
  • 在横幅中显示当前就诊，或“无当前就诊”。需要就诊个表单会说明迭一点并提议开始一次就诊，而勿是在保存时失败。

病人横幅

搿个组合记载辣 medical-banner，SvelteKit 示例应用辣 /patient-banner 有一个跑得通个页面：

  • 两个标识，以及出生日期旁边个年龄；
  • 过敏信息通过过敏列表显示，让“无已知过敏”“未记录”搭“无法获取”看上去从来勿会一样；
  • 缺失个值用文字表达（“勿详”），勿好用问号、破折号或者空单元格；
  • 已故病人：为主题提供 data-deceased，并且显示一行看得见个文字，绝对勿好光靠颜色；
  • 任何宽度下侪勿截断、勿裁切、勿隐藏任何字段，而是自动换行。
  • 患者标记（“需要口译员”、“感染风险”）是带标签个 tag-group 由文字组成，绝勿只用图标或颜色，并在横幅换行时保持可见。

检验结果

  • 无论结果是从啥个系统来个，结果只有一种显示方式：观察结果视图。
  • 标志是来自侬个翻译个文字（flagLabel），FHIR 解释代码则作为 data-interpretation 提供拨主题。
  • 拿新结果搭之前个结果分开，并且显示趋势（迷你折线图，或者附数据表个折线图）：临床医生关注个是显著变化，而勿光是范围。
  • 从来呒没记录过个结果搭无法获取个结果是勿同个状态，要用勿同个文字表达。
  • 未知勿等于正常。参考范围缺失、仍在加载或无法读取个结果呒没解读，并会说明迭一点； observation-view 绝勿自行推断，因此有范围但呒没 interpretation 个结果勿显示任何标记。
  • 超出量程个结果是仪器个极限加比较符（“> 33.3 mmol/L”： formatQuantity 配合 ">"）再加上侬个危急标记，绝勿是光秃秃个数字。近似值保留伊个 ≈（"~").
  • 把其他具名范围（“危急：低于 2.5”）作为 ranges拨出，每个各占一部分。
  • 更正或修改过个结果保留被替换个值，放在 <del>中，并用侬个文字说明何时更改（previousValue， previousLabel），让读过旧值个临床人员知道伊已更改。
  • 区间测量说明其时长搭函数（“均值，24 小时”），测量个状态搭方法（“坐位，大号袖带”）以可见文字显示在旁边，绝勿只是工具提示（openEHR INTERVAL_EVENT， state， protocol).
  • 趋势需要可比个数据点：勿要在侬个最小点数以下画线，在方法或检测改变处断开线条，并用文字说明方向搭含义（“下降，好转”）。
  • 以一种单位制录入个生命体征可以在旁边以侬个文字显示另一种（“70 kg（154 lb）”）；Lily 勿做任何换算，所以请说明侬个舍入方式。录入数量请使用 quantity-input-div，其数值遵循每个单位个限制。
  • 生长曲线是一个 line-chart ，侬个百分位线作为数据系列，加上孩子个数据点及其年龄搭数值个数据表；Lily 勿计算百分位，也勿附带生长参考标准。

药品

  • 通用名用小写，但是 FDA 搭 ISMP 清单，或者侬所辣国家个清单（澳大利亚搭加拿大发布了各自个清单）里向个 tall man 大写字母除外。辣 nameSegments 里标记伊拉；Lily 从来勿会猜。
  • 用 formatQuantity 书写规格：末尾勿带零，前头带零，单位前头加不换行空格。
  • 保留结果个比较符：formatQuantity(5, "mmol/L", locale, "<") 写作“<5 mmol/L”。FHIR 个 Quantity.comparator 写作 <、≤、≥ 或者 >；漏脱伊，“小于 5”就变成“5”。
  • 写 mL，勿好写 cc，并且避免 ISMP 易错缩写清单上个所有缩写。
  • 决勿截断药品个名称或者剂量。

日期搭辰光

  • 月份用文字书写，让日期勿会有两种读法（Intl.DateTimeFormat 搭配 month: "short"）。
  • 要有意识地选时钟制式：明确传进 hourCycle。NHS 要求用 24 小时制；搿个是英国个规定，勿是全世界个规定，所以 Lily 从来勿会代侬选。
  • 年龄通过 ageParts() 依照 Common User Interface 个分段；用其他惯例个服务就传进自家个文字。
  • 只知道到月或年个日期就保持迭样：用 date-field precision="month" 或 "year"询问，存储为 2019-03 或 2019，并用 formatPartialDate()书写。绝勿编造日期。
  • 一段时长是 duration-view，即一个 <time datetime="P3DT4H"> ，包含侬个文字，来自 durationParts() 搭 Intl.DurationFormat.

仪表板

  • 病区看板或者指挥中心屏幕更新交关频繁。勿要每趟变化侪播报：保留一个礼貌（polite）个摘要区域（“3 张空床，2 位待出院”），让大家自家去看看板。
  • 看板上个每一种状态（床位已清洁、已占用、已封闭）侪是文字，或者带文字个 data-* 状态，绝对勿好光靠颜色。
  • 任何东西都勿闪烁（WCAG 2.2.2、2.3.1），按定时器更新个看板有暂停控件，或只在请求时更新；更新绝勿移动焦点。逾期个条目用文字说明（“已等待超过 20 分钟”），并设置 data-overdue.
  • 计数或比率显示其分母（“68 中个 12”），并链接到其背后个列表。
  • 列表或时间线说明伊是啥个视图：显示啥、顺序搭时间窗口、隐藏了啥及原因，以及哪些来源呒没响应。来自未响应来源个空列表并勿能证明啥都勿存在。
  • 提醒列表是一个 record-list ，其各项带有到期日期（review-date）搭以文字表示个到期状态，并设置 data-due；生成伊个规则由侬决定。

表单

  • 答案为“是”、“否”或“未询问”个问题是一个 radio-group ，有三个答案，起初都勿选中，绝勿用复选框：复选框无法区分“否认”搭“从未询问”。系统回顾是每个身体系统一个 fieldset ，而“其余均无”按钮只设置未作答个项。
  • 有一系列答案个问题（药物、地址）是一个 repeatable-fieldset：添加或删除一项时，焦点随之移动，每个删除按钮都以其对应项命名。
  • 带小数逗号个数字：用 Intl.NumberFormat 显示，在 type="number" 勿接受逗号个地方，用带 inputmode="decimal" 个文本框接收，并在侬个代码中解析。绝勿更改用户输入个值，即使是为了限制在范围内：超出范围个值是用户能看到个错误。
  • 一次只渲染部分选项个长列表会在每个选项上设置 aria-setsize 搭 aria-posinset ，并记住页内查找看勿到其余部分。

记录、笔记及其来源

  • 在行之前说明列表或网格是啥个视图：时间窗口搭顺序、省略了啥及原因，以及哪些来源呒没响应（“最近 12 个月，最新个在前。全科医生记录未响应。”）。为 record-list 搭 timeline-list 设置 coverageLabel，并为 data-grid 辅助组件设置伊个 coverageLabel。来自未响应来源个空列表会用文字说明，绝勿会被读成“呒没记录”。
  • 用 record-provenance-view说明记录来自何处以及是否为最终版本：已签名、等待签名、已修订、已保存在本设备且尚未发送。未签名个草稿绝勿能看起来像已签名。
  • 关于他人（父母、胎儿、捐献者）个条目先说明是啥人个，使用记录项个 subjectLabel.
  • 被保留个条目以侬个文字留在列表中（“受限：侬无权查看”），录入错误个条目保留删除线并标注“录入错误”：为 record-list-item 或 timeline-list-item 设置 entryState 搭 entryStateLabel。绝勿悄悄删除其中任何一个，因为空缺会被读成“啥都没发生”。
  • 在临床笔记中，用 data-source 搭可见文字标明每段文字个来源（键入、口述、模板、沿用复制、生成），使复制或生成个文字绝勿会被当作今天个检查。
  • 无法加载个部分为 unavailable ，用侬个文字说明，并附重试按钮；技术代码如需显示，放在展开控件后面。由用户操作导致个失败会被播报，同时说明记录现在个值；页面加载时个失败则勿播报。
  • 医嘱个历史是一个 timeline-list，每个步骤一项（已计划、已排期、执行中、已暂停、已完成、已取消），附时间搭原因，当前状态也显示在该项上。

编码值

  • 显示 Coding.display；呒没就显示 CodeableConcept.text；两样侪呒没就显示 system|code。决勿留空单元格。
  • 提供一个控件，辣每个值旁边显示代码系统搭代码，比方写“显示代码”个切换按钮。隐藏起来个代码辣显示之前勿进阅读顺序。
  • 用文档个语言（lang）标记临床文字，伊可能搭界面个语言勿一样。翻译界面，决勿翻译临床内容。
  • Lily 勿附带术语库：呒没 SNOMED CT、LOINC、ATC 或者 UCUM 查询。照文档所写如实写。SvelteKit 示例个 /patient-summary 页面展示了迭个模式。

Lily 勿会做个事体

  • 计算早期预警评分、生长百分位、剂量或者参考范围。
  • 附带药品数据库、tall man 清单，或者 SNOMED CT、ICD、LOINC、UCUM 代码。
  • 复制有许可个量表（Wong-Baker FACES）或者其他机构个设计（NEWS2 图表）。
  • 限制同时打开个记录数量。
  • 根据范围推断解读、换算单位，或解析相对日期（“下周二”）。
  • 用开关表示“是、否或未知”：ARIA 个 switch 呒没第三种状态，所以要用三个单选按钮。
