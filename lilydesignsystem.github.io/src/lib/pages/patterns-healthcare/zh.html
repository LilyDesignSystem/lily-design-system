医疗用户界面

面向使用 Lily 构建临床软件的团队的指南：临床门户、检验结果与报告、处方与给药管理、决策支持和医院仪表板。

本页的翻译是未经审校的机器翻译草稿。英文页面才是权威版本。

Lily 做什么，不做什么

Lily 提供的是显示契约：针对临床界面中反复出现的内容，提供语义化标记、ARIA、键盘行为和类名钩子。它不提供临床逻辑、临床内容或监管声明。

监管。计算评分、生长百分位、剂量或药物相互作用的软件，通常属于医疗器械。Lily 有意不计算其中任何一项。如果你的产品受监管，其可用性工程文档（IEC 62366-1、FDA 的人因指南、EU MDR）由你负责。Lily 的测试、自我评估的无障碍符合性报告和屏幕阅读器矩阵可以作为该文档中的证据；但其中任何一项都不是符合性声明，而且该矩阵目前还没有结果。

警报：只对危急情况打断用户

警报疲劳是安全问题：当每条警报都打断用户时，人们会把它们全部关掉。AHRQ 的指南是按严重程度对警报分级，只让严重的警报打断用户。

  • 信息（indicator="info"）：内联显示在任务旁边，是页面中的决策支持卡片。
  • 警告（indicator="warning"）：可见但不阻断操作，使用同一张卡片，样式更醒目；不使用模态框。
  • 危急（indicator="critical"）：把卡片放进警报对话框，并提供 overrideReasons，这样关闭时会要求填写原因。
  • 决策支持卡片本身绝不是实时区域。新的危急卡片通过把焦点移入对话框来告知，而不是通过 aria-live。
  • 当卡片所回应的事件再次发生时，移除该卡片，并记录每一次结果（已接受，或附原因被覆盖）。

认错患者的差错：要核对，不要限制

  • 凡是显示患者数据的地方，都要显示两个标识：姓名加出生日期，以及用对应 view 组件显示的国民身份标识（The Joint Commission, Quick Safety 45）。
  • 在每一个针对某位患者记录进行操作的界面上都使用患者横幅，并保持其始终可见。
  • 在对横幅所示记录之外的其他记录执行操作之前，要用姓名、出生日期和标识进行确认。
  • 关于患者以外之人的条目（父母的病史、胎儿、捐献者）先用文字说明是谁的：为记录项设置 subjectLabel （“母亲”），这样亲属的诊断绝不会被读成患者的诊断（openEHR PARTY_RELATED，FHIR FamilyMemberHistory).
  • 不要限制临床医生可以打开的记录数量：一项涉及 3,356 名临床医生的随机试验（JAMA，2019）发现，这样做并未减少认错患者的医嘱，而且人们会想办法绕过限制。
  • 针对一条记录的操作菜单先说出这条记录，在 subjectLabel 上使用 context-menu 或 dropdown-menu （“Ada Lovelace，血压 11月3日”）：一个不可交互的首部分，同时也是菜单的无障碍名称。
  • 按操作的作用给每个操作分级，并在执行前让级别可见。 常规 （查看、打印）立即执行。 记录型 说明它将写入记录的内容（“为本次就诊添加一条备注”）。 临床型 （停用、取消医嘱）再次确认，放在 alert-dialog 中，其确认按钮是动词（“停用”），绝不是“确定”或“是”。 披露型 （紧急访问、在诊疗团队之外共享）先要求填写理由并记录下来。
  • 同时打开多份记录时（标签页、窗口、分屏），每个标签页的可见文字和无障碍名称都包含患者姓名和第二个标识符，活动面板重复显示横幅，任何操作都不会作用于其面板之外的患者。
  • 把记录将归属的地点（登录时选择的病区、门诊或机构）以文字显示在页眉中，并把更改它设为一个明确的操作。
  • 在横幅中显示当前就诊，或“无当前就诊”。需要就诊的表单会说明这一点并提议开始一次就诊，而不是在保存时失败。

患者横幅

该组合记录在 medical-banner 中，SvelteKit 示例应用在 /patient-banner 有一个可运行的页面：

  • 两个标识，以及出生日期旁边的年龄；
  • 过敏信息通过过敏列表显示，使“无已知过敏”“未记录”和“不可用”看起来绝不相同；
  • 缺失的值用文字表达（“未知”），绝不使用问号、破折号或空单元格；
  • 已故患者：为主题提供 data-deceased，并显示一行可见的文字，绝不只靠颜色；
  • 任何宽度下都不截断、不裁切、不隐藏任何字段，而是自动换行。
  • 患者标记（“需要口译员”、“感染风险”）是带标签的 tag-group 由文字组成，绝不只用图标或颜色，并在横幅换行时保持可见。

检验结果

  • 无论结果来自哪个系统，结果只有一种显示方式：观察结果视图。
  • 标志是来自你的翻译的文字（flagLabel），FHIR 解释代码则作为 data-interpretation 提供给主题。
  • 把新结果与之前的结果分开，并显示趋势（迷你折线图，或附数据表的折线图）：临床医生关注的是显著变化，而不只是范围。
  • 从未记录过的结果和无法获取的结果是不同的状态，要用不同的文字表达。
  • 未知不等于正常。参考范围缺失、仍在加载或无法读取的结果没有解读，并会说明这一点； observation-view 绝不自行推断，因此有范围但没有 interpretation 的结果不显示任何标记。
  • 超出量程的结果是仪器的极限加比较符（“> 33.3 mmol/L”： formatQuantity 配合 ">"）再加上你的危急标记，绝不是光秃秃的数字。近似值保留它的 ≈（"~").
  • 把其他具名范围（“危急：低于 2.5”）作为 ranges给出，每个各占一部分。
  • 更正或修改过的结果保留被替换的值，放在 <del>中，并用你的文字说明何时更改（previousValue， previousLabel），让读过旧值的临床人员知道它已更改。
  • 区间测量说明其时长和函数（“均值，24 小时”），测量的状态和方法（“坐位，大号袖带”）以可见文字显示在旁边，绝不只是工具提示（openEHR INTERVAL_EVENT， state， protocol).
  • 趋势需要可比的数据点：不要在你的最小点数以下画线，在方法或检测改变处断开线条，并用文字说明方向和含义（“下降，好转”）。
  • 以一种单位制录入的生命体征可以在旁边以你的文字显示另一种（“70 kg（154 lb）”）；Lily 不做任何换算，所以请说明你的舍入方式。录入数量请使用 quantity-input-div，其数值遵循每个单位的限制。
  • 生长曲线是一个 line-chart ，你的百分位线作为数据系列，加上孩子的数据点及其年龄和数值的数据表；Lily 不计算百分位，也不附带生长参考标准。

药品

  • 通用名用小写，但 FDA 和 ISMP 清单，或你所在国家清单（澳大利亚和加拿大发布了各自的清单）中的 tall man 大写字母除外。在 nameSegments 中标记它们；Lily 绝不猜测。
  • 用 formatQuantity 书写规格：末尾不带零，前面带零，单位前加不换行空格。
  • 保留结果的比较符：formatQuantity(5, "mmol/L", locale, "<") 写作“<5 mmol/L”。FHIR 的 Quantity.comparator 写作 <、≤、≥ 或 >；丢掉它会把“小于 5”变成“5”。
  • 写 mL，绝不写 cc，并避免 ISMP 易错缩写清单上的所有缩写。
  • 绝不截断药品的名称或剂量。

日期和时间

  • 月份用文字书写，使日期不会有两种读法（Intl.DateTimeFormat 配合 month: "short"）。
  • 有意识地选择时钟制式：明确传入 hourCycle。NHS 要求使用 24 小时制；那是英国的规定，不是全世界的规定，所以 Lily 绝不替你选择。
  • 年龄通过 ageParts() 遵循 Common User Interface 的分段；采用其他惯例的服务可传入自己的文字。
  • 只知道到月或年的日期就保持这样：用 date-field precision="month" 或 "year"询问，存储为 2019-03 或 2019，并用 formatPartialDate()书写。绝不编造日期。
  • 一段时长是 duration-view，即一个 <time datetime="P3DT4H"> ，包含你的文字，来自 durationParts() 和 Intl.DurationFormat.

仪表板

  • 病区看板或指挥中心屏幕更新频繁。绝不要对每次变化都播报：保留一个礼貌（polite）的摘要区域（“3 张空床，2 位待出院”），让人们自己阅读看板。
  • 看板上的每一种状态（床位已清洁、已占用、已封闭）都是文字，或带有文字的 data-* 状态，绝不只靠颜色。
  • 任何东西都不闪烁（WCAG 2.2.2、2.3.1），按定时器更新的看板有暂停控件，或只在请求时更新；更新绝不移动焦点。逾期的条目用文字说明（“已等待超过 20 分钟”），并设置 data-overdue.
  • 计数或比率显示其分母（“68 中的 12”），并链接到其背后的列表。
  • 列表或时间线说明它是什么的视图：显示什么、顺序和时间窗口、隐藏了什么及原因，以及哪些来源没有响应。来自未响应来源的空列表并不能证明什么都不存在。
  • 提醒列表是一个 record-list ，其各项带有到期日期（review-date）和以文字表示的到期状态，并设置 data-due；生成它的规则由你决定。

表单

  • 答案为“是”、“否”或“未询问”的问题是一个 radio-group ，有三个答案，起初都不选中，绝不用复选框：复选框无法区分“否认”和“从未询问”。系统回顾是每个身体系统一个 fieldset ，而“其余均无”按钮只设置未作答的项。
  • 有一系列答案的问题（药物、地址）是一个 repeatable-fieldset：添加或删除一项时，焦点随之移动，每个删除按钮都以其对应项命名。
  • 带小数逗号的数字：用 Intl.NumberFormat 显示，在 type="number" 不接受逗号的地方，用带 inputmode="decimal" 的文本框接收，并在你的代码中解析。绝不更改用户输入的值，即使是为了限制在范围内：超出范围的值是用户能看到的错误。
  • 一次只渲染部分选项的长列表会在每个选项上设置 aria-setsize 和 aria-posinset ，并记住页内查找看不到其余部分。

记录、笔记及其来源

  • 在行之前说明列表或网格是什么的视图：时间窗口和顺序、省略了什么及原因，以及哪些来源没有响应（“最近 12 个月，最新的在前。全科医生记录未响应。”）。为 record-list 和 timeline-list 设置 coverageLabel，并为 data-grid 辅助组件设置它的 coverageLabel。来自未响应来源的空列表会用文字说明，绝不会被读成“没有记录”。
  • 用 record-provenance-view说明记录来自何处以及是否为最终版本：已签名、等待签名、已修订、已保存在本设备且尚未发送。未签名的草稿绝不能看起来像已签名。
  • 关于他人（父母、胎儿、捐献者）的条目先说明是谁的，使用记录项的 subjectLabel.
  • 被保留的条目以你的文字留在列表中（“受限：你无权查看”），录入错误的条目保留删除线并标注“录入错误”：为 record-list-item 或 timeline-list-item 设置 entryState 和 entryStateLabel。绝不悄悄删除其中任何一个，因为空缺会被读成“什么都没发生”。
  • 在临床笔记中，用 data-source 和可见文字标明每段文字的来源（键入、口述、模板、沿用复制、生成），使复制或生成的文字绝不会被当作今天的检查。
  • 无法加载的部分为 unavailable ，用你的文字说明，并附重试按钮；技术代码如需显示，放在展开控件后面。由用户操作导致的失败会被播报，同时说明记录现在的值；页面加载时的失败则不播报。
  • 医嘱的历史是一个 timeline-list，每个步骤一项（已计划、已排期、执行中、已暂停、已完成、已取消），附时间和原因，当前状态也显示在该项上。

编码值

  • 显示 Coding.display；没有则显示 CodeableConcept.text；两者都没有则显示 system|code。绝不留空单元格。
  • 提供一个控件，在每个值旁边显示代码系统和代码，例如标有“显示代码”的切换按钮。隐藏的代码在显示之前不进入阅读顺序。
  • 用文档的语言（lang）标记临床文本，它可能与界面语言不同。翻译界面，绝不翻译临床内容。
  • Lily 不附带术语库：没有 SNOMED CT、LOINC、ATC 或 UCUM 查询。照文档所写如实书写。SvelteKit 示例的 /patient-summary 页面展示了这一模式。

Lily 不做什么

  • 计算早期预警评分、生长百分位、剂量或参考范围。
  • 附带药品数据库、tall man 清单，或 SNOMED CT、ICD、LOINC、UCUM 代码。
  • 复制受许可的量表（Wong-Baker FACES）或其他机构的设计（NEWS2 图表）。
  • 限制同时打开的记录数量。
  • 根据范围推断解读、换算单位，或解析相对日期（“下周二”）。
  • 用开关表示“是、否或未知”：ARIA 的 switch 没有第三种状态，所以要用三个单选按钮。
