警示：只係對危急情況先打斷用戶

警示疲勞係安全問題：如果每個警示都打斷用戶，人哋就會全部閂咗佢。AHRQ 嘅指引係按嚴重程度將警示分級，只係畀嚴重嘅警示打斷用戶。

  • 資訊（indicator="info"）：內嵌喺工作旁邊，係頁面入面嘅決策支援卡片。
  • 警告（indicator="warning"）：睇得到但唔會阻擋操作，用同一張卡片，樣式更加顯眼；唔用彈出視窗。
  • 危急（indicator="critical"）：將卡片放入警示對話框，並提供 overrideReasons，咁樣關閉嗰陣就會要求填寫原因。
  • 決策支援卡片本身永遠唔係即時區域。新嘅危急卡片係靠將焦點移入對話框嚟通知，而唔係靠 aria-live。
  • 當卡片所回應嘅事件再次發生，就移除張卡片，並記錄每次結果（已接受，或者附原因被覆蓋）。

認錯病人嘅差錯：要核對，唔好限制

  • 凡係顯示病人資料嘅地方，都要顯示兩個識別資料：姓名加出生日期，以及用對應 view 組件顯示嘅國民身份識別號碼（The Joint Commission, Quick Safety 45）。
  • 喺每個針對某位病人記錄操作嘅畫面都用病人橫幅，並保持佢一直睇得到。
  • 喺對橫幅所示記錄以外嘅另一份記錄執行操作之前，要用姓名、出生日期同識別號碼確認。
  • 關於病人以外嘅人嘅條目（父母嘅病史、胎兒、捐贈者）會先用文字講明係邊個嘅：幫記錄項設定 subjectLabel （「母親」），咁親屬嘅診斷就永遠唔會被讀成病人嘅（openEHR PARTY_RELATED，FHIR FamilyMemberHistory).
  • 唔好限制臨床人員可以打開幾多份記錄：一項涉及 3,356 名臨床人員嘅隨機試驗（JAMA，2019）發現，咁做並冇減少認錯病人嘅醫囑，而且人哋會想辦法繞過限制。
  • 針對一份記錄嘅操作選單會先講出呢份記錄，喺 subjectLabel 上面用 context-menu 或 dropdown-menu （「Ada Lovelace，血壓 11月3日」）：一個唔可以互動嘅第一部分，同時亦係選單嘅無障礙名稱。
  • 按每個操作做咩嚟分級，喺執行之前令級別睇得到。 日常 （睇、列印）即刻執行。 記錄類 講明會寫咩入記錄（「幫今次就診加一條備註」）。 臨床類 （停用、取消醫囑）會再問多次，放喺 alert-dialog 入面，確認掣係動詞（「停用」），永遠唔係「確定」或者「係」。 披露類 （緊急存取、喺護理團隊以外分享）會先要求原因並記低。
  • 同時打開幾份記錄嗰陣（分頁、視窗、分割面板），每個分頁嘅可見文字同無障礙名稱都包括病人姓名同第二個識別碼，活動面板會重複顯示橫幅，冇任何操作會作用喺佢面板以外嘅病人身上。
  • 將記錄會歸屬嘅地點（登入時揀嘅病房、診所或者機構）以文字顯示喺頁首，並將更改佢設定為一個明確嘅操作。
  • 喺橫幅顯示目前嘅就診，或者「冇目前就診」。需要就診嘅表格會講明，並提議開始一次就診，而唔係喺儲存時失敗。

病人橫幅

呢個組合記載喺 medical-banner，SvelteKit 示範應用程式喺 /patient-banner 有一個行得通嘅頁面：

  • 兩個識別資料，以及出生日期旁邊嘅年齡；
  • 過敏資料透過過敏列表顯示，等「無已知過敏」、「未有記錄」同「無法提供」永遠唔會睇落一樣；
  • 缺失嘅值用文字表達（「不詳」），唔好用問號、破折號或者空白儲存格；
  • 已身故病人：為主題提供 data-deceased，並顯示一行睇得到嘅文字，絕對唔可以淨係靠顏色；
  • 任何闊度都唔會截斷、裁切或者隱藏任何欄位，而係自動換行。
  • 病人標示（「需要傳譯員」、「感染風險」）係有標籤嘅 tag-group ，由文字組成，永遠唔只係圖示或者顏色，而且橫幅換行時都保持睇得到。

檢驗結果

  • 無論結果嚟自邊個系統，結果只有一種顯示方式：觀察結果檢視。
  • 標記係來自你嘅翻譯嘅文字（flagLabel），FHIR 解讀代碼就以 data-interpretation 提供畀主題。
  • 將新結果同之前嘅結果分開，並顯示趨勢（迷你折線圖，或者附數據表嘅折線圖）：臨床人員留意嘅係顯著變化，而唔只係範圍。
  • 從來未記錄過嘅結果同無法取得嘅結果係唔同嘅狀態，要用唔同嘅文字表達。
  • 唔知唔等於正常。參考範圍冇咗、仲載入緊或者讀唔到嘅結果冇解讀，並會講明； observation-view 永遠唔會自行推斷，所以有範圍但冇 interpretation 嘅結果唔會顯示任何標示。
  • 超出量程嘅結果係儀器嘅極限加比較符（「> 33.3 mmol/L」： formatQuantity 配合 ">"）同埋你嘅危急標示，永遠唔係一個淨數字。近似值保留佢嘅 ≈（"~").
  • 將其他有名嘅範圍（「危急：低過 2.5」）作為 ranges提供，每個自成一部分。
  • 更正或者修改過嘅結果會保留被取代嘅值，放喺 <del>入面，並用你嘅文字講明幾時改咗（previousValue， previousLabel），等睇過舊值嘅臨床人員知道佢改咗。
  • 區間量度會講明時長同函數（「平均值，24 小時」），量度嘅狀態同方法（「坐低，大號袖帶」）係旁邊睇得到嘅文字，永遠唔只係工具提示（openEHR INTERVAL_EVENT， state， protocol).
  • 趨勢需要可以比較嘅數據點：唔好喺你嘅最少點數以下畫線，喺方法或者檢驗改變嘅地方斷開條線，並用文字講出方向同意思（「下降，好轉」）。
  • 用一種單位制輸入嘅生命徵象可以喺旁邊用你嘅文字顯示另一種（「70 kg（154 lb）」）；Lily 唔會做任何換算，所以請講明你點樣四捨五入。輸入數量請用 quantity-input-div，佢嘅數字跟每個單位嘅限制。
  • 生長曲線係一個 line-chart ，你嘅百分位線作為數據系列，加埋小朋友嘅數據點同年齡及數值嘅數據表；Lily 唔計百分位，亦都唔附帶生長參考標準。

藥物

  • 通用名用小寫，但 FDA 同 ISMP 清單，或者你所在國家嘅清單（澳洲同加拿大發佈咗各自嘅清單）入面嘅 tall man 大寫字母除外。喺 nameSegments 標記佢哋；Lily 永遠唔會估。
  • 用 formatQuantity 寫劑量規格：尾部唔帶零，前面帶零，單位前面加不換行空格。
  • 保留結果嘅比較符：formatQuantity(5, "mmol/L", locale, "<") 會寫成「<5 mmol/L」。FHIR 嘅 Quantity.comparator 寫成 <、≤、≥ 或者 >；漏咗佢，「細過 5」就會變成「5」。
  • 寫 mL，唔好寫 cc，並避免 ISMP 易錯縮寫清單上嘅所有縮寫。
  • 永遠唔好截斷藥物嘅名稱或者劑量。

日期同時間

  • 月份用文字寫，咁日期就唔會有兩種讀法（Intl.DateTimeFormat 配合 month: "short"）。
  • 要有意識咁揀時鐘制式：明確傳入 hourCycle。NHS 要求用 24 小時制；嗰個係英國嘅規定，唔係全世界嘅規定，所以 Lily 永遠唔會代你揀。
  • 年齡透過 ageParts() 跟 Common User Interface 嘅分段；用其他慣例嘅服務就傳入自己嘅文字。
  • 只知道到月份或者年份嘅日期就保持噉：用 date-field precision="month" 或 "year"問，儲存做 2019-03 或 2019，並用 formatPartialDate()寫出嚟。永遠唔好作日子。
  • 一段時間係 duration-view，即係一個 <time datetime="P3DT4H"> ，載住你嘅文字，嚟自 durationParts() 同 Intl.DurationFormat.

儀表板

  • 病房看板或者指揮中心畫面會頻密更新。千祈唔好每次改動都播報：保留一個禮貌（polite）嘅摘要區域（「3 張空床，2 位待出院」），等人自己睇個看板。
  • 看板上面每個狀態（床位已清潔、佔用中、已封閉）都係文字，或者帶文字嘅 data-* 狀態，絕對唔可以淨係靠顏色。
  • 冇嘢會閃（WCAG 2.2.2、2.3.1），跟計時器更新嘅看板有暫停控制，或者只係有要求先更新；更新永遠唔會移動焦點。逾時嘅條目會用文字講明（「已等咗超過 20 分鐘」），並設定 data-overdue.
  • 計數或者比率會顯示分母（「68 個入面 12 個」），並連結到背後嘅列表。
  • 列表或者時間線會講明佢係咩嘅視圖：顯示咩、次序同時間範圍、隱藏咗咩同點解，以及邊啲來源冇回應。嚟自冇回應來源嘅空列表唔能夠證明乜都冇。
  • 提醒列表係一個 record-list ，佢嘅項目帶有到期日（review-date）同用文字表示嘅到期狀態，並設定 data-due；產生佢嘅規則由你決定。

表格

  • 答案係「係」、「唔係」或者「冇問過」嘅問題係一個 radio-group ，有三個答案，一開始全部唔揀，永遠唔用剔選框：剔選框分唔到「否認」同「從來冇問過」。系統回顧係每個身體系統一個 fieldset ，而「其餘全部冇」掣只會設定未答嘅項目。
  • 有一系列答案嘅問題（藥物、地址）係一個 repeatable-fieldset：加或者刪一項時焦點會跟住，每個刪除掣都以佢嘅項目命名。
  • 有小數逗號嘅數字：用 Intl.NumberFormat 顯示，喺 type="number" 唔接受逗號嘅地方，用帶 inputmode="decimal" 嘅文字欄接收，並喺你嘅程式碼入面解析。永遠唔好改用戶輸入嘅值，就算係為咗限制喺範圍內：超出範圍嘅值係佢睇得到嘅錯誤。
  • 一次只顯示部分選項嘅長列表會喺每個選項設定 aria-setsize 同 aria-posinset ，並記住頁內搜尋睇唔到其餘部分。

記錄、筆記同佢哋嘅來源

  • 喺行之前講明列表或者網格係咩嘅視圖：時間範圍同次序、略去咗咩同點解，以及邊啲來源冇回應（「最近 12 個月，最新嘅喺前面。家庭醫生記錄冇回應。」）。幫 record-list 同 timeline-list 設定 coverageLabel，並幫 data-grid 輔助元件設定佢嘅 coverageLabel。嚟自冇回應來源嘅空列表會用文字講明，永遠唔會被讀成「冇記錄」。
  • 用 record-provenance-view講明記錄嚟自邊度、係咪最終版本：已簽署、等緊簽署、已修訂、已儲存喺呢部裝置但未傳送。未簽署嘅草稿永遠唔可以睇落似已簽署。
  • 關於其他人（父母、胎兒、捐贈者）嘅條目會先講明係邊個嘅，用記錄項嘅 subjectLabel.
  • 被扣起嘅條目會用你嘅文字留喺列表（「受限：你冇權睇」），錯誤輸入嘅條目會保留刪除線並標明「錯誤輸入」：幫 record-list-item 或 timeline-list-item 設定 entryState 同 entryStateLabel。永遠唔好靜靜雞刪走任何一個，因為空缺會被讀成「乜都冇發生」。
  • 喺臨床筆記入面，用 data-source 同睇得到嘅文字標明每段文字嘅來源（打字、口述、範本、沿用複製、生成），令複製或者生成嘅文字永遠唔會被當成今日嘅檢查。
  • 載入唔到嘅部分係 unavailable ，用你嘅文字講明，並附重試掣；技術代碼如果要顯示，就放喺展開控制後面。由用戶操作引致嘅失敗會被讀出，同時講明記錄而家嘅值；頁面載入時嘅失敗就唔會。
  • 醫囑嘅歷史係一個 timeline-list，每個步驟一項（已計劃、已排期、進行中、已暫停、已完成、已取消），附時間同原因，目前狀態亦顯示喺該項。
