Benutzeroberflächen im Gesundheitswesen

Ein Leitfaden für Teams, die mit Lily klinische Software bauen: klinische Portale, Befunde und Berichte, Verordnung und Verabreichung von Arzneimitteln, Entscheidungsunterstützung und Krankenhaus-Dashboards.

Diese Übersetzung ist ein nicht geprüfter maschineller Entwurf. Die englische Seite ist die maßgebliche Fassung.

Was Lily tut und was nicht

Lily liefert Ihnen Darstellungsverträge: semantisches Markup, ARIA, Tastaturverhalten und Klassen-Hooks für das, was sich auf klinischen Bildschirmen wiederholt. Es liefert Ihnen weder klinische Logik noch klinische Inhalte noch eine regulatorische Aussage.

Die Zusammenstellung des Patientenbanners Jede Beschriftung und jeden Wert, und wer klinische Informationen sehen darf

Regulierung. Software, die einen Score, ein Perzentil, eine Dosis oder eine Arzneimittelwechselwirkung berechnet, ist in der Regel ein Medizinprodukt. Lily berechnet nichts davon, mit Absicht. Ist Ihr Produkt reguliert, gehört Ihnen seine Gebrauchstauglichkeitsakte (IEC 62366-1, die Human-Factors-Leitlinien der FDA, EU-MDR). Die Tests von Lily, sein selbst bewerteter Barrierefreiheits-Konformitätsbericht und seine Screenreader-Matrix können Nachweise in dieser Akte sein; keiner davon ist eine Konformitätsaussage, und die Matrix hat noch keine Ergebnisse.

Warnungen: nur bei Kritischem unterbrechen

Alarmmüdigkeit ist ein Sicherheitsproblem: Wenn jede Warnung unterbricht, werden alle weggeklickt. Die AHRQ empfiehlt, Warnungen nach Schweregrad abzustufen und nur die schweren unterbrechend zu machen.

  • Information (indicator="info"): eingebettet, neben der Aufgabe, eine Entscheidungsunterstützungskarte in der Seite.
  • Warnung (indicator="warning"): sichtbar, ohne zu blockieren, dieselbe Karte, auffällig gestaltet; kein Modal.
  • Kritisch (indicator="critical"): Setzen Sie die Karte in einen Warndialog und bieten Sie overrideReasons an, damit beim Schließen ein Grund verlangt wird.
  • Eine Entscheidungsunterstützungskarte ist nie von sich aus eine Live-Region. Kündigen Sie eine neue kritische Karte an, indem Sie den Fokus in den Dialog verschieben, nicht mit aria-live.
  • Entfernen Sie eine Karte, wenn das Ereignis, auf das sie antwortete, erneut eintritt, und erfassen Sie jedes Ergebnis (angenommen oder mit Begründung übergangen).

Patientenverwechslungen: identifizieren, nicht einschränken

  • Zeigen Sie zwei Identifikatoren überall dort, wo Daten eines Patienten erscheinen: den Namen mit dem Geburtsdatum und die nationale Kennung mit ihrer Anzeigekomponente (The Joint Commission, Quick Safety 45).
  • Verwenden Sie das Patientenbanner auf jedem Bildschirm, der auf die Akte eines Patienten wirkt, und halten Sie es sichtbar.
  • Bestätigen Sie vor einer Aktion an einer anderen Akte als der im Banner diese mit Name, Geburtsdatum und Kennung.
  • Begrenzen Sie nicht, wie viele Akten eine Ärztin oder ein Arzt öffnen darf: Eine randomisierte Studie mit 3.356 Klinikern (JAMA, 2019) ergab, dass dies Verordnungen beim falschen Patienten nicht verringert, und man umgeht es.

Das Patientenbanner

Die Zusammenstellung ist bei medical-banner dokumentiert, mit einer funktionierenden Seite unter /patient-banner in der SvelteKit-Beispiel-App:

  • zwei Identifikatoren und das Alter neben dem Geburtsdatum;
  • Allergien über eine Allergieliste, damit „keine bekannten Allergien“, „nicht erfasst“ und „nicht verfügbar“ nie gleich aussehen;
  • ein fehlender Wert wird in Worten angegeben („Nicht bekannt“), nie als Fragezeichen, Strich oder leere Zelle;
  • ein verstorbener Patient: data-deceased für das Theme und eine sichtbare Textzeile, nie nur Farbe;
  • kein Feld abgeschnitten, beschnitten oder ausgeblendet, bei keiner Breite; es bricht um.

Befunde

  • Eine Darstellung für einen Befund, aus welchem System er auch stammt: die Beobachtungsansicht.
  • Die Kennzeichnung besteht aus Wörtern Ihrer Übersetzung (flagLabel), mit dem FHIR-Interpretationscode als data-interpretation für das Theme.
  • Trennen Sie neue Befunde von früheren und zeigen Sie einen Verlauf (eine Sparkline oder ein Liniendiagramm mit seiner Datentabelle): Klinikerinnen und Kliniker suchen eine bedeutsame Veränderung, nicht nur den Bereich.
  • Ein nie erfasster Befund und ein nicht verfügbarer Befund sind verschiedene Zustände, mit verschiedenen Wörtern.

Arzneimittel

  • Generische Namen in Kleinbuchstaben, außer Tall-Man-Buchstaben aus den Listen von FDA und ISMP oder Ihres Landes (Australien und Kanada veröffentlichen eigene). Markieren Sie sie in nameSegments; Lily errät sie nie.
  • Schreiben Sie die Stärke mit formatQuantity: keine nachgestellte Null, eine führende Null, ein geschütztes Leerzeichen vor der Einheit.
  • Schreiben Sie mL, nie cc, und vermeiden Sie jede Abkürzung auf der ISMP-Liste fehleranfälliger Abkürzungen.
  • Kürzen Sie nie den Namen oder die Dosis eines Arzneimittels.

Datum und Uhrzeit

  • Schreiben Sie den Monat als Text, damit ein Datum nicht auf zwei Arten gelesen werden kann (Intl.DateTimeFormat mit month: "short").
  • Wählen Sie die Uhr bewusst: Übergeben Sie hourCycle ausdrücklich. Der NHS verlangt die 24-Stunden-Uhr; das ist eine britische Regel, keine weltweite, daher wählt Lily sie nie für Sie.
  • Altersangaben folgen den Stufen der Common User Interface über ageParts(); ein Dienst mit einer anderen Konvention übergibt eigene Wörter.

Dashboards

  • Eine Stationstafel oder ein Leitstellenbildschirm aktualisiert sich oft. Kündigen Sie nie jede Änderung an: Halten Sie eine höfliche Zusammenfassungsregion („3 Betten frei, 2 Entlassungen fällig“) und lassen Sie die Menschen die Tafel lesen.
  • Jeder Zustand auf einer Tafel (Bett gereinigt, belegt, gesperrt) ist Text oder ein data-*-Zustand mit Worten, nie nur Farbe.

Was Lily nicht tun wird

  • Einen Frühwarnscore, ein Wachstumsperzentil, eine Dosis oder einen Referenzbereich berechnen.
  • Eine Arzneimitteldatenbank, eine Tall-Man-Liste oder Codes aus SNOMED CT, ICD, LOINC oder UCUM mitliefern.
  • Ein lizenziertes Instrument (Wong-Baker FACES) oder das Design einer anderen Stelle (das NEWS2-Diagramm) nachbilden.
  • Die Zahl der gleichzeitig geöffneten Akten begrenzen.
