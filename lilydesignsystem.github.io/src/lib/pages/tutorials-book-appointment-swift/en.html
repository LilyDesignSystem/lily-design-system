Book an appointment in Swift

A booking screen for iPhone, with SwiftUI and Lily: labelled choices, a line of guidance, and the bars a phone app has.

What you'll build

One screen of a booking app, on iPhone, with SwiftUI: a top bar of labelled buttons, a large heading, a line of guidance, four choices (where, what type, with whom, and what time of day), and a tab bar. It is generic: a service anyone might book, with example places and people. About 30 minutes.

Before you start

You need Xcode 26 or later and the Swift tutorial's first steps. In Xcode, choose File ▸ New ▸ Project ▸ iOS ▸ App, name it BookAppointment, with SwiftUI. Then File ▸ Add Package Dependencies…, enter this address, and add LilyUI and LilyThemes to the app: 

https://github.com/LilyDesignSystem/lily-design-system-swift.git

Version 0.1.0 or later. Each code block below is one whole file in the app's BookAppointment folder; replace the file Xcode made where the names match, and delete ContentView.swift.

Step 2: Describe the booking

What the person has chosen, the choices offered, and one rule: times can be looked for once a type is chosen.

BookAppointment/Booking.swift

// What the person has chosen, and the choices offered. The choices come from the service; these are examples.

struct Choice: Identifiable, Hashable {
    let id: String
    let label: String
}

struct Booking {
    var location = "main"
    var type = ""
    var person = "any"
    var timeOfDay = ""

    static let locations = [
        Choice(id: "main", label: "Main office"),
        Choice(id: "north", label: "North branch"),
        Choice(id: "online", label: "Online"),
    ]
    static let types = [
        Choice(id: "", label: "Select type"),
        Choice(id: "first", label: "First visit"),
        Choice(id: "follow-up", label: "Follow-up"),
        Choice(id: "advice", label: "Advice by phone"),
    ]
    static let people = [
        Choice(id: "any", label: "No preference"),
        Choice(id: "sam", label: "Sam Okoro"),
        Choice(id: "alex", label: "Alex Kim"),
    ]
    static let timesOfDay = [
        Choice(id: "", label: "Select an option"),
        Choice(id: "morning", label: "Morning"),
        Choice(id: "afternoon", label: "Afternoon"),
        Choice(id: "evening", label: "Evening"),
    ]

    /// Times can be looked for once a type is chosen: the type decides how long the appointment is.
    var canFindTimes: Bool { !type.isEmpty }
}

Step 3: Choose the colours

Lily ships no brand. The navy band and the gold line are the service's own; the text on the band is white, well above 4.5:1, and the brand colour is never the colour of text on the page.

BookAppointment/Brand.swift

import SwiftUI

// The service's own colours. A brand colour colours a band or a line, never text on the page; the text on the band is
// white, well above 4.5:1 on this navy (AGENTS/visual-identity.md). Lily ships no brand: these are yours.
enum Brand {
    static let band = Color(red: 0x1F / 255, green: 0x2A / 255, blue: 0x44 / 255)
    static let onBand = Color.white
    static let line = Color(red: 0xC8 / 255, green: 0x9B / 255, blue: 0x3C / 255)
}

Step 4: Ask for a choice

Lily's Field draws the label above the control and gives the control its spoken name, so VoiceOver says "Location" before "Main office". The box with a chevron is a Menu holding a Picker.

BookAppointment/ChoiceField.swift

import LilyThemes
import LilyUI
import SwiftUI

/// A labelled choice drawn as a box with a chevron, like a web select. Lily's Field gives the label, which is also what
/// VoiceOver says before the current choice.
struct ChoiceField: View {
    let label: String
    let choices: [Choice]
    @Binding var selection: String
    @Environment(\.lilyTokens) private var tokens

    var body: some View {
        Field(label: label) {
            Menu {
                Picker(selection: $selection) {
                    ForEach(choices) { Text($0.label).tag($0.id) }
                } label: {
                    EmptyView()
                }
            } label: {
                HStack {
                    Text(choices.first { $0.id == selection }?.label ?? "")
                    Spacer()
                    Image(systemName: "chevron.down").accessibilityHidden(true)
                }
                .foregroundStyle(tokens.baseContent)
                .padding(.horizontal, 16)
                .frame(maxWidth: 300, minHeight: 50)
                .background(tokens.base100)
                .overlay(Rectangle().strokeBorder(tokens.baseContent, lineWidth: 2))
            }
        }
    }
}

Step 5: Draw the screen

The heading is marked as a header for VoiceOver's rotor. Lily's InsetText sets the guidance apart, with the theme's rail at its edge.

BookAppointment/BookAppointmentView.swift

import LilyThemes
import LilyUI
import SwiftUI

struct BookAppointmentView: View {
    @State private var booking = Booking()
    @Environment(\.lilyTokens) private var tokens

    var body: some View {
        ScrollView {
            VStack(alignment: .leading, spacing: 24) {
                Text(Words.title)
                    .font(.system(size: 40, weight: .bold))
                    .accessibilityAddTraits(.isHeader)
                InsetText { Text(Words.intro) }
                ChoiceField(label: Words.location, choices: Booking.locations, selection: $booking.location)
                ChoiceField(label: Words.type, choices: Booking.types, selection: $booking.type)
                ChoiceField(label: Words.person, choices: Booking.people, selection: $booking.person)
                ChoiceField(label: Words.timeOfDay, choices: Booking.timesOfDay, selection: $booking.timeOfDay)
                Button(Words.findTimes) {}
                    .buttonStyle(.borderedProminent)
                    .disabled(!booking.canFindTimes)
                    .accessibilityHint(booking.canFindTimes ? "" : Words.choose)
            }
            .padding(.horizontal, 20)
            .padding(.vertical, 16)
            .frame(maxWidth: .infinity, alignment: .leading)
        }
        .foregroundStyle(tokens.baseContent)
        .background(tokens.base200)
    }
}

Step 6: Add the bars

Both bars are drawn here so they match the service's design, rather than iOS's own floating tab bar. A tab bar drawn by hand must still say which tab is selected, so the selected button has the .isSelected trait.

BookAppointment/AppShell.swift

import LilyThemes
import SwiftUI

/// The app's frame: a top bar of labelled buttons, the screen, and a tab bar. Both bars are drawn here so they match the
/// service's own design; a tab bar drawn by hand must still say which tab is selected, as TabView does.
struct AppShell: View {
    @State private var tab = Words.appointments

    var body: some View {
        VStack(spacing: 0) {
            TopBar()
            BookAppointmentView()
            TabBar(selection: $tab)
        }
    }
}

private struct BarButton: View {
    let icon: String
    let label: String
    var body: some View {
        Button {} label: {
            VStack(spacing: 2) {
                Image(systemName: icon).font(.title2).accessibilityHidden(true)
                Text(label).font(.caption2)
            }
            .frame(minWidth: 52, minHeight: 44)
        }
    }
}

private struct TopBar: View {
    var body: some View {
        HStack {
            BarButton(icon: "house", label: Words.home)
            BarButton(icon: "character.bubble", label: Words.language)
            Spacer()
            HStack(spacing: 6) {
                Image(systemName: "circle.hexagongrid.fill").font(.title).accessibilityHidden(true)
                Text(Words.appName).font(.caption.bold())
            }
            .accessibilityElement(children: .combine)
            .accessibilityAddTraits(.isHeader)
            Spacer()
            BarButton(icon: "questionmark.circle", label: Words.help)
            BarButton(icon: "message", label: Words.messages)
        }
        .padding(.horizontal, 8)
        .padding(.bottom, 8)
        .foregroundStyle(Brand.onBand)
        .tint(Brand.onBand)
        .background(Brand.band.ignoresSafeArea(edges: .top))
    }
}

private struct TabBar: View {
    @Binding var selection: String
    @Environment(\.lilyTokens) private var tokens
    private let tabs = [
        (Words.appointments, "calendar"), (Words.orders, "bag"), (Words.account, "person.crop.circle"),
        (Words.more, "ellipsis"),
    ]

    var body: some View {
        HStack {
            ForEach(tabs, id: \.0) { label, icon in
                let selected = label == selection
                Button { selection = label } label: {
                    VStack(spacing: 4) {
                        Image(systemName: icon).font(.title3).symbolVariant(selected ? .fill : .none)
                            .accessibilityHidden(true)
                        Text(label).font(.caption2).fontWeight(selected ? .bold : .regular)
                    }
                    .frame(maxWidth: .infinity, minHeight: 48)
                    .foregroundStyle(selected ? Brand.band : tokens.baseContent)
                }
                .accessibilityAddTraits(selected ? [.isSelected] : [])
            }
        }
        .padding(.top, 6)
        .background(tokens.base100.ignoresSafeArea(edges: .bottom))
        .overlay(alignment: .top) { Rectangle().fill(Brand.line).frame(height: 2) }
        .accessibilityElement(children: .contain)
        .accessibilityLabel(Words.tabs)
    }
}

Step 7: Start the app

.lilyTheme(.light) draws every Lily component in the light theme's tokens.

BookAppointment/BookAppointmentApp.swift

import LilyThemes
import SwiftUI

@main
struct BookAppointmentApp: App {
    var body: some Scene {
        WindowGroup {
            AppShell()
                .lilyTheme(.light)
        }
    }
}

Check your work: run the app in an iPhone simulator. Turn on VoiceOver (or the Accessibility Inspector) and move through the screen: each choice says its label, then its value, and the Appointments tab says it is selected. "Find times" is dimmed until you choose a type.

What this does not do yet

  • The buttons in the bars and "Find times" do nothing: the screen is the lesson, not the booking.
  • The choices are fixed examples. A real app asks its service for them, in the person's language.
  • It has one language. The words are in one place, so adding another touches no view.
