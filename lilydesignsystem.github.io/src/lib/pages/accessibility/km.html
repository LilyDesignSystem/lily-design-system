អ្វីទៅដែល “មានគោលដៅ WCAG 2.2 AAA” មានន័យនៅទីនេះ

ពាក្យ មានគោលដៅ ត្រូវបានជ្រើសរើសដោយចេតនា។ ទំព័រនេះប្រាប់ច្បាស់ថាអ្វីត្រូវបានផ្ទៀងផ្ទាត់ ដោយអ្វី អ្វីមិនត្រូវបានផ្ទៀងផ្ទាត់ដោយអ្វីសោះ និងអ្វីដែលយើងមានបំណងធ្វើអំពីគម្លាតនោះ។ Lily មិនដែលអះអាង “ការអនុលោម” WCAG ទេ — គ្មានសវនកម្មណាគាំទ្រវាទេ។

ផ្ទៀងផ្ទាត់ជាបន្តបន្ទាប់

  • ធាតុន័យវិទ្យាស្តង់ដារនៃសមាសភាគនីមួយៗ គុណលក្ខណៈ ARIA និង class hook — បញ្ជាក់ដោយសំណុំតេស្តឯកតាក្នុងមួយក្របខណ្ឌ (ករណីជាង ១៥,០០០ ក្នុងក្របខណ្ឌប្រាំពីរ)។
  • ទំព័រសាកល្បងសមាសភាគ ៥៧១ នីមួយៗក្នុងកម្មវិធីគំរូ SvelteKit ស្អាតពី axe (សំណុំច្បាប់ WCAG 2.0/2.1 A+AA និង 2.2 AA) — ការស្កេនកាតាឡុកពេញលេញ បង្កើត baseline លើកដំបូង 2026-08-27 ហើយដំណើរការឡើងវិញ 2026-10-06 — បូក baseline ក្នុងមួយកម្មវិធីនៅលើទំព័រដើម កាតាឡុក និងផ្លូវផ្សំក្នុងកម្មវិធីគំរូទាំងប្រាំពីរ។
  • កិច្ចសន្យាក្តារចុចសម្រាប់សមាសភាគអន្តរកម្មនីមួយៗ ចងក្រងក្នុងទិន្នន័យមេស្តង់ដារនៃសមាសភាគនីមួយៗ ហើយអនុវត្តដោយសំណុំតេស្ត; កញ្ចប់ជំនួយការក៏ដំណើរការលក្ខណៈបច្ចេកទេស Playwright ក្នុងកម្មវិធីរុករកពិតប្រាកដផងដែរ។
  • កម្រិតទាបនៃទំហំគោលដៅ WCAG 2.2 និងកម្មវិធីការពារលើសទំហំក្នុងស្បែកទាំង ៥៧; តំណរំលង ចំណុចសម្គាល់ និងគ្មានការលើសទំហំផ្ដេកក្នុងវ៉ាត់ប៉ត់ចំនួនបួនក្នុងមួយកម្មវិធី; lang/dir ការអនុវត្ត និងការត្រឡប់ RTL។

មិនត្រូវបានផ្ទៀងផ្ទាត់ដោយអ្វីសោះ

  • មិនដែលមានសវនកម្មអនុលោមភាពត្រូវបានអនុវត្តទេ។ គ្មាន VPAT គ្មានវិញ្ញាបនបត្រ។ ឧបករណ៍ស្វ័យប្រវត្តិគ្របដណ្តប់តែភាគតិចនៃលក្ខណៈវិនិច្ឆ័យជោគជ័យ WCAG។
  • លក្ខណៈវិនិច្ឆ័យជាក់លាក់ AAA (កម្រិតពណ៌ប្រៀបធៀបកើនឡើង និងផ្សេងទៀត) ជាចេតនារចនា មិនមែនជាលក្ខណសម្បត្តិដែលបានផ្ទៀងផ្ទាត់ទេ; សំណុំច្បាប់ axe ដំណើរការ A/AA។ មិនទាន់មានស្បែកកម្រិតពណ៌ប្រៀបធៀបខ្ពស់ពិសេសនៅឡើយទេ។
  • អាកប្បកិរិយាកម្មវិធីអានអេក្រង់ភាគច្រើនមិនទាន់បានសាកល្បង។ សំណុំតេស្តបញ្ជាក់គុណលក្ខណៈ ARIA មិនមែនអ្វីដែល VoiceOver, NVDA ឬ JAWS ប្រកាសទេ — ហើយគម្រោងនេះបានដឹកជញ្ជូនសំណុំតេស្តពណ៌បៃតងលើពិការភាពពិតប្រាកដលើសពីមួយដង ដែលនីមួយៗត្រូវបានសរសេរក្នុងកំណត់ហេតុការផ្លាស់ប្តូរ ពីព្រោះសំណុំតេស្តមិនអាចមើលឃើញវា។

អ្វីដែលយើងមានបំណងធ្វើអំពីវា

សវនកម្មភាពងាយស្រួលចូលប្រើឯករាជ្យ ជាការប្រើប្រាស់ដែលបានដាក់ឈ្មោះដំបូងនៃមូលនិធិគម្រោងណាមួយ ហើយវិសាលភាពដែលសវនករត្រូវការត្រូវបានរៀបចំរួចហើយ។ រហូតដល់ពេលនោះ របាយការណ៍កម្មវិធីអានអេក្រង់ជាការចូលរួមចំណែកដែលគម្រោងនេះចង់បានបំផុត៖ “សមាសភាគ X ប្រកាស Y ដែលខុស ព្រោះ Z” អាចអនុវត្តបានដោយផ្ទាល់។
