Apa tegesé “ngarah menyang WCAG 2.2 AAA” ing kéné

Tembung ngarah iku dipilih kanthi sengaja. Kaca iki ngandhakaké persis apa sing diverifikasi, nganggo apa, apa sing ora diverifikasi dening apa waé, lan apa sing arep kita lakoni babagan kekosongan kuwi. Lily ora tau ngaku “kapatuhan” WCAG — ora ana audit sing ndhukung.

Diverifikasi terus-terusan

  • Elemèn semantik kanonik, atribut ARIA, lan pancingan kelas saben komponèn — dikonfirmasi dening suite tés unit saben framework (luwih saka 15.000 kasus ing pitu framework).
  • Saben saka 581 kaca demo komponèn ing aplikasi conto SvelteKit resik miturut axe (set aturan WCAG 2.0/2.1 A+AA lan 2.2 AA) — sapuan katalog kabèh, pisanan didasaraké ing 2026-08-27 lan dijalanaké manèh ing 2026-10-06 — ditambah dasar saben aplikasi kanggo beranda, katalog, lan rute gabungan ing kabèh pitu aplikasi conto.
  • Kontrak keyboard saben komponèn interaktif, didokumentasi ing metadata kanonik saben komponèn lan dilatih dening suite; paket pembantu uga njalanaké spesifikasi Playwright ing browser nyata.
  • Wates ngisor ukuran target WCAG 2.2 lan pangreksa luber ing kabèh 57 tema; tautan nglangkahi, tetenger, lan ora ana luber horizontal ing papat viewport saben aplikasi; lang/dir panrapan, kalebu pambalikan RTL.

Ora diverifikasi dening apa waé

  • Audit kapatuhan durung tau dilakoni. Ora ana VPAT, ora ana sertifikasi. Piranti otomatis nyakup minoritas kriteria sukses WCAG.
  • Kriteria khusus AAA (kontras sing ditingkataké lan liyané) iku niat desain, dudu properti sing diverifikasi; set aturan axe mlaku A/AA. Durung ana tema kontras dhuwur khusus.
  • Prilaku pembaca layar umumé durung dites. Suite ngonfirmasi atribut ARIA, dudu apa sing diumumaké VoiceOver, NVDA, utawa JAWS — lan proyèk iki wis ngeculaké suite ijo ing ndhuwur cacat nyata luwih saka sepisan, saben siji dicathet ing changelog persis amarga suite ora bisa ndeleng kuwi.

Apa sing arep kita lakoni babagan kuwi

Audit aksesibilitas mandiri iku panggunaan kapisan sing disebutaké saka dana proyèk apa waé, lan wilayah sing dibutuhaké auditor wis disiapaké. Nganti kuwi, laporan saka pembaca layar iku sumbangan sing paling dikarepaké proyèk iki: “komponèn X ngumumaké Y, sing salah amarga Z” bisa langsung ditindakaké.
