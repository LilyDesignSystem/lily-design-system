“มุ่งเป้าไปที่ WCAG 2.2 AAA” ในที่นี้หมายถึงอะไร

คำว่า มุ่งเป้า เลือกมาอย่างตั้งใจ หน้านี้ระบุอย่างแม่นยำว่าอะไรได้รับการตรวจสอบ ด้วยอะไร อะไรที่ไม่มีสิ่งใดตรวจสอบ และเราตั้งใจจะทำอย่างไรกับช่องว่างนั้น Lily ไม่เคยอ้างว่า “สอดคล้อง” กับ WCAG — ไม่มีการตรวจสอบใดรองรับ

ตรวจสอบอย่างต่อเนื่อง

  • องค์ประกอบเชิงความหมายมาตรฐาน แอตทริบิวต์ ARIA และคลาสฮุกของทุกคอมโพเนนต์ — ยืนยันด้วยชุดทดสอบหน่วยของแต่ละเฟรมเวิร์ก (กว่า 15,000 กรณีใน 7 เฟรมเวิร์ก)
  • หน้าเดโมของคอมโพเนนต์ทั้ง 581 หน้าในแอปตัวอย่าง SvelteKit ผ่าน axe โดยไม่มีข้อผิดพลาด (ชุดกฎ WCAG 2.0/2.1 A+AA และ 2.2 AA) — การกวาดตรวจทั้งแคตตาล็อก กำหนดเส้นฐานครั้งแรกเมื่อ 2026-08-27 และรันซ้ำเมื่อ 2026-10-06 — รวมถึงเส้นฐานต่อแอปสำหรับหน้าแรก แคตตาล็อก และเส้นทางแบบประกอบในแอปตัวอย่างทั้งเจ็ด
  • ข้อตกลงด้านแป้นพิมพ์ของแต่ละคอมโพเนนต์ที่โต้ตอบได้ บันทึกไว้ในเมทาดาทามาตรฐานของคอมโพเนนต์และทดสอบโดยชุดทดสอบ แพ็กเกจตัวช่วยยังรันสเปก Playwright บนเบราว์เซอร์จริงเพิ่มเติมด้วย
  • ขีดต่ำสุดของขนาดเป้าหมายตาม WCAG 2.2 และตัวป้องกันการล้นในทั้ง 57 ธีม ลิงก์ข้าม แลนด์มาร์ก และไม่มีการล้นแนวนอนที่สี่วิวพอร์ตต่อแอป การใช้ lang/dir รวมถึงการสลับ RTL

ไม่มีสิ่งใดตรวจสอบ

  • ไม่เคยมีการตรวจสอบความสอดคล้องเลย ไม่มี VPAT ไม่มีการรับรอง เครื่องมืออัตโนมัติครอบคลุมเกณฑ์ความสำเร็จของ WCAG เพียงส่วนน้อย
  • เกณฑ์เฉพาะของ AAA (ความคมชัดที่ปรับปรุงแล้ว และอื่น ๆ) เป็นเจตนาการออกแบบ ไม่ใช่คุณสมบัติที่ผ่านการตรวจสอบ ชุดกฎของ axe รันที่ระดับ A/AA ยังไม่มีธีมความคมชัดสูงโดยเฉพาะ
  • พฤติกรรมของโปรแกรมอ่านหน้าจอส่วนใหญ่ยังไม่ได้ทดสอบ ชุดทดสอบยืนยันแอตทริบิวต์ ARIA ไม่ใช่สิ่งที่ VoiceOver, NVDA หรือ JAWS อ่านออกเสียง — และโครงการนี้เคยปล่อยชุดทดสอบสีเขียวทั้งที่มีข้อบกพร่องจริงมากกว่าหนึ่งครั้ง แต่ละครั้งบันทึกไว้ในบันทึกการเปลี่ยนแปลงเพราะชุดทดสอบมองไม่เห็นมัน

สิ่งที่เราตั้งใจจะทำ

การตรวจสอบการเข้าถึงโดยหน่วยงานอิสระคือการใช้เงินทุนของโครงการเป็นอย่างแรกที่ระบุไว้ และขอบเขตที่ผู้ตรวจสอบต้องการก็เตรียมไว้แล้ว จนกว่าจะถึงเวลานั้น รายงานจากโปรแกรมอ่านหน้าจอคือการสมทบที่โครงการนี้ต้องการมากที่สุด: “คอมโพเนนต์ X อ่านว่า Y ซึ่งผิดเพราะ Z” นำไปดำเนินการได้ทันที
