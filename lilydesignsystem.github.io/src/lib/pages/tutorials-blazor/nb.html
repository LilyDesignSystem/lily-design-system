Blazor-veiledning

Razor-klassebibliotekskomponenter med parametere, ChildContent gjengivelsesfragmenter, attributtspredning og en bUnit-test per komponent.

Hva du skal bygge

Et lite kontaktskjema — et inndatafelt med etikett, en send-knapp, @bind-Value binding, ekte tastatur- og skjermleseroppførsel — først bart, så stilet, på omtrent 10 minutter.

Før du begynner

Du trenger git og .NET SDK 8 eller nyere. Ethvert Blazor-prosjekt fungerer — Blazor Web App, Server eller WebAssembly.

Steg 1 — Hent koden

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-blazor-headless
dotnet build
dotnet test      # bUnit — 1,400+ cases across the catalog

Komponentene bor i src/LilyBlazorHeadless/Components/ — Button.razor, TextInput.razor — én Razor-fil hver. Referer til prosjektet (eller kopier filene) fra Blazor-appen din og legg til @using LilyBlazorHeadless.Components i _Imports.razor.

Steg 2 — Din første komponent

<Button OnClick="Save">Save</Button>

Gjengir <button class="button">. De delte parameterkonvensjonene: Label (en aria-label overstyring), CssClass (føyd til basekroken), ChildContentog [Parameter(CaptureUnmatchedValues = true)] attributtspredning slik at ethvert ekstra HTML-attributt går gjennom.

Steg 3 — Sett sammen et lite skjema

<Form OnSubmit="HandleSubmit">
  <Field Label="Full name" Required="true">
    <TextInput Id="name" Label="Full name" @bind-Value="name" Required="true" />
  </Field>
  <Button Type="submit">Save</Button>
</Form>

@code {
  private string name = "";
}

Field tar den synlige Label som sin egen parameter i stedet for en nøstet etikettkomponent — send den inn én gang, på Fieldog TextInputpå Label gir det tilgjengelige navnet.

Verifisert 2026-08-29: et tidligere utkast nøstet en separat Label komponent inni Field, som gjengir to etiketter (én tom) fordi Field allerede gjengir sin egen fra Label parameter — oppdaget ved å sjekke komponentkilden; Form har ikke noen egen Label parameter, så bruken av <Form> i det tidligere utkastet ble rettet ved å utelate den i stedet for å finne på et attributt som ikke finnes. Den sammensatte kontaktskjema-ruten er det samme mønsteret, prøvd med ekte e2e- og axe-tester.

Sjekk arbeidet ditt: kjør appen, og skjemaet ser enkelt ut — akkurat som tiltenkt: stilingen ligger fortsatt foran. Trykk Tab: fokus beveger seg gjennom hver kontroll, etiketten kunngjøres og innsending fungerer. Oppførselen er ferdig; utseendet er ditt og er neste.

Steg 4 — Stil det

Stil klassekrokene — .button, .text-input, .label, .field — i app.css, eller lenk et ferdig tema i App.razor / index.html: 

<link rel="stylesheet" href="themes/wireframe.css" />

Steg 5 — Se alt fungere

Blazor Web-eksempelappen viser hele katalogen stilet og demonstrert, med Playwright e2e-tester: 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-blazor-web-examples
dotnet run --project src/LilyBlazorWebExamples

Neste steg

  • Tema — bytte ved kjøretid med Blazor theme-picker-hjelperen (et Razor-klassebibliotek på NuGet).
  • Preferansehjelpere — språk og tekststørrelse.
  • Komponentkatalog — egenskaper, ARIA og tastatur per komponent.

Spørsmål underveis? hjelpesiden er full av svar — og hvis et steg kan bli tydeligere, fortell oss så forbedrer vi gjerne veiledningen.
