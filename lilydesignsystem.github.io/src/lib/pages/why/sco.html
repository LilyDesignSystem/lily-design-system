The case for Lily

Lily hauns ye the sair pairts — semantics, accessibility, keyboard behaviour, internationalization — an leaves the look entirely, happily, tae yersel.

Stairt frae yer design

Yer team aareadies kens hoo yer product shuid look. Lily stairts exactly there: it supplies the pairts that are genuinely sair tae git richt an dear tae redae — the richt semantic element, the ARIA states, the keyboard contract, focus management — an leaves ilka visual decision entirely, joyfully, yours. Yer CSS is the design system's look, frae day ane.

Because ilka component cairries a stable class hook an pure structure, yer styling bides cleanly yours through ilka upgrade — an the accessibility unnerneath keeps wirkin, version efter version.

Whit Lily commits tae

  • Accessible bi defauld. WCAG 2.2 AAA is the target for ilka component. Patterns follae the WAI-ARIA Authoring Practices; ilka interactive component is keyboard-operable wi a documentit contract; the example apps haud a clean axe-core baseline.
  • Internationalizable bi construction. Ilka uiser-facin string — ilka label, error, an announcement — is a prop wi stable names athort frameworks, sae translation flows naturally. RTL an bidirectional text inherit frae yer dir. Locale-awaur components tak the locale as a prop, aye explicitly.
  • Ae catalog, aicht frameworks. The same 571 components (536 as native Web Components) wi the same class hooks an prop conventions in HTML, Svelte, React, Vue, Angular, Blazor, Nunjucks, an Web Components. Yer CSS an yer team's knowledge transfer athort stacks.
  • CSS-strategy agnostic. Ae stable kebab-case class per component root. Semantic CSS, Tailwind utilities, CSS-in-JS, or ane o the 57 ready-made themes — Lily walcomes them aw an gits oot the road gracefully.
  • Free, forever, on yer ain terms. Open source unner yer choice o BSD, MIT, Apache-2.0, GPL-2.0, or GPL-3.0. Nae pro tier, nae seat licences, nae telemetry.

Depth whaur it maitters

Ayont the usual buttons an dialogs, the catalog reaches further than maist:

  • Public-sector patterns researched frae the NHS UK, GOV.UK, USWDS, an ONS design systems — error summaries, warnin callouts, summary lists, phase banners, skip links.
  • 140 national personal identifier components coverin healthcare, national-ID, tax, an passport identifiers athort 50+ kintras, ilkane documentin its format an validation algorithm.
  • Editorial an scrollytelling primitives adaptit frae Reuters Graphics — article layoots, scrollers, timelines, tile maps.
  • Picker helpers — wee packages that ain ae interaction frae stairt tae feenish: theme switchin (wi runtime stylesheet loadin), leid, text size, reduced motion, seek, page links, sharin, an date-time entry. Ilkane is a headless icon button that opens a popup — no a native <select> — wi persistence an SSR safety biggit in.

Themes for the public sector, oot the box

Lily ships wi 57 standalane reference themes that target its class hooks directly: NHS England, NHS Scotland, an NHS Wales (ilkane in patient-facin an practitioner-facin variants), GOV.UK, USWDS, Adobe Spectrum an Mozilla Protocol inspired palettes, an a set o general-purpose licht an daurk themes. Link ae stylesheet an a govrenment-grade look is on; the theme-picker helper swaps them at runtime.

Hoo Lily compares

We keep an honest, component-bi-component comparison against ither design systems — styled an headless, commercial an public-sector. Whaur anither library is a better fit for ye, the comparison will shaw it; Lily lears frae them aw an cites its inspirations in the open.

Wha's ahint it

Lily is a young, independent open-source project that walcomes collaboration, guidance, an feedback — see Aboot for the story an the inspirations. Aathing — the specification, the tests, the roadmap, even the audit tooling — is in the open at github.com/LilyDesignSystem.

Help Lily grow

If Lily is uiseful tae ye, the maist valuable things ye can dae:

  • Stairn an share. Stairn the main repo an shaw a colleague the catalog — awaurness is the scarcest resource a young project haes.
  • Big something an tell us. Real-warld uiss reports — whit warked, whit could be smoother — shape the roadmap mair than onything else.
  • Audit accessibility. Screen-reader passes (VoiceOver, NVDA, JAWS) on the example apps are gowd; file whit ye find.
  • Contribute a theme or a translation. Baith are self-contained, weel-scopit first contributions.
  • Share whit ye find, wi a minimal reproduction, on the GitHub repository, or email joel@joelparkerhenderson.com.
