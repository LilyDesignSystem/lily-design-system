Un formulaire qui fonctionne partout dans le monde

Lily vise tous les pays, pas un seul. Il ne fournit aucun texte anglais et ne suppose aucun pays : les choix qui rendent un formulaire local sont les vôtres, faits délibérément. Ce tutoriel les passe en revue.

Ce que vous allez construire

Un formulaire d'inscription pour une clinique qui reçoit des personnes de nombreux pays : un nom, une date de naissance, une adresse, un numéro de téléphone, un tarif, et une page qui se lit de droite à gauche quand il le faut. Les exemples utilisent Svelte ; chaque catalogue prend les mêmes props. Environ 20 minutes, après le tutoriel des formulaires accessibles.

Étape 1 — Les noms : un seul champ, pas deux

<label class="label" for="name">Full name</label>
<TextInput id="name" name="name" autocomplete="name" label="Full name" />

« Prénom » et « nom de famille » ne conviennent pas à beaucoup de gens : un nom unique, le nom de famille en premier, deux noms de famille, un patronyme. Demandez le nom complet dans un seul champ, et si vous devez savoir comment appeler quelqu'un, demandez-le à part.

Étape 2 — Les dates : les parties dans l'ordre du lecteur

<DateField
  label="Date of birth"
  dayLabel="Day"
  monthLabel="Month"
  yearLabel="Year"
  order="dmy"
  autocomplete="bday"
  name="dob"
  bind:value={dob}
/>

order vaut "dmy", "mdy" ou "ymd" : choisissez celui qu'attendent vos lecteurs, car 03/04 est en mars dans un pays et en avril dans le suivant. La valeur est toujours au format ISO (YYYY-MM-DD), quel que soit l'ordre. Pour une date que l'on ne connaît qu'à moitié, comme le début d'une maladie, precision="month" enregistre 2019-03 et n'invente jamais de jour.

Pour afficher une date, formatez-la avec Intl.DateTimeFormat dans la langue du lecteur ; Lily ne le fait jamais à votre place.

Étape 3 — Les adresses : la forme d'aucun pays par défaut

<AddressInput label="Home address">
  <label class="label" for="address">Address</label>
  <textarea class="text-area-input" id="address" name="address" autocomplete="street-address" rows="4"></textarea>
  <label class="label" for="country">Country or territory</label>
  <select class="select" id="country" name="country" autocomplete="country"> … </select>
</AddressInput>

AddressInput est un groupe nommé ; les champs qu'il contient sont les vôtres. Une adresse en texte libre plus un pays fonctionne partout. Si vous la découpez, faites-le par pays (le code postal est facultatif ou absent dans beaucoup d'entre eux) et ne rendez jamais obligatoire un champ « État ».

Étape 4 — Numéros de téléphone et argent

<TelInput label="Phone number" name="phone" autocomplete="tel" />
<CurrencyInput label="Fee" currencyCode="KES" bind:value={fee} />

Acceptez un numéro de téléphone tel qu'il est saisi, avec des espaces et un + ; n'imposez pas le format d'un pays. CurrencyInput n'a pas de devise par défaut : currencyCode (ISO 4217) est obligatoire, car une devise par défaut serait l'argent d'un seul pays.

Étape 5 — Sens d'écriture et langue

<LocalePicker label="Language" locales={["en", "fr", "ar", "sw"]} bind:value={locale} />

Le sélecteur de langue définit lang et dir sur la page, si bien que l'arabe ou l'hébreu se lisent de droite à gauche. Chaque composant Lily hérite de dir ; les thèmes utilisent des propriétés logiques (margin-inline-start, et non margin-left), et votre CSS doit faire de même. Le sélecteur ne traduit rien : votre texte vient de vos propres traductions.

Étape 6 — Les étiquettes des assistants, dans la langue du lecteur

<script lang="ts">
  import { labelsFor } from "@lilydesignsystem/svelte-locale-translations";
  import sw from "@lilydesignsystem/svelte-locale-translations/sw-001";
  import DataGrid from "@lilydesignsystem/svelte-data-grid";
</script>

<DataGrid label="Wagonjwa" labels={labelsFor("data-grid", sw)} … />

La grille de données, le tableau kanban, le calendrier, le diagramme de Gantt et le filtre contiennent de nombreuses étiquettes pour lecteurs d'écran. Lily les fournit en 64 langues sous forme de paquets d'étiquettes. Seul l'anglais est relu ; les 63 autres sont des brouillons automatiques : faites vérifier la formulation par un locuteur natif avant de vous y fier. Un paquet ne se rabat jamais sur une autre langue.

Vérifiez votre travail : passez la page en arabe et vérifiez que la mise en page se reflète sans texte coupé ; saisissez une date dans votre ordre et confirmez que la valeur envoyée est au format ISO ; donnez à quelqu'un un nom d'un seul mot et une adresse sans code postal, et assurez-vous que le formulaire accepte les deux.
