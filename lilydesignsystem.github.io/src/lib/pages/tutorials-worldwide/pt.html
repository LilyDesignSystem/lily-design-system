Um formulário que funciona em todo o mundo

O Lily visa todos os países, não um. Não traz texto em inglês nem pressupõe nenhum país, por isso as escolhas que tornam um formulário local são suas, feitas de propósito. Este tutorial percorre-as.

O que você vai construir

Um formulário de registo para uma clínica que atende pessoas de muitos países: um nome, uma data de nascimento, uma morada, um telefone, uma taxa e uma página que se lê da direita para a esquerda quando deve. Os exemplos usam Svelte; todos os catálogos aceitam as mesmas props. Cerca de 20 minutos, depois do tutorial de formulários acessíveis.

Passo 1 — Nomes: um campo, não dois

<label class="label" for="name">Full name</label>
<TextInput id="name" name="name" autocomplete="name" label="Full name" />

«Nome próprio» e «apelido» falham com muitas pessoas: um nome único, o apelido primeiro, dois apelidos, um patronímico. Peça o nome completo num só campo e, se precisar de saber como tratar alguém, pergunte à parte.

Passo 2 — Datas: as partes na ordem do leitor

<DateField
  label="Date of birth"
  dayLabel="Day"
  monthLabel="Month"
  yearLabel="Year"
  order="dmy"
  autocomplete="bday"
  name="dob"
  bind:value={dob}
/>

order é "dmy", "mdy" ou "ymd": escolha a que os seus leitores esperam, porque 03/04 é março num país e abril no seguinte. O valor é sempre ISO (YYYY-MM-DD), seja qual for a ordem. Para uma data que alguém só sabe em parte, como quando uma doença começou, precision="month" guarda 2019-03 e nunca inventa um dia.

Para mostrar uma data, formate-a com Intl.DateTimeFormat no idioma do leitor; o Lily nunca formata por si.

Passo 3 — Moradas: a forma de nenhum país por omissão

<AddressInput label="Home address">
  <label class="label" for="address">Address</label>
  <textarea class="text-area-input" id="address" name="address" autocomplete="street-address" rows="4"></textarea>
  <label class="label" for="country">Country or territory</label>
  <select class="select" id="country" name="country" autocomplete="country"> … </select>
</AddressInput>

AddressInput é um grupo com nome; os campos lá dentro são seus. Uma morada em texto livre mais um país funciona em todo o lado. Se a dividir, faça-o por país (o código postal é opcional ou inexistente em muitos) e nunca torne obrigatório um campo de «estado».

Passo 4 — Telefones e dinheiro

<TelInput label="Phone number" name="phone" autocomplete="tel" />
<CurrencyInput label="Fee" currencyCode="KES" bind:value={fee} />

Aceite o telefone como foi escrito, com espaços e um +; não imponha o formato de um país. CurrencyInput não tem moeda por omissão: currencyCode (ISO 4217) é obrigatório, porque uma moeda por omissão seria o dinheiro de um só país.

Passo 5 — Direção e idioma

<LocalePicker label="Language" locales={["en", "fr", "ar", "sw"]} bind:value={locale} />

O seletor de idioma define lang e dir na página, para que o árabe ou o hebraico se leiam da direita para a esquerda. Todos os componentes Lily herdam dir; os temas usam propriedades lógicas (margin-inline-start, não margin-left), e o seu CSS também deve. O seletor não traduz nada: o seu texto vem das suas próprias traduções.

Passo 6 — Os rótulos dos ajudantes, no idioma do leitor

<script lang="ts">
  import { labelsFor } from "@lilydesignsystem/svelte-locale-translations";
  import sw from "@lilydesignsystem/svelte-locale-translations/sw-001";
  import DataGrid from "@lilydesignsystem/svelte-data-grid";
</script>

<DataGrid label="Wagonjwa" labels={labelsFor("data-grid", sw)} … />

A grelha de dados, o quadro kanban, o calendário, o gráfico de Gantt e o filtro têm muitos rótulos para leitores de tela. O Lily fornece-os em 64 idiomas como pacotes de rótulos. Só o inglês está revisto; os outros 63 são rascunhos automáticos, por isso peça a um falante nativo que verifique o texto antes de confiar num. Um pacote nunca recorre a outro idioma.

Verifique o seu trabalho: mude a página para árabe e verifique que o layout se espelha sem texto cortado; introduza uma data na sua ordem e confirme que o valor enviado é ISO; dê a alguém um nome de uma só palavra e uma morada sem código postal, e garanta que o formulário aceita ambos.
