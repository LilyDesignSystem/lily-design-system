AI エージェントのスキルで、Lily はさらに使いやすくなります

Lily は、一般向け、フレームワークごと、サブプロジェクトごとの的を絞ったスキルを提供します。 エージェントは必要な文脈だけを読み込み、不要なものは読み込みません。

どのスキルが必要ですか？

各階層は、それぞれ異なる問いに答えます。Lily をまだ知らないときは、一般向けスキルを読み込みます。 フレームワークは分かっていても、どのサブプロジェクトが必要か分からないときは、フレームワークのスキルを読み込みます。 取り組む対象が正確に分かっているときは、headless-skill か helpers-skill を直接読み込みます。

  • 一般 / メンテナー — 「Lily とは何か？」/「このモノレポはどう構成されているか？」 — lily-design-system-skill, lily-design-system-maintainer-skill
  • フレームワークの総合スキル — 「{framework} には何があり、どの部品が必要か？」 — 8 個。 各フレームワークに {framework}-skill が 1 つずつ
  • ヘッドレス / ヘルパー — 「{framework} のコンポーネントや *-picker ヘルパーを正確にどう使うか？」 — 16 個。 各フレームワークに {framework}-headless-skill と {framework}-helpers-skill が 1 つずつ

8 つのフレームワーク

どのフレームワークにも、同じ 3 階層の構成があります。総合スキルは、そのフレームワークの実在するすべてのサブプロジェクトを対応づけます。 これには、兄弟の 2 つのスキルがどちらも扱わないサンプルアプリも含まれます。そして約束事を繰り返さず、各サブプロジェクトを指し示します。

Web Components は、両方向での唯一の例外です。ヘッドレスカタログは意図的に 581 個中 546 個の範囲で（ネイティブのカスタム要素で、フレームワークのランタイムはなく、 残りの 35 個のコンポーネントは恒久的に対象外です）、Web Components のサンプルアプリもまだありません。総合スキルは、あるかのようにほのめかさず、ありのままにそう述べています。

スキルを 1 つ追加する

各スキルは SKILL.md ファイルと補助ファイルで構成され、ビルド手順はありません。必要なものを、お使いの Claude Code がスキルを読み込む場所にクローンしてください （プロジェクトやアカウントのスキルディレクトリについては、上にリンクした公式ドキュメントを参照）。 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-skill

複数のフレームワークにまたがって作業する場合や、モノレポ自体を扱う場合は、代わりに 正式なモノレポをクローンしてください。 27 個のスキルはすべてそのルートにあり、それらが説明するヘッドレスライブラリ、ヘルパーのカタログ、サンプルアプリと並んでいます。
