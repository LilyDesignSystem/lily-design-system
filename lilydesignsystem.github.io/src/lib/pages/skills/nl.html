Skills voor AI-agenten maken Lily nog makkelijker

Lily levert gerichte skills – algemeen, per framework en per subproject – zodat een agent precies de context laadt die hij nodig heeft en niets wat hij niet nodig heeft.

Welke skill wil je?

Elke laag beantwoordt een andere vraag. Laad de algemene skill als je Lily nog niet kent. Laad een frameworkskill als je je framework kent maar niet welk subproject je nodig hebt. Laad een headless-skill of helpers-skill rechtstreeks als je al precies weet waaraan je werkt.

  • Algemeen / beheerder – „Wat is Lily?” / „Hoe is deze monorepo opgebouwd?” – lily-design-system-skill, lily-design-system-maintainer-skill
  • Frameworkparaplu – „Wat is er beschikbaar voor {framework}, en welk onderdeel heb ik nodig?” – 8, telkens één {framework}-skill
  • Headless / helpers – „Hoe gebruik ik precies de componenten / *-picker-helpers van {framework}?” – 16, telkens één {framework}-headless-skill en één {framework}-helpers-skill

De acht frameworks

Elk framework krijgt dezelfde stapel van drie lagen. De paraplu-skill brengt alle echte subprojecten van dat framework in kaart – inclusief de voorbeeldapp, die geen van zijn twee zusterskills dekt – en wijst naar beneden naar die subprojecten in plaats van hun contracten te herhalen.

Web Components is de enige uitzondering in beide richtingen: de headless catalogus heeft een bewuste scope van 536 van 571 (native custom elements, geen framework-runtime; de overige 35 componenten zijn permanent uitgesloten), en er is nog geen voorbeeldapp voor Web Components – de paraplu-skill zegt dat in plaats van te suggereren dat die er is.

Voeg één skill toe

Elke skill is een SKILL.md-bestand – plus ondersteunende bestanden, geen buildstap. Kloon degene die je nodig hebt naar de plek waar je Claude Code-configuratie skills laadt (zie de hierboven gelinkte officiële documentatie voor de skillsmap van je project of account): 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-skill

Werk je met meerdere frameworks, of aan de monorepo zelf? Kloon dan de canonieke monorepo – alle 26 skills staan al in de root, naast de headless bibliotheken, de helpercatalogi en de voorbeeldapps die ze beschrijven.
