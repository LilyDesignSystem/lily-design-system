AI 에이전트의 스킬이 Lily를 더 쉽게 만듭니다

Lily는 일반, 프레임워크별, 하위 프로젝트별로 초점을 맞춘 스킬을 제공하므로, 에이전트는 필요한 맥락만 불러오고 필요 없는 것은 불러오지 않습니다.

어떤 스킬이 필요하신가요?

각 계층은 서로 다른 질문에 답합니다. Lily를 아직 모를 때는 일반 스킬을 불러오세요. 프레임워크는 알지만 어떤 하위 프로젝트가 필요한지 모를 때는 프레임워크 스킬을 불러오세요. 무엇을 작업하는지 정확히 알 때는 headless-skill이나 helpers-skill을 바로 불러오세요.

  • 일반 / 유지관리자 — “Lily란 무엇인가?” / “이 모노레포는 어떻게 구성되어 있는가?” — lily-design-system-skill, lily-design-system-maintainer-skill
  • 프레임워크 통합 스킬 — “{framework}에는 무엇이 있고, 어떤 부분이 필요한가?” — 8개. 프레임워크마다 {framework}-skill 하나씩
  • 헤드리스 / 도우미 — “{framework}의 컴포넌트와 *-picker 도우미를 정확히 어떻게 쓰는가?” — 16개. 프레임워크마다 {framework}-headless-skill과 {framework}-helpers-skill 하나씩

여덟 가지 프레임워크

모든 프레임워크는 같은 3단 구성을 갖습니다. 통합 스킬은 그 프레임워크의 실제 하위 프로젝트를 모두 대응시키며, 자매 스킬 두 개가 모두 다루지 않는 예제 앱도 포함합니다. 그리고 규약을 반복하는 대신 각 하위 프로젝트를 가리킵니다.

Web Components 스킬 스킬 (536/571) 스킬

Web Components는 양쪽 모두에서 유일한 예외입니다. 헤드리스 카탈로그는 의도적으로 571개 중 536개 범위이며(네이티브 커스텀 엘리먼트이고 프레임워크 런타임이 없으며, 나머지 35개 컴포넌트는 영구적으로 제외됩니다), Web Components 예제 앱은 아직 없습니다. 통합 스킬은 있는 것처럼 암시하지 않고 그대로 그렇게 밝힙니다.

스킬 하나 추가하기

각 스킬은 SKILL.md 파일과 보조 파일로 이루어져 있으며 빌드 단계가 없습니다. 필요한 것을 Claude Code가 스킬을 불러오는 위치에 복제하세요(프로젝트나 계정의 스킬 디렉터리는 위에 링크한 공식 문서를 참고하세요). 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-skill
