Skill บนเอเจนต์ AI ทำให้ Lily ใช้ง่ายขึ้นอีก

Lily มี skill ที่เจาะจง — ทั่วไป ต่อเฟรมเวิร์ก และต่อโครงการย่อย — เอเจนต์จึงโหลดเฉพาะบริบทที่ต้องการ และไม่โหลดสิ่งที่ไม่ต้องการ

คุณต้องการ skill ไหน?

แต่ละระดับตอบคำถามที่ต่างกัน โหลด skill ทั่วไปเมื่อคุณยังไม่รู้จัก Lily โหลด skill ของเฟรมเวิร์กเมื่อคุณรู้จักเฟรมเวิร์กของคุณแต่ไม่รู้ว่าต้องใช้โครงการย่อยใด โหลด headless-skill หรือ helpers-skill โดยตรงเมื่อคุณรู้แน่ชัดอยู่แล้วว่ากำลังทำงานกับอะไร

  • ทั่วไป / ผู้ดูแล — “Lily คืออะไร?” / “โมโนรีโพนี้ประกอบกันอย่างไร?” — lily-design-system-skill, lily-design-system-maintainer-skill
  • skill ร่มของเฟรมเวิร์ก — “มีอะไรให้ใช้สำหรับ {framework} และฉันต้องการส่วนไหน?” — 8 รายการ เฟรมเวิร์กละหนึ่ง {framework}-skill
  • Headless / ตัวช่วย — “ฉันใช้คอมโพเนนต์ / ตัวช่วย *-picker ของ {framework} อย่างไรกันแน่?” — 16 รายการ เฟรมเวิร์กละหนึ่ง {framework}-headless-skill และหนึ่ง {framework}-helpers-skill

แปดเฟรมเวิร์ก

ทุกเฟรมเวิร์กมีสแตกสามชั้นเหมือนกัน skill ร่มจะแมปโครงการย่อยจริงทั้งหมดของเฟรมเวิร์กนั้น — รวมถึงแอปตัวอย่างซึ่ง skill พี่น้องทั้งสองไม่ครอบคลุม — และชี้ลงไปยังโครงการเหล่านั้นแทนที่จะพูดซ้ำข้อตกลงของมัน

Web Components เป็นข้อยกเว้นเพียงรายเดียวทั้งสองทาง: แคตตาล็อก headless ของมันมีขอบเขตตั้งใจที่ 536 จาก 571 (custom element แบบเนทีฟ ไม่มีรันไทม์ของเฟรมเวิร์ก ส่วนอีก 35 คอมโพเนนต์ถูกยกเว้นถาวร) และยังไม่มีแอปตัวอย่าง Web Components — skill ร่มของมันบอกเช่นนั้นแทนที่จะบอกเป็นนัยว่ามี
