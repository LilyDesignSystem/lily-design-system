Les compétences sur les agents IA rendent Lily encore plus simple

Lily fournit des compétences ciblées — générales, par framework et par sous-projet — pour qu'un agent charge exactement le contexte dont il a besoin, et rien de plus.

Quelle compétence voulez-vous ?

Chaque niveau répond à une question différente. Chargez la compétence générale quand vous ne connaissez pas encore Lily. Chargez une compétence de framework quand vous connaissez votre framework mais pas le sous-projet dont vous avez besoin. Chargez directement une compétence headless ou d'assistants quand vous savez exactement sur quoi vous travaillez.

  • Générale / maintenance — « Qu'est-ce que Lily ? » / « Comment ce monodépôt est-il organisé ? » — lily-design-system-skill, lily-design-system-maintainer-skill
  • Parapluie de framework — « Qu'y a-t-il pour {framework}, et de quel élément ai-je besoin ? » — 8, une {framework}-skill chacun
  • Headless / assistants — « Comment utiliser exactement les composants / assistants *-picker de {framework} ? » — 16, une {framework}-headless-skill et une {framework}-helpers-skill chacun

Les huit frameworks

Chaque framework reçoit la même pile à trois niveaux. La compétence parapluie cartographie tous les vrais sous-projets de ce framework — y compris l'application d'exemple, que ses deux compétences sœurs ne couvrent pas — et renvoie vers eux plutôt que de répéter leurs contrats.

Web Components est la seule exception dans les deux sens : son catalogue headless a un périmètre délibéré de 536 sur 571 (éléments personnalisés natifs, sans environnement d'exécution de framework ; les 35 autres composants sont exclus de façon permanente), et il n'existe pas encore d'application d'exemple Web Components — sa compétence parapluie le dit plutôt que de laisser croire qu'il y en a une.

Ajouter une compétence

Chaque compétence est un fichier SKILL.md accompagné de fichiers annexes, sans étape de compilation. Clonez celle dont vous avez besoin là où votre installation de Claude Code charge ses compétences (consultez la documentation officielle liée ci-dessus pour le répertoire de compétences de votre projet ou de votre compte) :

git clone https://github.com/LilyDesignSystem/lily-design-system-svelte-skill

Vous travaillez avec plusieurs frameworks, ou sur le monodépôt lui-même ? Clonez plutôt le monodépôt canonique — les 26 compétences s'y trouvent déjà à la racine, avec les bibliothèques headless, les catalogues d'assistants et les applications d'exemple qu'elles décrivent.
