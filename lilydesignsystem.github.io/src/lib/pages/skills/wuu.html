AI 代理上个技能让 Lily 更加简单

Lily 附带有针对性个技能——通用个、按框架个、按子项目的——这样代理只加载伊恰好需要个上下文，勿多也勿少。

侬需要哪种技能？

每一层回答不同个问题。当侬还勿了解 Lily 时，加载通用技能。当侬了解自己个框架但勿知道需要哪个子项目时，加载框架技能。当侬已经确切知道自己在做啥时，直接加载 headless 技能或辅助组件技能。

  • 通用 / 维护 — “Lily 是啥？” / “搿个单体仓库是如何组织个？” — lily-design-system-skill、lily-design-system-maintainer-skill
  • 框架总览 — “{framework} 有哪些可用个内容，我需要哪一块？” — 8 个，每个框架一个 {framework}-skill
  • Headless / 辅助组件 — “我具体该如何使用 {framework} 个组件 / *-picker 辅助组件？” — 16 个，每个框架各一个 {framework}-headless-skill 搭 {framework}-helpers-skill

八种框架

每个框架侪获得同样个三层结构。总览技能会梳理该框架所有真实个子项目——包括伊个两个同级技能侪未涵盖个示例应用——并指向伊拉，而不是重复伊拉个契约。

添加一项技能

每项技能侪是一个 SKILL.md 文件，外加辅助文件，无需构建步骤。把侬需要个那一个克隆到侬个 Claude Code 加载技能个位置（项目或账户个技能目录请参阅上方链接个官方文档）：

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-skill

要跨多个框架工作，或在单体仓库本身上工作？那就改为克隆规范单体仓库——全部 27 项技能已在其根目录，与伊拉所描述个 headless 库、辅助组件目录搭示例应用放在一起。
