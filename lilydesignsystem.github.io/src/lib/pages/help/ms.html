Pasang

Lily tinggal dalam satu monorepo Git, dengan direktori bagi setiap perpustakaan tanpa kepala rangka kerja, pakej pembantu dan aplikasi contoh. Cara terpantas mencuba ialah mengklon monorepo dan membuka perpustakaan tanpa kepala untuk tindanan anda: 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-react-headless
pnpm install

Corak yang sama berfungsi untuk rangka kerja lain:

  • @lilydesignsystem/html-headless — tiada pemasangan diperlukan; salin .html fail
  • @lilydesignsystem/svelte-headless — pnpm install
  • @lilydesignsystem/react-headless — pnpm install
  • @lilydesignsystem/vue-headless — pnpm install
  • @lilydesignsystem/angular-headless — pnpm install
  • @lilydesignsystem/nunjucks-headless — pnpm install
  • lily-design-system-blazor-headless — dotnet build

Perpustakaan tanpa kepala direka untuk diklon atau divendor — anggap sumber sebagai punca kebenaran dan salin apa yang anda perlukan. pembantu keutamaan turut disediakan sebagai pakej boleh dipasang dengan saluran binaan dan penerbitan (npm untuk rangka kerja JS, NuGet untuk Blazor).

Gunakan komponen tanpa kepala

Komponen tanpa kepala menyediakan HTML semantik, ARIA dan prop — tetapi tiada CSS. Berikut ialah Button dalam setiap rangka kerja:

HTML

<button class="button" type="button" aria-label="Save">
  Save
</button>

Svelte

<script>
  import Button from "lily-design-system-svelte-headless/components/Button/Button.svelte";
</script>

<Button onclick={save}>Save</Button>

React

import Button from "lily-design-system-react-headless/components/Button";

<Button onClick={save}>Save</Button>

Vue

<script setup>
  import Button from "lily-design-system-vue-headless/components/Button.vue";
</script>

<Button @click="save">Save</Button>

Angular

import { Button } from "@lilydesignsystem/angular-headless";

@Component({
  imports: [Button],
  template: `<lily-button (click)="save()">Save</lily-button>`,
})

Blazor

<Button OnClick="Save">Save</Button>

Nunjucks

{% from "components/button/macro.njk" import button %}

{{ button({ text: "Save", type: "button" }) }}

Gunakan contoh bergaya

Aplikasi contoh termasuk CSS, laluan dan halaman demo penuh. Cara terpantas bereksperimen ialah memulakan aplikasi contoh SvelteKit, Next, Nuxt, Analog atau Eleventy dan melihat demo di /components. 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-sveltekit-examples
pnpm install
pnpm run dev

Kemudian buka http://localhost:5173 dan layari /components.

Penggayaan dan token reka bentuk

Setiap komponen dipaparkan dengan satu kelas kebab-case pada elemen akarnya. Contohnya, <Button> memaparkan <button class="button">. Gayakan sesuka hati: 

.button {
  background: var(--my-primary);
  color: #fff;
  padding: 0.75rem 1.5rem;
  border-radius: 0.5rem;
}
.button:hover { background: var(--my-primary-hover); }

Palet warna Lily lalai (digunakan dalam aplikasi contoh) ialah:

  • Utama: #2563eb
  • Bahaya: #dc2626
  • Amaran: #f59e0b
  • Kejayaan: #16a34a
  • Latar halaman: #f9fafb
  • Latar kad: #ffffff

Ini cadangan, bukan keperluan. Gantikannya dengan palet jenama anda sendiri dan Lily akan menyesuaikan diri dengan senang hati.

Tema siap pakai

Tidak mahu menulis CSS dari kosong? Lily disertakan dengan 57 tema rujukan kendiri dalam direktori themes/ . Setiap satu ialah satu helaian gaya yang menyasarkan cangkuk kelas Lily — pautkan dan anda sudah digayakan: 

<link rel="stylesheet" href="/assets/themes/united-kingdom-government-digital-service.css" />

Set ini meliputi:

  • Sektor awam — NHS England, NHS Scotland dan NHS Wales (varian untuk pesakit dan pengamal masing-masing), GOV.UK GDS dan U.S. Web Design System.
  • Diilhamkan vendor — Adobe Spectrum, Mozilla Protocol.
  • Serba guna — light, dark, nord, dracula, wireframe, dan tiga puluhan lagi.

Pemilih tema menggunakan :where(...), jadi CSS anda sendiri sentiasa menang dari segi kekhususan. Pasangkan dengan pembantu theme-picker di bawah untuk penukaran runtime, atau ikuti tutorial tema.

Pembantu keutamaan

Setiap rangka kerja mempunyai lapan pemilih kecil, masing-masing dalam pakej lily-design-system-{framework}-{package} tersendiri (dan picker-bar yang menghimpunkannya). Setiap satu ialah butang ikon tanpa kepala yang membuka popup — kotak senarai, senarai pautan, borang carian, atau (untuk date-time-picker) dialog pemilih tarikh — bukan natif <select>; selamat untuk SSR; dan disertakan tanpa CSS:

  • theme-picker — memuatkan helaian gaya tema semasa runtime dengan menukar <link>yang diurus, menetapkan data-theme pada dokumen, dan secara pilihan menyimpan ke localStorage.
  • locale-picker — menetapkan lang dan dir (dengan pengesanan RTL automatik) supaya perpustakaan i18n anda boleh mengikutinya; ia sendiri tidak menerjemah.
  • text-size-picker — menetapkan data-text-size pada dokumen; CSS anda memetakan setiap nilai kepada saiz fon.
  • motion-picker — menetapkan data-motion pada dokumen, bermula daripada tetapan gerakan dikurangkan pelawat; CSS dan skrip anda memutuskan apa yang ditindas.
  • search-picker — butang ikon yang membuka medan carian; penghantaran menavigasi ke halaman carian. Memiliki tindakan, bukan keutamaan.
  • link-picker — ikon rumah yang membuka menu pautan halaman yang ditakrifkan aplikasi anda (Utama, Perihal Kami, Hubungi Kami, Dasar Privasi, …). Memiliki tindakan, bukan keutamaan.
  • share-picker — membuka helaian kongsi natif atau senarai destinasi yang dibekalkan pengguna, ditambah salin-URL. Memiliki tindakan, bukan keutamaan: tidak menggunakan apa-apa, tidak menyimpan apa-apa.
  • date-time-picker — medan teks ditambah dialog pemilih tarikh APG untuk tarikh, masa, atau kedua-duanya. Memiliki nilai borang, bukan keutamaan: rentetan ISO berulang-alik ke <input type="date">.

cd lily-design-system/lily-design-system-svelte-theme-picker

Katalog Svelte ialah rujukan kanonik; port React, Vue, Angular, HTML, Nunjucks, Web Components dan Blazor sepadan dengannya kontrak demi kontrak. Lihat tutorial pembantu.

Kebolehcapaian

Komponen menyasarkan WCAG 2.2 AAA. Mereka mengikut corak ini:

  • Elemen HTML semantik berbanding generik <div>s.
  • <label for="id"> memaut label kepada input.
  • aria-labelledby / aria-describedby untuk rujukan silang.
  • aria-invalid + aria-errormessage untuk keadaan ralat.
  • role="alert" dan aria-live untuk kandungan dinamik.
  • aria-pressed, aria-expanded, aria-current untuk keadaan.
  • Roving tabindex untuk grid.

Penunjuk fokus sengaja dibekalkan oleh pengguna — Lily tidak pernah melukis gelang fokus lalai yang bertembung dengan reka bentuk anda. Aplikasi contoh mengekalkan garis dasar axe-core yang bersih merentas laluan mereka.

Pengantarabangsaan

Setiap label, pemegang tempat, mesej ralat dan teks butang ialah prop. Tiada rentetan dikodkan keras. Masukkan rangka kerja terjemahan pilihan anda — Paraglide, i18next, vue-i18n, react-intl, fail .resx, apa sahaja.

Untuk tarikh, nombor dan mata wang, komponen menerima rentetan yang telah diformat: anda memformat dengan Intl.DateTimeFormat / Intl.NumberFormat / perpustakaan pilihan anda dan menghantar hasilnya.

Pembantu locale-picker memberi isyarat lokal yang dipilih kepada perpustakaan i18n anda dengan menetapkan lang dan dir pada akar dokumen.

Ujian

Setiap subprojek rangka kerja menghantar ujiannya sendiri menggunakan tindanan idiomatiknya:

  • HTML: WebDriverIO menjalankan pelayar sebenar.
  • Svelte: Vitest + @testing-library/svelte.
  • React: Vitest + @testing-library/react.
  • Vue: Vitest + @testing-library/vue.
  • Angular: Vitest + TestBed (melalui pemalam Analog Vite).
  • Nunjucks: Vitest dengan pembantu paparan.
  • Blazor: bUnit.

Ujian menggunakan hanya pemadan terbina dalam Vitest — tidak pernah jest-dom pemadan. Ini memastikan suite ujian mudah alih. Aplikasi contoh menambah suite hujung-ke-hujung Playwright, garis dasar kebolehcapaian axe-core dan sapuan viewport responsif.

Ejen AI

Penyelesaian masalah

Komponen dipaparkan tetapi kelihatan tidak bergaya

Itulah tanpa kepala berfungsi seperti yang dimaksudkan — tiada CSS disertakan dengan komponen. Sama ada tulis CSS terhadap kelas kebab-case komponen (ditunjukkan pada setiap halaman katalog) atau pautkan salah satu daripada 57 tema siap pakai.

CSS saya nampaknya tidak digunakan di atas tema

Ia sepatutnya — pemilih tema dibalut dalam :where(...), yang mempunyai kekhususan sifar. Jika peraturan masih kalah, semak bahawa helaian gaya anda dimuatkan selepas helaian gaya tema <link> dan bahawa pemilih benar-benar sepadan dengan cangkuk kelas komponen.

pnpm install gagal dengan ralat peer atau versi

Gunakan pnpm semasa (v10+) dan Node 22+. Setiap subprojek mengepin versi rangka kerjanya dalam package.jsonsendiri; jika rantai alat global anda lebih lama, pnpm env use --global lts ialah penyelesaian terpantas.

Pembaca skrin mengumumkan nama yang salah untuk kawalan

Semak prop wajib komponen label — komponen yang tiada teks kelihatan memerlukannya, dan aria-label / aria-labelledby yang dibekalkan pengguna dan dihantar melalui rest-props sengaja menang atas pendawaian terbina dalam. Setiap halaman katalog mendokumenkan kontrak ARIA komponen.

Pembantu theme-picker tidak menukar helaian gaya

Sahkan bahawa themesUrl menunjuk ke direktori yang boleh diambil pelayar (hidangkan themes/ fail sebagai aset statik) dan bahawa slug tema dalam prop themes sepadan dengan nama fail. Pembantu menukar href satu <link data-lily-theme-picker> yang diurus — periksa dalam devtools untuk melihat URL yang diminta.

Menyumbang

Lily masih muda dan mengalu-alukan kerjasama. Sumbangan paling berguna sekarang ialah:

  • Komponen baharu (terutamanya corak daripada sistem reka bentuk yang mantap).
  • Tema baharu — masing-masing satu helaian gaya kendiri, PR pertama yang berskop baik.
  • Penggayaan contoh yang lebih baik — tunjukkan apa yang mungkin.
  • Terjemahan rentetan aplikasi contoh.
  • Laporan pepijat dengan pengeluaran semula minimum.
  • Audit kebolehcapaian dengan pembaca skrin dan teknologi bantuan.

Soalan lazim

Mengapa tanpa kepala dan bukan bergaya?

Komponen pra-gaya memang mudah — sehingga ia tidak sepadan dengan jenama anda. Komponen tanpa kepala memerlukan sedikit lebih kerja di awal tetapi memberi anda kawalan penuh ke atas reka bentuk visual. Aplikasi contoh dan 57 tema menunjukkan cara menggayakannya; anda boleh mengambilnya atau menggantikannya sepenuhnya. Hujah yang lebih panjang terdapat di Mengapa Lily.

Mengapa begitu banyak komponen?

Lily bertujuan meliputi corak yang diperlukan kebanyakan aplikasi tanpa memaksa anda membinanya dari awal — termasuk perkara mendalam seperti input pengecam kebangsaan dan scrollytelling editorial. Katalog ini diambil daripada sedozen sistem reka bentuk mantap serta kerja asli — lihat Perihal.

Bolehkah saya menggunakan Lily dengan Tailwind?

Ya. Setiap komponen mendedahkan satu kelas akar kebab-case ditambah className / classyang dibekalkan pengguna. Letakkan utiliti Tailwind di atasnya sesuka hati.

Bolehkah saya menggunakan Lily dengan rangka kerja CSS semantik seperti DaisyUI?

Ya. Nama kelas kebab-case pada elemen akar berfungsi sebagai cangkuk CSS semantik. Pasangkan Lily dengan rangka kerja semantik dan anda mendapat komponen pra-gaya yang masih menghormati ARIA dan i18n.

Adakah terdapat pakej npm?

Pembantu pembantu keutamaan disediakan sebagai pakej dengan saluran penerbitan npm/NuGet. Perpustakaan komponen tanpa kepala direka untuk diklon atau divendor — sumber ialah serahan, supaya anda boleh membaca, memangkas dan memiliki tepat apa yang anda hantar. Penerbitan registri untuk perpustakaan tanpa kepala kekal dalam peta jalan.

Mengapa berbilang lesen?

Projek berbeza mempunyai keperluan lesen berbeza. BSD dan MIT bersifat permisif, Apache-2.0 mempunyai pemberian paten, dan pilihan GPL menyokong copyleft. Pilih yang sesuai dengan situasi anda.
