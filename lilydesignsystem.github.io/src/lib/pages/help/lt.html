Diegimas

Lily gyvena viename Git monorepo su katalogu kiekvieno karkaso bevaigei bibliotekai, pagalbiniams paketams ir pavyzdinei programai. Greičiausias būdas išbandyti — klonuoti monorepo ir atidaryti bevaigę biblioteką savo technologijų rinkiniui: 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-react-headless
pnpm install

Tas pats šablonas veikia ir kitiems karkasams:

  • @lilydesignsystem/html-headless — diegti nereikia; nukopijuokite .html failus
  • @lilydesignsystem/svelte-headless — pnpm install
  • @lilydesignsystem/react-headless — pnpm install
  • @lilydesignsystem/vue-headless — pnpm install
  • @lilydesignsystem/angular-headless — pnpm install
  • @lilydesignsystem/nunjucks-headless — pnpm install
  • lily-design-system-blazor-headless — dotnet build

Bevaigės bibliotekos sukurtos klonuoti ar įtraukti į projektą — laikykite pirminį kodą tiesos šaltiniu ir kopijuokite, ko reikia. nuostatų pagalbininkai papildomai tiekiami kaip diegiami paketai su kūrimo ir skelbimo konvejeriu (npm JS karkasams, NuGet Blazor).

Bevaigio komponento naudojimas

Bevaigiai komponentai tiekia semantinį HTML, ARIA ir savybes — bet ne CSS. Štai Button kiekviename karkase:

HTML

<button class="button" type="button" aria-label="Save">
  Save
</button>

Svelte

<script>
  import Button from "lily-design-system-svelte-headless/components/Button/Button.svelte";
</script>

<Button onclick={save}>Save</Button>

React

import Button from "lily-design-system-react-headless/components/Button";

<Button onClick={save}>Save</Button>

Vue

<script setup>
  import Button from "lily-design-system-vue-headless/components/Button.vue";
</script>

<Button @click="save">Save</Button>

Angular

import { Button } from "@lilydesignsystem/angular-headless";

@Component({
  imports: [Button],
  template: `<lily-button (click)="save()">Save</lily-button>`,
})

Blazor

<Button OnClick="Save">Save</Button>

Nunjucks

{% from "components/button/macro.njk" import button %}

{{ button({ text: "Save", type: "button" }) }}

Stilizuoto pavyzdžio naudojimas

Pavyzdinės programos apima CSS, maršrutus ir pilnus demonstracinius puslapius. Greičiausias būdas eksperimentuoti — paleisti SvelteKit, Next, Nuxt, Analog ar Eleventy pavyzdinę programą ir pamatyti demonstraciją adresu /components. 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-sveltekit-examples
pnpm install
pnpm run dev

Tada atidarykite http://localhost:5173 ir naršykite /components.

Stilizavimas ir dizaino žetonai

Kiekvienas komponentas atvaizduojamas su viena kebab-case klase savo šakniniame elemente. Pavyzdžiui, <Button> atvaizduojamas kaip <button class="button">. Stilizuokite kaip norite: 

.button {
  background: var(--my-primary);
  color: #fff;
  padding: 0.75rem 1.5rem;
  border-radius: 0.5rem;
}
.button:hover { background: var(--my-primary-hover); }

Numatytoji Lily spalvų paletė (naudojama pavyzdinėse programose) yra:

  • Pagrindinė: #2563eb
  • Pavojus: #dc2626
  • Įspėjimas: #f59e0b
  • Sėkmė: #16a34a
  • Puslapio fonas: #f9fafb
  • Kortelės fonas: #ffffff

Tai pasiūlymai, o ne reikalavimai. Pakeiskite juos savo prekės ženklo paletė, ir Lily mielai prisitaikys.

Paruoštos temos

Nenorite rašyti CSS nuo nulio? Lily tiekia 57 savarankiškas pavyzdines temas kataloge themes/ . Kiekviena yra vienas stilių lapas, taikantis Lily klasės kabliukus — susiekite jį ir esate stilizuoti: 

<link rel="stylesheet" href="/assets/themes/united-kingdom-government-digital-service.css" />

Rinkinys apima:

  • Viešasis sektorius — NHS England, NHS Scotland ir NHS Wales (kiekviena pacientams ir praktikams skirtais variantais), GOV.UK GDS ir U.S. Web Design System.
  • Tiekėjų įkvėptos — Adobe Spectrum, Mozilla Protocol.
  • Bendrosios paskirties — light, dark, nord, dracula, wireframe ir dar trisdešimt.

Temų selektoriai naudoja :where(...), todėl jūsų paties CSS visada laimi specifiškumu. Suporuokite jas su žemiau esančiu pagalbininku theme-picker perjungimui vykdymo metu arba vadovaukitės temų mokymu.

Nuostatų pagalbininkai

Kiekvienas karkasas turi aštuonis mažus parinkiklius, kiekvienas — atskiras lily-design-system-{framework}-{package} paketas (ir picker-bar , juos sujungiantis). Kiekvienas yra bevaigis piktogramos mygtukas, atidarantis iškylantįjį langą — sąrašo langelį, nuorodų sąrašą, paieškos formą ar (date-time-picker atveju) datos pasirinkimo dialogą — ne vietinis <select>; yra saugus SSR; ir netiekia CSS:

  • theme-picker — vykdymo metu įkelia temų stilių lapus pakeisdamas valdomą <link>, nustato data-theme dokumente ir pasirinktinai išsaugo localStorage.
  • locale-picker — nustato lang ir dir (su automatiniu RTL aptikimu), kad jūsų i18n biblioteka galėtų sekti; pats nieko neverčia.
  • text-size-picker — nustato data-text-size dokumente; jūsų CSS susieja kiekvieną reikšmę su šrifto dydžiu.
  • motion-picker — nustato data-motion dokumente, pradėdamas nuo lankytojo sumažinto judesio nustatymo; jūsų CSS ir scenarijai sprendžia, ką slopinti.
  • search-picker — piktogramos mygtukas, atidarantis paieškos lauką; pateikimas nukreipia į paieškos puslapį. Valdo veiksmą, o ne nuostatą.
  • link-picker — namo piktograma, atidaranti jūsų programos apibrėžtų puslapių nuorodų meniu (Pagrindinis, Apie mus, Kontaktai, Privatumo politika, …). Valdo veiksmą, o ne nuostatą.
  • share-picker — atidaro vietinį dalijimosi lapą arba vartotojo pateiktą paskirčių sąrašą, plius URL kopijavimą. Valdo veiksmą, o ne nuostatą: nieko netaiko, nieko neišsaugo.
  • date-time-picker — teksto laukas plius APG datos pasirinkimo dialogas datai, laikui ar abiem. Valdo formos reikšmę, o ne nuostatą: ISO eilutė konvertuojama pirmyn ir atgal į <input type="date">. 
git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-theme-picker

Svelte katalogas yra kanoninė nuoroda; React, Vue, Angular, HTML, Nunjucks, Web Components ir Blazor perkėlimai atitinka jį sutartis po sutarties. Žr. pagalbininkų mokymą.

Prieinamumas

Komponentai taikosi į WCAG 2.2 AAA. Jie laikosi šių šablonų:

  • Semantiniai HTML elementai vietoj bendrų <div>s.
  • <label for="id"> , susiejančių etiketes su įvestimis.
  • aria-labelledby / aria-describedby kryžminėms nuorodoms.
  • aria-invalid + aria-errormessage klaidų būsenoms.
  • role="alert" ir aria-live dinaminiam turiniui.
  • aria-pressed, aria-expanded, aria-current būsenai.
  • Roving tabindex tinkleliams.

Fokuso indikatorius sąmoningai pateikia vartotojas — Lily niekada nepiešia numatytojo fokuso žiedo, kuris prieštarautų jūsų dizainui. Pavyzdinės programos visuose savo maršrutuose išlaiko švarią axe-core bazinę liniją.

Internacionalizacija

Kiekviena etiketė, vietos žymeklis, klaidos pranešimas ir mygtuko tekstas yra savybė. Į kodą įrašytų eilučių nėra. Prijunkite pasirinktą vertimo karkasą — Paraglide, i18next, vue-i18n, react-intl, .resx failus, bet ką.

Datoms, skaičiams ir valiutoms komponentai priima iš anksto suformatuotas eilutes: formatuojate su Intl.DateTimeFormat / Intl.NumberFormat / jūsų mėgstama biblioteka ir perduodate rezultatą.

Pagalbininkas locale-picker praneša pasirinktą lokalę jūsų i18n bibliotekai nustatydamas lang ir dir dokumento šaknyje.

Testavimas

Kiekvienas karkaso paprojektis tiekia savo testus naudodamas savo idiomatinį technologijų rinkinį:

  • HTML: WebDriverIO, paleidžiantis tikras naršykles.
  • Svelte: Vitest + @testing-library/svelte.
  • React: Vitest + @testing-library/react.
  • Vue: Vitest + @testing-library/vue.
  • Angular: Vitest + TestBed (per Analog Vite papildinį).
  • Nunjucks: Vitest su atvaizdavimo pagalbininku.
  • Blazor: bUnit.

Testai naudoja tik Vitest įmontuotus atitikmenis — niekada jest-dom atitikmenų. Tai išlaiko testų rinkinius perkeliamus. Pavyzdinės programos prideda Playwright pilnos grandinės rinkinius, axe-core prieinamumo bazines linijas ir adaptyvių peržiūros langų peržiūrą.

Trikčių šalinimas

Komponentas atvaizduojamas, bet atrodo nestilizuotas

Tai bevaigiškumas, veikiantis kaip numatyta — su komponentu nėra tiekiamas jokis CSS. Arba parašykite CSS komponento kebab-case klasei (rodomai kiekviename katalogo puslapyje) arba susiekite vieną iš 57 paruoštų temų.

Atrodo, mano CSS netaikomas virš temos

Turėtų — temų selektoriai apgaubti :where(...), kuris turi nulinį specifiškumą. Jei taisyklė vis tiek pralaimi, patikrinkite, ar jūsų stilių lapas įkeliamas po temos <link> ir ar selektorius iš tikrųjų atitinka komponento klasės kabliuką.

pnpm install nepavyksta su peer arba versijos klaida

Naudokite dabartinį pnpm (v10+) ir Node 22+. Kiekvienas paprojektis savo karkaso versijas fiksuoja savo package.json; jei jūsų visuotinė įrankių grandinė senesnė, pnpm env use --global lts yra greičiausias sprendimas.

Ekrano skaitytuvas praneša neteisingą valdiklio pavadinimą

Patikrinkite komponento privalomą label savybę — komponentai be matomo teksto jos reikalauja, o vartotojo pateikti aria-label / aria-labelledby perduoti per rest-props sąmoningai laimi prieš integruotą sujungimą. Kiekvienas katalogo puslapis dokumentuoja komponento ARIA sutartį.

theme-picker pagalbininkas neperjungia stilių lapų

Patvirtinkite, kad themesUrl nurodo katalogą, kurį naršyklė gali gauti (teikite themes/ failus kaip statinius išteklius) ir kad temų trumpieji pavadinimai jūsų themes savybėje atitinka failų pavadinimus. Pagalbininkas keičia href vieno valdomo <link data-lily-theme-picker> — apžiūrėkite jį kūrėjo įrankiuose, kad pamatytumėte prašomą URL.

DUK

Kodėl bevaigis, o ne stilizuotas?

Iš anksto stilizuoti komponentai yra patogūs — kol neatitinka jūsų prekės ženklo. Bevaigiai komponentai pradžioje reikalauja šiek tiek daugiau darbo, bet suteikia visišką vizualinio dizaino kontrolę. Pavyzdinės programos ir 57 temos rodo stilizavimo būdus; galite juos pasiimti arba visiškai pakeisti. Ilgesnis argumentas yra Kodėl Lily.

Kodėl tiek daug komponentų?

Lily siekia apimti šablonus, kurių reikia daugumai programų, neversdamas jūsų jų kurti nuo nulio — įskaitant gilesnius dalykus, tokius kaip nacionalinių identifikatorių įvestis ir redakcinis scrollytelling. Katalogas semiasi iš tuzino nusistovėjusių dizaino sistemų ir originalaus darbo — žr. Apie.

Ar galiu naudoti Lily su Tailwind?

Taip. Kiekvienas komponentas atskleidžia vieną kebab-case šaknies klasę plius vartotojo pateiktą className / class. Sluoksniuokite Tailwind pagalbines klases viršuje, kaip norite.

Ar galiu naudoti Lily su semantiniais CSS karkasais, tokiais kaip DaisyUI?

Taip. Kebab-case klasių pavadinimai šakniniame elemente veikia kaip semantiniai CSS kabliukai. Suporuokite Lily su semantiniu karkasu, ir gausite iš anksto stilizuotus komponentus, kurie vis tiek gerbia ARIA ir i18n.

Ar yra npm paketas?

Nuostatų pagalbininkai tiekiami kaip paketai su npm/NuGet skelbimo konvejeriu. Bevaigės komponentų bibliotekos sukurtos klonuoti ar įtraukti į projektą — pirminis kodas yra tiekiamas produktas, todėl galite skaityti, genėti ir valdyti būtent tai, ką išleidžiate. Bevaigių bibliotekų skelbimas registruose tebėra plane.

Kodėl kelios licencijos?

Skirtingi projektai turi skirtingus licencijavimo poreikius. BSD ir MIT yra leidžiančios, Apache-2.0 turi patento suteikimą, o GPL parinktys palaiko copyleft. Pasirinkite tai, kas tinka jūsų situacijai.
