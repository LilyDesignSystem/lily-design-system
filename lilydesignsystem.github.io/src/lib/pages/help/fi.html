Asennus

Lily asuu yhdessä Git-monorepossa, jossa on hakemisto jokaisen kehyksen päättömälle kirjastolle, apupaketeille ja esimerkkisovellukselle. Nopein tapa kokeilla on kloonata monorepo ja avata oman pinosi päätön kirjasto: 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-react-headless
pnpm install

Sama malli toimii muille kehyksille:

  • @lilydesignsystem/html-headless – asennusta ei tarvita; kopioi .html -tiedostot
  • @lilydesignsystem/svelte-headless — pnpm install
  • @lilydesignsystem/react-headless — pnpm install
  • @lilydesignsystem/vue-headless — pnpm install
  • @lilydesignsystem/angular-headless — pnpm install
  • @lilydesignsystem/nunjucks-headless — pnpm install
  • lily-design-system-blazor-headless — dotnet build

Päättömät kirjastot on suunniteltu kloonattaviksi tai kopioitaviksi projektiin – pidä lähdekoodia totuuden lähteenä ja kopioi tarvitsemasi. asetusapurit toimitetaan lisäksi asennettavina paketteina rakennus- ja julkaisuputkella (npm JS-kehyksille, NuGet Blazorille).

Päättömän komponentin käyttö

Päättömät komponentit sisältävät semanttisen HTML:n, ARIA:n ja ominaisuudet – mutta eivät CSS:ää. Tässä Button kussakin kehyksessä:

HTML

<button class="button" type="button" aria-label="Save">
  Save
</button>

Svelte

<script>
  import Button from "lily-design-system-svelte-headless/components/Button/Button.svelte";
</script>

<Button onclick={save}>Save</Button>

React

import Button from "lily-design-system-react-headless/components/Button";

<Button onClick={save}>Save</Button>

Vue

<script setup>
  import Button from "lily-design-system-vue-headless/components/Button.vue";
</script>

<Button @click="save">Save</Button>

Angular

import { Button } from "@lilydesignsystem/angular-headless";

@Component({
  imports: [Button],
  template: `<lily-button (click)="save()">Save</lily-button>`,
})

Blazor

<Button OnClick="Save">Save</Button>

Nunjucks

{% from "components/button/macro.njk" import button %}

{{ button({ text: "Save", type: "button" }) }}

Tyylitellyn esimerkin käyttö

Esimerkkisovellukset sisältävät CSS:n, reitit ja täydet demosivut. Nopein tapa kokeilla on käynnistää SvelteKit-, Next-, Nuxt-, Analog- tai Eleventy-esimerkkisovellus ja katsoa demoa osoitteessa /components. 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-sveltekit-examples
pnpm install
pnpm run dev

Avaa sitten http://localhost:5173 ja selaa /components.

Tyylittely ja suunnittelutunnisteet

Jokainen komponentti renderöidään yhdellä kebab-case-luokalla juurielementissään. Esimerkiksi <Button> renderöityy muotoon <button class="button">. Tyylittele se haluamallasi tavalla: 

.button {
  background: var(--my-primary);
  color: #fff;
  padding: 0.75rem 1.5rem;
  border-radius: 0.5rem;
}
.button:hover { background: var(--my-primary-hover); }

Lilyn oletusvaripaletti (käytössä esimerkkisovelluksissa) on:

  • Ensisijainen: #2563eb
  • Vaara: #dc2626
  • Varoitus: #f59e0b
  • Onnistuminen: #16a34a
  • Sivun tausta: #f9fafb
  • Kortin tausta: #ffffff

Nämä ovat ehdotuksia, eivät vaatimuksia. Korvaa ne oman brändisi paletilla, niin Lily seuraa mukana mielellään.

Valmiit teemat

Etkö halua kirjoittaa CSS:ää alusta alkaen? Lily toimittaa 57 itsenäistä viiteteemaa hakemistossa themes/ . Jokainen on yksi tyylitiedosto, joka kohdistuu Lilyn luokkakoukkuihin – linkitä se, ja olet tyylitelty: 

<link rel="stylesheet" href="/assets/themes/united-kingdom-government-digital-service.css" />

Joukko kattaa:

  • Julkinen sektori – NHS England, NHS Scotland ja NHS Wales (kukin potilas- ja ammattilaisversiona), GOV.UK GDS ja U.S. Web Design System.
  • Toimittajista innoituksensa saaneet – Adobe Spectrum, Mozilla Protocol.
  • Yleiskäyttöiset – light, dark, nord, dracula, wireframe ja parikymmentä muuta.

Teemavalitsimet käyttävät :where(...):ia, joten oma CSS:äsi voittaa aina spesifisyydessä. Yhdistä ne alla olevaan theme-picker -apuriin ajonaikaista vaihtoa varten tai seuraa teemaopetusohjelmaa.

Asetusapurit

Jokaisella kehyksellä on kahdeksan pientä valitsinta, kukin omana lily-design-system-{framework}-{package} -pakettinaan (ja picker-bar , joka kokoaa ne yhteen). Jokainen on päätön kuvakepainike, joka avaa ponnahdusikkunan – luettelon, linkkiluettelon, hakulomakkeen tai (date-time-pickerin tapauksessa) päivämäärävalintaikkunan – ei natiivi <select>; on SSR-turvallinen; eikä sisällä CSS:ää:

  • theme-picker – lataa teemojen tyylitiedostot ajon aikana vaihtamalla hallittua <link>:ia, asettaa data-theme -attribuutin dokumentille ja tallentaa halutessa kohteeseen localStorage.
  • locale-picker – asettaa lang ja dir (automaattisella RTL-tunnistuksella), jotta i18n-kirjastosi voi seurata; ei käännä itse mitään.
  • text-size-picker – asettaa data-text-size -attribuutin dokumentille; CSS:äsi kohdistaa jokaisen arvon fonttikokoon.
  • motion-picker – asettaa data-motion -attribuutin dokumentille lähtien kävijän vähennetyn liikkeen asetuksesta; CSS:äsi ja skriptisi päättävät, mitä vaimennetaan.
  • search-picker – kuvakepainike, joka avaa hakukentän; lähettäminen siirtyy hakusivulle. Omistaa toiminnon, ei asetusta.
  • link-picker – kotikuvake, joka avaa valikon sovelluksesi määrittelemistä sivulinkeistä (Etusivu, Tietoa meistä, Ota yhteyttä, Tietosuojakäytäntö, …). Omistaa toiminnon, ei asetusta.
  • share-picker – avaa natiivin jakoikkunan tai kuluttajan antaman kohdeluettelon sekä URL:n kopioinnin. Omistaa toiminnon, ei asetusta: ei sovella mitään, ei tallenna mitään.
  • date-time-picker – tekstikenttä ja APG-päivämäärävalintaikkuna päivämäärälle, ajalle tai molemmille. Omistaa lomakkeen arvon, ei asetusta: ISO-merkkijono muuntuu edestakaisin muotoon <input type="date">.

cd lily-design-system/lily-design-system-svelte-theme-picker

Svelte-luettelo on kanoninen viite; React-, Vue-, Angular-, HTML-, Nunjucks-, Web Components- ja Blazor-portit vastaavat sitä sopimus sopimukselta. Katso apuriopetusohjelma.

Saavutettavuus

Komponentit tavoittelevat WCAG 2.2 AAA-tasoa. Ne noudattavat näitä malleja:

  • Semanttiset HTML-elementit yleisten <div>s.
  • <label for="id"> -elementtien sijaan, jotka yhdistävät nimiöt syötteisiin.
  • aria-labelledby / aria-describedby ristiviittauksiin.
  • aria-invalid + aria-errormessage virhetiloihin.
  • role="alert" ja aria-live dynaamiseen sisältöön.
  • aria-pressed, aria-expanded, aria-current tilaan.
  • Liikkuva tabindex ruudukoille.

Kohdistuksen ilmaisimet ovat tarkoituksella kuluttajan toimittamia – Lily ei koskaan piirrä oletuskohdistusrengasta, joka olisi ristiriidassa suunnittelusi kanssa. Esimerkkisovellukset pitävät puhtaan axe-core-perustason kaikilla reiteillään.

Kansainvälistäminen

Jokainen nimiö, paikkamerkki, virheilmoitus ja painiketeksti on ominaisuus. Kovakoodattuja merkkijonoja ei ole. Liitä valitsemasi käännyskehys – Paraglide, i18next, vue-i18n, react-intl, .resx-tiedostot, mikä tahansa.

Päivämäärille, luvuille ja valuutoille komponentit hyväksyvät valmiiksi muotoiltuja merkkijonoja: muotoilet itse käyttäen Intl.DateTimeFormat / Intl.NumberFormat / haluamaasi kirjastoa ja välität tuloksen.

Apuri locale-picker ilmoittaa valitun kielen i18n-kirjastollesi asettamalla lang ja dir dokumentin juureen.

Testaus

Jokainen kehyksen aliprojekti toimittaa omat testinsä käyttäen sen omaa tyypillistä pinoa:

  • HTML: WebDriverIO, joka ajaa oikeita selaimia.
  • Svelte: Vitest + @testing-library/svelte.
  • React: Vitest + @testing-library/react.
  • Vue: Vitest + @testing-library/vue.
  • Angular: Vitest + TestBed (Analog Vite -laajennuksen kautta).
  • Nunjucks: Vitest renderöintiapurilla.
  • Blazor: bUnit.

Testit käyttävät vain Vitestin sisäänrakennettuja vertaajia – ei koskaan jest-dom -vertaajia. Tämä pitää testisarjat siirrettävinä. Esimerkkisovellukset lisäävät Playwright-päästä päähän -sarjat, axe-core-saavutettavuusperustasot ja responsiivisen näkymäalueen läpikäynnin.

Tekoälyagentit

Tämä sivusto julkaisee llms.txt ja llms.json juuressaan – kuratoidun kartan tärkeimmistä sivuistaan, mille tahansa työkalulle, joka noudattaa llms.txt-käytäntöä.

Vianmääritys

Komponentti renderöityy mutta näyttää tyylittelemättömältä

Päätön toimii tarkoitetulla tavalla – komponentin mukana ei tule CSS:ää. Kirjoita CSS komponentin kebab-case-luokalle (näkyy jokaisella luettelosivulla) tai linkitä yksi 57 valmiista teemasta.

CSS:äni ei näytä vaikuttavan teeman päällä

Sen pitäisi – teemavalitsimet on kääritty :where(...):iin, jolla on nolla spesifisyyttä. Jos sääntö silti häviää, tarkista, että tyylitiedostosi latautuu teeman <link> -elementin jälkeen ja että valitsin todella vastaa komponentin luokkakoukkua.

pnpm install epäonnistuu peer- tai versiovirheeseen

Käytä ajantasaista pnpm:ää (v10+) ja Node 22+:aa. Jokainen aliprojekti kiinnittää kehysversionsa omaan package.json-tiedostoonsa; jos globaali työkaluketjusi on vanhempi, pnpm env use --global lts on nopein korjaus.

Näytönlukija ilmoittaa ohjaimelle väärän nimen

Tarkista komponentin pakollinen label -ominaisuus – komponentit, joilla ei ole näkyvää tekstiä, vaativat sellaisen, ja kuluttajan antama aria-label / aria-labelledby joka välitetään rest-propsien kautta, voittaa tarkoituksella sisäänrakennetun kytkennän. Jokainen luettelosivu dokumentoi komponentin ARIA-sopimuksen.

theme-picker-apuri ei vaihda tyylitiedostoja

Varmista, että themesUrl osoittaa hakemistoon, jonka selain voi hakea (tarjoa themes/ -tiedostot staattisina resursseina) ja että teemojen tunnisteet themes -ominaisuudessasi vastaavat tiedostonimiä. Apuri vaihtaa yhden hallitun href -elementin <link data-lily-theme-picker> -attribuuttia – tarkista se kehittäjätyökaluista nähdäksesi pyydettävän URL:n.

UKK

Miksi päätön eikä tyylitelty?

Valmiiksi tyylitellyt komponentit ovat käteviä – kunnes ne eivät sovi brändiisi. Päättömät komponentit vaativat hieman enemmän työtä alussa, mutta antavat täyden hallinnan visuaaliseen suunnitteluun. Esimerkkisovellukset ja 57 teemaa näyttävät tapoja tyylitellä ne; voit ottaa ne käyttöösi tai korvata ne kokonaan. Pidempi perustelu on sivulla Miksi Lily.

Miksi niin monta komponenttia?

Lily pyrkii kattamaan mallit, joita useimmat sovellukset tarvitsevat, pakottamatta sinua rakentamaan niitä alusta – mukaan lukien syvälliset jutut, kuten kansallisten tunnisteiden syötteet ja toimituksellinen scrollytelling. Luettelo ammentaa tusinasta vakiintunutta suunnittelujärjestelmää sekä omasta työstä – katso Tietoa.

Voinko käyttää Lilyä Tailwindin kanssa?

Kyllä. Jokainen komponentti tarjoaa yhden kebab-case-juuriluokan sekä kuluttajan antaman className / class:n. Kerro Tailwind-apuluokat päälle haluamallasi tavalla.

Voinko käyttää Lilyä semanttisten CSS-kehysten, kuten DaisyUI:n, kanssa?

Kyllä. Juurielementin kebab-case-luokkanimet toimivat semanttisina CSS-koukkuina. Yhdistä Lily semanttiseen kehykseen, niin saat valmiiksi tyylitellyt komponentit, jotka silti kunnioittavat ARIA:a ja i18n:ää.

Onko npm-pakettia?

asetusapurit toimitetaan paketteina npm/NuGet-julkaisuputkella. Päättömät komponenttikirjastot on suunniteltu kloonattaviksi tai kopioitaviksi projektiin – lähdekoodi on toimitettava tuote, joten voit lukea, karsia ja omistaa täsmälleen sen, minkä toimitat. Päättömien kirjastojen julkaisu rekistereihin on edelleen tiekartalla.

Miksi useita lisenssejä?

Eri projekteilla on erilaiset lisenssitarpeet. BSD ja MIT ovat salliavia, Apache-2.0:ssa on patenttimyöntö, ja GPL-vaihtoehdot tukevat copyleftiä. Valitse se, joka sopii tilanteeseesi.
