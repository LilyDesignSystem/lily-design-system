Uppsetning

Lily býr í einu Git-einrepói, með möppu fyrir höfuðlausa safn, hjálparpakka og dæmaforrit hvers ramma. Fljótlegasta leiðin til að prófa er að klóna einrepóið og opna höfuðlausa safnið fyrir þinn ramma: 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-react-headless
pnpm install

Sama mynstur gildir fyrir hina rammana:

  • @lilydesignsystem/html-headless — engin uppsetning nauðsynleg; afritaðu .html skrárnar
  • @lilydesignsystem/svelte-headless — pnpm install
  • @lilydesignsystem/react-headless — pnpm install
  • @lilydesignsystem/vue-headless — pnpm install
  • @lilydesignsystem/angular-headless — pnpm install
  • @lilydesignsystem/nunjucks-headless — pnpm install
  • lily-design-system-blazor-headless — dotnet build

Höfuðlausu söfnin eru hönnuð til að vera klónuð eða tekin inn — líttu á upprunann sem sannleiksgjafa og afritaðu það sem þú þarft. stillingahjálpartækin koma auk þess sem uppsetjanlegir pakkar með byggingar- og útgáfuferli (npm fyrir JS-ramma, NuGet fyrir Blazor).

Notaðu höfuðlausan íhlut

Höfuðlausir íhlutir koma með merkingarfræðilegu HTML, ARIA og eiginleikum — en ekkert CSS. Hér er Button í hverjum ramma:

HTML

<button class="button" type="button" aria-label="Save">
  Save
</button>

Svelte

<script>
  import Button from "lily-design-system-svelte-headless/components/Button/Button.svelte";
</script>

<Button onclick={save}>Save</Button>

React

import Button from "lily-design-system-react-headless/components/Button";

<Button onClick={save}>Save</Button>

Vue

<script setup>
  import Button from "lily-design-system-vue-headless/components/Button.vue";
</script>

<Button @click="save">Save</Button>

Angular

import { Button } from "@lilydesignsystem/angular-headless";

@Component({
  imports: [Button],
  template: `<lily-button (click)="save()">Save</lily-button>`,
})

Blazor

<Button OnClick="Save">Save</Button>

Nunjucks

{% from "components/button/macro.njk" import button %}

{{ button({ text: "Save", type: "button" }) }}

Notaðu stílað dæmi

Dæmaforritin innihalda CSS, leiðir og fullar sýnisíður. Fljótlegasta leiðin til að gera tilraunir er að ræsa SvelteKit-, Next-, Nuxt-, Analog- eða Eleventy-dæmaforritið og skoða sýnið á /components. 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-sveltekit-examples
pnpm install
pnpm run dev

Opnaðu svo http://localhost:5173 og skoðaðu /components.

Stílun og hönnunargildi

Hver íhlutur birtist með einum kebab-case klasa á rótarþættinum. Til dæmis <Button> birtir <button class="button">. Stílaðu hann eins og þú vilt: 

.button {
  background: var(--my-primary);
  color: #fff;
  padding: 0.75rem 1.5rem;
  border-radius: 0.5rem;
}
.button:hover { background: var(--my-primary-hover); }

Sjálfgefið Lily-litaspjald (notað í dæmaforritunum) er:

  • Aðallitur: #2563eb
  • Hætta: #dc2626
  • Viðvörun: #f59e0b
  • Árangur: #16a34a
  • Bakgrunnur síðu: #f9fafb
  • Bakgrunnur korts: #ffffff

Þetta eru tillögur, ekki kröfur. Skiptu þeim út fyrir þitt eigið vörumerkjalitaspjald og Lily fylgir með glöð.

Tilbúin þemu

Viltu ekki skrifa CSS frá grunni? Lily inniheldur 57 sjálfstæð viðmiðunarþemu í möppunni themes/ . Hvert er eitt stílblað sem miðar á Lily-klasakrókana — tengdu það og þú ert stíluð(ur): 

<link rel="stylesheet" href="/assets/themes/united-kingdom-government-digital-service.css" />

Settið nær yfir:

  • Opinber geiri — NHS England, NHS Scotland og NHS Wales (útgáfur fyrir sjúklinga og fagfólk hvert), GOV.UK GDS og U.S. Web Design System.
  • Innblásið af söluaðilum — Adobe Spectrum, Mozilla Protocol.
  • Almenn notkun — light, dark, nord, dracula, wireframe og þrjátíu til viðbótar.

Þemaveljarar nota :where(...), svo þitt eigið CSS vinnur alltaf á sértækni. Paraðu þau við hjálpartækið theme-picker hér að neðan fyrir skipti á keyrslutíma, eða fylgdu þemakennsluefni.

Stillingahjálpartæki

Hver rammi er með átta litla veljara, hver sinn eigin lily-design-system-{framework}-{package} pakka (og picker-bar sem setur þá saman). Hver er höfuðlaus táknhnappur sem opnar sprettglugga — valmöguleikalista, tengla, leitarform eða (fyrir date-time-picker) dagsetningarvalsglugga — ekki innbyggt <select>; er SSR-öruggur; og kemur án CSS:

  • theme-picker — hleður þemastílblöðum á keyrslutíma með því að skipta um stýrt <link>, setur data-theme á skjalið og vistar valfrjálst í localStorage.
  • locale-picker — setur lang og dir (með sjálfvirkri RTL-greiningu) svo i18n-safnið þitt geti fylgt; framkvæmir enga þýðingu sjálft.
  • text-size-picker — setur data-text-size á skjalinu; CSS-ið þitt varpar hverju gildi á leturstærð.
  • motion-picker — setur data-motion á skjalinu, með upphafsgildi úr stillingu gesta um minni hreyfingu; CSS og skriftur þínar ákveða hvað er bælt.
  • search-picker — táknhnappur sem opnar leitarreit; innsending leiðir á leitarsíðu. Á aðgerð, ekki stillingu.
  • link-picker — heimatákn sem opnar valmynd með síðutenglum sem forritið þitt skilgreinir (Heim, Um okkur, Hafðu samband, Persónuverndarstefna, …). Á aðgerð, ekki stillingu.
  • share-picker — opnar innbyggðan deilingarglugga eða lista yfir áfangastaði frá notanda, auk þess að afrita vefslóð. Á aðgerð, ekki stillingu: beitir engu, vistar ekkert.
  • date-time-picker — textareitur auk APG-dagsetningarvalsglugga fyrir dagsetningu, tíma eða hvort tveggja. Á formgildi, ekki stillingu: ISO-strengurinn fer fram og til baka til <input type="date">. 
git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-theme-picker

Svelte-safnið er kjarnaviðmiðið; React-, Vue-, Angular-, HTML-, Nunjucks-, Web Components- og Blazor-færslur samsvara því samningur fyrir samning. Sjá hjálpartækjakennsluefni.

Aðgengi

Íhlutir miða við WCAG 2.2 AAA. Þeir fylgja þessum mynstrum:

  • Merkingarfræðilega HTML-þætti frekar en almenna <div>s.
  • <label for="id"> sem tengja merkimiða við innslætti.
  • aria-labelledby / aria-describedby fyrir víxlvísanir.
  • aria-invalid + aria-errormessage fyrir villustöður.
  • role="alert" og aria-live fyrir kvikt efni.
  • aria-pressed, aria-expanded, aria-current fyrir stöðu.
  • Roving tabindex fyrir ristir.

Fókusvísar eru viljandi í höndum notandans — Lily málar aldrei sjálfgefinn fókushring sem rekst á hönnun þína. Dæmaforritin halda hreinni axe-core grunnlínu á öllum leiðum sínum.

Alþjóðavæðing

Hver merkimiði, staðgengiltexti, villuskilaboð og hnappatexti er eiginleiki. Enginn textastrengur er harðkóðaður. Notaðu þýðingarrammann að eigin vali — Paraglide, i18next, vue-i18n, react-intl, .resx-skrár, hvað sem er.

Fyrir dagsetningar, tölur og gjaldmiðla taka íhlutirnir við forsniðnum strengjum: þú sniðgerir með Intl.DateTimeFormat / Intl.NumberFormat / safninu sem þú kýst og sendir niðurstöðuna.

Hjálpartækið locale-picker gefur i18n-safninu þínu til kynna valda staðfærslu með því að stilla lang og dir á rót skjalsins.

Prófanir

Hvert rammaundirverkefni sendir sín eigin próf með eigin hefðbundnu tækjum:

  • HTML: WebDriverIO sem keyrir raunverulega vafra.
  • Svelte: Vitest + @testing-library/svelte.
  • React: Vitest + @testing-library/react.
  • Vue: Vitest + @testing-library/vue.
  • Angular: Vitest + TestBed (í gegnum Analog Vite-viðbótina).
  • Nunjucks: Vitest með birtingarhjálp.
  • Blazor: bUnit.

Próf nota aðeins innbyggða samsvörun Vitest — aldrei jest-dom samsvörun. Þetta heldur prófasöfnunum færanlegum. Dæmaforritin bæta við Playwright-prófum frá enda til enda, axe-core aðgengisgrunnlínum og sjónarhornakönnun.

Bilanaleit

Íhlutur birtist en lítur óstílaður út

Það er höfuðleysið að virka eins og til er ætlast — ekkert CSS fylgir íhlutnum. Skrifaðu annaðhvort CSS gegn kebab-case klasa íhlutarins (sýndur á hverri safnsíðu) eða tengdu eitt af 57 tilbúnu þemunum.

CSS-ið mitt virðist ekki gilda yfir þema

Það ætti að gera það — þemaveljarar eru vafðir í :where(...), sem hefur núll sértækni. Ef regla tapar enn, athugaðu að stílblaðið þitt hlaðist á eftir stílblaði þemans <link> og að veljarinn passi í raun við klasakrók íhlutarins.

pnpm install mistekst með jafningja- eða útgáfuvillu

Notaðu núverandi pnpm (v10+) og Node 22+. Hvert undirverkefni festir rammaútgáfur sínar í eigin package.json; ef alþjóðlegt verkfærasett þitt er eldra, pnpm env use --global lts er fljótlegasta lausnin.

Skjálesari tilkynnir rangt heiti fyrir stýringu

Athugaðu nauðsynlegan label eiginleika íhlutarins — íhlutir sem hafa engan sýnilegan texta krefjast eins, og aria-label / aria-labelledby frá notanda sem sent er í gegnum rest-props gildir viljandi umfram innbyggðu tengingarnar. Hver safnsíða skjalfestir ARIA-samning íhlutarins.

Theme-picker hjálpartækið skiptir ekki um stílblöð

Staðfestu að themesUrl bendi á möppu sem vafrinn getur sótt (þjónaðu themes/ skránum sem kyrrstæðum eignum) og að þemaheitin í themes eiginleikanum passi við skráarheitin. Hjálpartækið skiptir um href á einu stýrðu <link data-lily-theme-picker> — skoðaðu það í devtools til að sjá vefslóðina sem beðið er um.

Algengar spurningar

Af hverju höfuðlaust frekar en stílað?

Forstíluð íhlutasöfn eru þægileg — þar til þau passa ekki við vörumerkið þitt. Höfuðlausir íhlutir kosta örlítið meiri vinnu í upphafi en veita þér fulla stjórn á sjónrænni hönnun. Dæmaforritin og 57 þemun sýna leiðir til að stíla þá; þú getur tekið þær eða skipt þeim alveg út. Lengri rökin eru á Af hverju Lily.

Af hverju svona margir íhlutir?

Lily stefnir að því að ná yfir mynstrin sem flest forrit þurfa án þess að þú þurfir að byggja þau frá grunni — þar á meðal sérhæfða hluti eins og innslátt landsauðkenna og ritstjórnarskrunsögur. Safnið sækir í tugi rótgróinna hönnunarkerfa auk frumlegrar vinnu — sjá Um.

Get ég notað Lily með Tailwind?

Já. Hver íhlutur birtir einn kebab-case rótarklasa auk className / classfrá notanda. Leggðu Tailwind-tól ofan á eins og þú vilt.

Get ég notað Lily með merkingarfræðilegum CSS-römmum eins og DaisyUI?

Já. Kebab-case klasaheitin á rótarþættinum virka sem merkingarfræðilegir CSS-krókar. Paraðu Lily við merkingarfræðilegan ramma og þú færð forstílaða íhluti sem virða samt ARIA og i18n.

Er til npm-pakki?

Hjálpartækið stillingahjálpartækin koma sem pakkar með npm/NuGet útgáfuferli. Höfuðlausu íhlutasöfnin eru hönnuð til að vera klónuð eða tekin inn — upprunakóðinn er afurðin, svo þú getir lesið, snyrt og átt nákvæmlega það sem þú gefur út. Útgáfa höfuðlausu safnanna í skrám er enn á vegvísinum.
