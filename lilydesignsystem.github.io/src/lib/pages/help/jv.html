Instalasi

Lily manggon ing siji monorepo Git, kanthi direktori kanggo pustaka tanpa sirah, paket pembantu, lan aplikasi conto saben framework. Cara paling cepet kanggo nyoba yaiku kloning monorepo lan mbukak pustaka tanpa sirah kanggo tumpukan sampéyan: 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-react-headless
pnpm install

Pola sing padha makarya kanggo framework liyané:

  • @lilydesignsystem/html-headless — ora perlu instalasi; salinen berkas .html
  • @lilydesignsystem/svelte-headless — pnpm install
  • @lilydesignsystem/react-headless — pnpm install
  • @lilydesignsystem/vue-headless — pnpm install
  • @lilydesignsystem/angular-headless — pnpm install
  • @lilydesignsystem/nunjucks-headless — pnpm install
  • lily-design-system-blazor-headless — dotnet build

Pustaka tanpa sirah dirancang kanggo dikloning utawa dilebokaké — anggep kode sumber minangka sumber kebeneran lan salinen apa sing sampéyan butuhaké. pembantu preferensi uga dikirim minangka paket sing bisa diinstal kanthi pipeline build lan publikasi (npm kanggo framework JS, NuGet kanggo Blazor).

Nganggo komponèn tanpa sirah

Komponèn tanpa sirah nyedhiyakaké HTML semantik, ARIA, lan properti — nanging ora ana CSS. Iki Button ing saben framework:

HTML

<button class="button" type="button" aria-label="Save">
  Save
</button>

Svelte

<script>
  import Button from "lily-design-system-svelte-headless/components/Button/Button.svelte";
</script>

<Button onclick={save}>Save</Button>

React

import Button from "lily-design-system-react-headless/components/Button";

<Button onClick={save}>Save</Button>

Vue

<script setup>
  import Button from "lily-design-system-vue-headless/components/Button.vue";
</script>

<Button @click="save">Save</Button>

Angular

import { Button } from "@lilydesignsystem/angular-headless";

@Component({
  imports: [Button],
  template: `<lily-button (click)="save()">Save</lily-button>`,
})

Blazor

<Button OnClick="Save">Save</Button>

Nunjucks

{% from "components/button/macro.njk" import button %}

{{ button({ text: "Save", type: "button" }) }}

Nganggo conto sing digayani

Aplikasi conto kalebu CSS, rute, lan kaca demo lengkap. Cara paling cepet kanggo ékspérimèn yaiku miwiti aplikasi conto SvelteKit, Next, Nuxt, Analog, utawa Eleventy lan ndeleng demoné ing /components. 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-sveltekit-examples
pnpm install
pnpm run dev

Banjur bukak http://localhost:5173 lan jelajahi /components.

Gaya lan token desain

Saben komponèn dirender kanthi siji kelas kebab-case ing elemèn oyodé. Contoné, <Button> dirender minangka <button class="button">. Gayani kaya sing sampéyan karepake: 

.button {
  background: var(--my-primary);
  color: #fff;
  padding: 0.75rem 1.5rem;
  border-radius: 0.5rem;
}
.button:hover { background: var(--my-primary-hover); }

Tema siap

Ora péngin nulis CSS saka nol? Lily nyedhiyakaké 57 tema rujukan mandiri ing direktori themes/ . Saben siji iku siji stylesheet sing nargetaké pancingan kelas Lily — sambungna lan sampéyan wis digayani: 

<link rel="stylesheet" href="/assets/themes/united-kingdom-government-digital-service.css" />

Setèl iki nyakup:

  • Sektor umum — NHS England, NHS Scotland, lan NHS Wales (saben siji ing varian kanggo pasien lan praktisi), GOV.UK GDS, lan U.S. Web Design System.
  • Kainspirasi vendor — Adobe Spectrum, Mozilla Protocol.
  • Tujuan umum — light, dark, nord, dracula, wireframe, lan telung puluhan liyané.

Selektor tema nganggo :where(...), dadi CSS sampéyan dhéwé tansah menang ing spesifisitas. Pasangna karo pembantu theme-picker ing ngisor kanggo ganti nalika mlaku, utawa tututi tutorial tema.

Pembantu preferensi

Saben framework duwé wolung pamilih cilik, saben siji paket lily-design-system-{framework}-{package} dhéwé (lan picker-bar sing nyusun kuwi). Saben siji iku tombol ikon tanpa sirah sing mbukak popup — kothak dhaptar, dhaptar tautan, formulir panelusuran, utawa (kanggo date-time-picker) dialog pamilih tanggal — dudu <select>asli; aman kanggo SSR; lan ora ngirim CSS:

  • theme-picker — muat stylesheet tema nalika mlaku kanthi ngganti <link>sing dikelola, nyetèl data-theme ing dokumèn, lan opsional nyimpen kanthi permanèn ing localStorage.
  • locale-picker — nyetèl lang lan dir (kanthi deteksi RTL otomatis) supaya pustaka i18n sampéyan bisa nututi; ora nerjemahaké apa waé dhéwé.
  • text-size-picker — nyetèl data-text-size ing dokumèn; CSS sampéyan mapakaké saben nilai menyang ukuran font.
  • motion-picker — nyetèl data-motion ing dokumèn, diwiwiti saka setelan gerakan dikurangi pengunjung; CSS lan skrip sampéyan sing mutusaké apa sing ditahan.
  • search-picker — tombol ikon sing mbukak kolom panelusuran; ngirim bakal menyang kaca panelusuran. Nduwèni aksi, dudu preferensi.
  • link-picker — ikon omah sing mbukak menu tautan kaca sing ditetepaké aplikasi sampéyan (Beranda, Babagan Kita, Hubungi Kita, Kabijakan Privasi, …). Nduwèni aksi, dudu preferensi.
  • share-picker — mbukak lembar nuduhaké asli utawa dhaptar tujuan sing diwènèhaké konsumen, ditambah nyalin URL. Nduwèni aksi, dudu preferensi: ora nrapaké apa waé, ora nyimpen apa waé.
  • date-time-picker — kolom tèks plus dialog pamilih tanggal APG kanggo tanggal, wektu, utawa loro-loroné. Nduwèni nilai formulir, dudu preferensi: string ISO diowahi bolak-balik menyang <input type="date">.

Aksesibilitas

Komponèn ngarah menyang WCAG 2.2 AAA. Kuwi nututi pola-pola iki:

  • Elemèn HTML semantik tinimbang <div>s.
  • <label for="id"> umum sing nyambungaké labèl karo input.
  • aria-labelledby / aria-describedby kanggo rujukan silang.
  • aria-invalid + aria-errormessage kanggo kahanan kesalahan.
  • role="alert" lan aria-live kanggo isi dinamis.
  • aria-pressed, aria-expanded, aria-current kanggo kahanan.
  • Roving tabindex kanggo kisi.

Indikator fokus sengaja diwènèhaké konsumen — Lily ora tau nggambar cincin fokus baku sing bentrok karo desain sampéyan. Aplikasi conto njaga dasar axe-core sing resik ing kabèh rutené.

Internasionalisasi

Saben labèl, placeholder, pesen kesalahan, lan tèks tombol iku properti. Ora ana string permanèn. Sambungna framework terjemahan pilihan sampéyan — Paraglide, i18next, vue-i18n, react-intl, berkas .resx, apa waé.

Kanggo tanggal, angka, lan mata uang, komponèn nampa string sing wis diformat: sampéyan ngformat nganggo Intl.DateTimeFormat / Intl.NumberFormat / pustaka kesenengan sampéyan lan ngirim asilé.

Pembantu locale-picker menehi sinyal lokal sing dipilih marang pustaka i18n sampéyan kanthi nyetèl lang lan dir ing oyod dokumèn.

Tés

Saben subproyèk framework ngirim tés dhéwé nganggo tumpukan idiomatiké:

  • HTML: WebDriverIO sing njalanaké browser nyata.
  • Svelte: Vitest + @testing-library/svelte.
  • React: Vitest + @testing-library/react.
  • Vue: Vitest + @testing-library/vue.
  • Angular: Vitest + TestBed (liwat plugin Vite Analog).
  • Nunjucks: Vitest nganggo pembantu render.
  • Blazor: bUnit.

Tés nganggo mung matcher bawaan Vitest — ora tau matcher jest-dom . Iki njaga suite tés bisa dipindhah. Aplikasi conto nambahaké suite end-to-end Playwright, dasar aksesibilitas axe-core, lan sapuan viewport responsif.

Pemecahan masalah

Komponèn dirender nanging katon ora digayani

Kuwi tanpa sirah sing makarya kaya sing dikarepaké — ora ana CSS sing teka karo komponèn. Tulisen CSS kanggo kelas kebab-case komponèn (dituduhaké ing saben kaca katalog) utawa sambungna salah siji saka 57 tema siap.

CSS-ku ora katon ditrapaké ing ndhuwur tema

Mestiné ditrapaké — selektor tema dibungkus ing :where(...), sing duwé spesifisitas nol. Yèn aturan tetep kalah, priksa yèn stylesheet sampéyan dimuat sawisé <link> saka tema lan selektoré pancèn cocog karo pancingan kelas komponèn.

pnpm install gagal kanthi kesalahan peer utawa versi

Gunakna pnpm saiki (v10+) lan Node 22+. Saben subproyèk nancepaké versi frameworké ing package.jsondhéwé; yèn rantai piranti global sampéyan luwih lawas, pnpm env use --global lts iku pangapura paling cepet.

Pembaca layar ngumumaké jeneng sing salah kanggo kontrol

Priksa properti wajib label komponèn — komponèn tanpa tèks katon mbutuhaké siji, lan aria-label / aria-labelledby sing diwènèhaké konsumen lan dilewatké liwat rest-props sengaja ngalahaké kabel bawaan. Saben kaca katalog ndokumentasiaké kontrak ARIA komponèn.

Pembantu theme-picker ora ngganti stylesheet

Pastikna yèn themesUrl nuding menyang direktori sing bisa dijupuk browser (sajèkna berkas themes/ minangka aset statis) lan yèn slug tema ing properti themes sampéyan cocog karo jeneng berkas. Pembantu ngganti href saka siji <link data-lily-theme-picker> sing dikelola — priksanen ing devtools kanggo ndeleng URL sing dijaluk.

FAQ

Kenging punapa tanpa sirah tinimbang digayani?

Komponèn sing wis digayani iku kepénak — nganti ora cocog karo mérek sampéyan. Komponèn tanpa sirah mbutuhaké tenaga rada luwih ing wiwitan nanging menehi kontrol kabèh ing desain visual. Aplikasi conto lan 57 tema nuduhaké cara menehi gaya; sampéyan bisa njupuk kuwi utawa ngganti kabèh. Argumen sing luwih dawa ana ing Kenging punapa Lily.

Kenging punapa komponèné akèh banget?

Lily ngarahaké nyakup pola sing dibutuhaké akèh aplikasi tanpa meksa sampéyan mbangun saka nol — kalebu bab-bab jero kaya input pangenal nasional lan scrollytelling editorial. Katalog njupuk saka selusin sistem desain sing wis mapan ditambah karya asli — delengen Babagan.

Apa aku bisa nganggo Lily karo Tailwind?

Bisa. Saben komponèn mbukak siji kelas oyod kebab-case ditambah className / classsing diwènèhaké konsumen. Tumpukna utilitas Tailwind ing ndhuwur kaya sing sampéyan karepake.

Apa aku bisa nganggo Lily karo framework CSS semantik kaya DaisyUI?

Bisa. Jeneng kelas kebab-case ing elemèn oyod makarya minangka pancingan CSS semantik. Pasangna Lily karo framework semantik lan sampéyan entuk komponèn sing wis digayani sing tetep ngajèni ARIA lan i18n.

Apa ana paket npm?

Pembantu preferensi dikirim minangka paket kanthi pipeline publikasi npm/NuGet. Pustaka komponèn tanpa sirah dirancang kanggo dikloning utawa dilebokaké — kode sumber iku sing dikirim, supaya sampéyan bisa maca, nyuda, lan nduwèni persis apa sing sampéyan rilis. Publikasi pustaka tanpa sirah menyang registri tetep ana ing peta dalan.

Kenging punapa pirang-pirang lisènsi?

Proyèk sing béda duwé kabutuhan lisènsi sing béda. BSD lan MIT iku permisif, Apache-2.0 duwé pemberian paten, lan opsi GPL ndhukung copyleft. Pilih apa sing cocog karo kahanan sampéyan.
