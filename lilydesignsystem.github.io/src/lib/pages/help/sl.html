Namestitev

Lily živi v enem monorepozitoriju Git, z mapo za brezglavo knjižnico, pomožne pakete in vzorčno aplikacijo vsakega ogrodja. Najhitrejši način za preizkus je klonirati monorepozitorij in odpreti brezglavo knjižnico za svoj sklad: 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-react-headless
pnpm install

Enak vzorec deluje za druga ogrodja:

  • @lilydesignsystem/html-headless — namestitev ni potrebna; kopirajte datoteke .html
  • @lilydesignsystem/svelte-headless — pnpm install
  • @lilydesignsystem/react-headless — pnpm install
  • @lilydesignsystem/vue-headless — pnpm install
  • @lilydesignsystem/angular-headless — pnpm install
  • @lilydesignsystem/nunjucks-headless — pnpm install
  • lily-design-system-blazor-headless — dotnet build

Brezglave knjižnice so zasnovane za kloniranje ali vključitev v projekt — vzemite izvorno kodo kot vir resnice in kopirajte, kar potrebujete. pomočniki za nastavitve se dodatno dobavljajo kot namestljivi paketi s cevovodom za gradnjo in objavo (npm za ogrodja JS, NuGet za Blazor).

Uporaba brezglave komponente

Brezglave komponente dobavljajo semantični HTML, ARIA in lastnosti — a ne CSS. Tu je Button v vsakem ogrodju:

HTML

<button class="button" type="button" aria-label="Save">
  Save
</button>

Svelte

<script>
  import Button from "lily-design-system-svelte-headless/components/Button/Button.svelte";
</script>

<Button onclick={save}>Save</Button>

React

import Button from "lily-design-system-react-headless/components/Button";

<Button onClick={save}>Save</Button>

Vue

<script setup>
  import Button from "lily-design-system-vue-headless/components/Button.vue";
</script>

<Button @click="save">Save</Button>

Angular

import { Button } from "@lilydesignsystem/angular-headless";

@Component({
  imports: [Button],
  template: `<lily-button (click)="save()">Save</lily-button>`,
})

Blazor

<Button OnClick="Save">Save</Button>

Nunjucks

{% from "components/button/macro.njk" import button %}

{{ button({ text: "Save", type: "button" }) }}

Uporaba stiliziranega primera

Vzorčne aplikacije vključujejo CSS, poti in popolne predstavitvene strani. Najhitrejši način za eksperimentiranje je zagnati vzorčno aplikacijo SvelteKit, Next, Nuxt, Analog ali Eleventy in si ogledati predstavitev na /components. 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-sveltekit-examples
pnpm install
pnpm run dev

Nato odprite http://localhost:5173 in brskajte po /components.

Stiliziranje in oblikovalski žetoni

Vsaka komponenta se upodobi z enim razredom v kebab-case na svojem korenskem elementu. Na primer, <Button> se upodobi kot <button class="button">. Stilizirajte ga, kakor želite: 

.button {
  background: var(--my-primary);
  color: #fff;
  padding: 0.75rem 1.5rem;
  border-radius: 0.5rem;
}
.button:hover { background: var(--my-primary-hover); }

Privzeta barvna paleta Lily (uporabljena v vzorčnih aplikacijah) je:

  • Primarna: #2563eb
  • Nevarnost: #dc2626
  • Opozorilo: #f59e0b
  • Uspeh: #16a34a
  • Ozadje strani: #f9fafb
  • Ozadje kartice: #ffffff

To so predlogi, ne zahteve. Zamenjajte jih s paleto lastne blagovne znamke in Lily vas z veseljem spremlja.

Pripravljene teme

Ne želite pisati CSS od začetka? Lily dobavlja 57 samostojnih referenčnih tem v mapi themes/ . Vsaka je ena slogovna datoteka, ki cilja na kavlje razredov Lily — povežite jo in ste stilizirani: 

<link rel="stylesheet" href="/assets/themes/united-kingdom-government-digital-service.css" />

Nabor zajema:

  • Javni sektor — NHS England, NHS Scotland in NHS Wales (vsaka v različicah za bolnike in za strokovnjake), GOV.UK GDS in U.S. Web Design System.
  • Navdahnjeno z dobavitelji — Adobe Spectrum, Mozilla Protocol.
  • Splošna uporaba — light, dark, nord, dracula, wireframe in še trideset drugih.

Izbirniki tem uporabljajo :where(...), zato vaš lasten CSS vedno zmaga po specifičnosti. Povežite jih s pomočnikom theme-picker spodaj za preklapljanje med izvajanjem ali sledite vodiču o temah.

Pomočniki za nastavitve

Vsako ogrodje ima osem majhnih izbirnikov, vsak je ločen paket lily-design-system-{framework}-{package} (in en picker-bar , ki jih sestavi). Vsak je brezglav gumb z ikono, ki odpre pojavno okno — seznamsko polje, seznam povezav, iskalni obrazec ali (za date-time-picker) pogovorno okno za izbiro datuma — ne izvorni <select>; je varen za SSR; in ne dobavlja CSS:

  • theme-picker — med izvajanjem naloži slogovne datoteke tem z zamenjavo upravljanega <link>, nastavi data-theme na dokumentu in po želji trajno shrani v localStorage.
  • locale-picker — nastavi lang in dir (s samodejnim zaznavanjem RTL), da lahko vaša knjižnica i18n sledi; sam ničesar ne prevaja.
  • text-size-picker — nastavi data-text-size na dokumentu; vaš CSS preslika vsako vrednost v velikost pisave.
  • motion-picker — nastavi data-motion na dokumentu, izhajajoč iz obiskovalčeve nastavitve zmanjšanega gibanja; vaš CSS in skripti odločajo, kaj zatreti.
  • search-picker — gumb z ikono, ki odpre iskalno polje; oddaja vodi na iskalno stran. Lasti dejanje, ne nastavitve.
  • link-picker — ikona hiše, ki odpre meni povezav strani, ki jih določa vaša aplikacija (Domov, O nas, Stik, Politika zasebnosti, …). Lasti dejanje, ne nastavitve.
  • share-picker — odpre izvorni list za deljenje ali seznam ciljev, ki ga priskrbi uporabnik, poleg kopiranja URL. Lasti dejanje, ne nastavitve: ničesar ne uveljavi, ničesar ne shrani.
  • date-time-picker — besedilno polje poleg pogovornega okna za izbiro datuma po APG za datum, čas ali oboje. Lasti vrednost obrazca, ne nastavitve: niz ISO se pretvarja tja in nazaj v <input type="date">.

cd lily-design-system/lily-design-system-svelte-theme-picker

Dostopnost

Komponente ciljajo na WCAG 2.2 AAA. Sledijo tem vzorcem:

  • Semantični elementi HTML namesto splošnih <div>s.
  • <label for="id"> ki povezujejo oznake z vnosi.
  • aria-labelledby / aria-describedby za navzkrižna sklicevanja.
  • aria-invalid + aria-errormessage za stanja napak.
  • role="alert" in aria-live za dinamično vsebino.
  • aria-pressed, aria-expanded, aria-current za stanje.
  • Roving tabindex za mreže.

Kazalnike fokusa namerno priskrbi uporabnik — Lily nikoli ne nariše privzetega obroča fokusa, ki bi bil v nasprotju z vašim oblikovanjem. Vzorčne aplikacije ohranjajo čisto izhodišče axe-core na vseh svojih poteh.

Internacionalizacija

Vsaka oznaka, nadomestno besedilo, sporočilo o napaki in besedilo gumba je lastnost. Trdo zapisanih nizov ni. Vključite ogrodje za prevajanje po svoji izbiri — Paraglide, i18next, vue-i18n, react-intl, datoteke .resx, karkoli.

Za datume, števila in valute komponente sprejemajo vnaprej oblikovane nize: oblikujete z Intl.DateTimeFormat / Intl.NumberFormat / svojo najljubšo knjižnico in rezultat podate naprej.

Pomočnik locale-picker sporoči izbrani jezik vaši knjižnici i18n z nastavitvijo lang in dir na korenu dokumenta.

Testiranje

Vsak podprojekt ogrodja dobavlja lastne teste z njegovim idiomatskim skladom:

  • HTML: WebDriverIO, ki poganja prave brskalnike.
  • Svelte: Vitest + @testing-library/svelte.
  • React: Vitest + @testing-library/react.
  • Vue: Vitest + @testing-library/vue.
  • Angular: Vitest + TestBed (prek vtičnika Vite od Analog).
  • Nunjucks: Vitest s pomočnikom za upodabljanje.
  • Blazor: bUnit.

Testi uporabljajo samo vgrajene primerjalnike Vitest — nikoli primerjalnikov jest-dom . To ohranja skupke testov prenosljive. Vzorčne aplikacije dodajo skupke Playwright od konca do konca, izhodišča dostopnosti axe-core in pregled odzivnih okenskih pogledov.

Odpravljanje težav

Komponenta se upodobi, a izgleda nestilizirano

To je brezglavost, ki deluje, kot je predvideno — s komponento ne pride noben CSS. Ali napišite CSS za razred komponente v kebab-case (prikazan na vsaki strani kataloga) ali povežite eno od 57 pripravljenih tem.

Moj CSS se zdi, da se ne uveljavi nad temo

Moral bi — izbirniki tem so oviti v :where(...), ki ima ničelno specifičnost. Če pravilo vseeno izgubi, preverite, ali se vaša slogovna datoteka naloži po <link> teme in ali se izbirnik res ujema s kavljem razreda komponente.

pnpm install ne uspe z napako peer ali različice

Uporabite aktualen pnpm (v10+) in Node 22+. Vsak podprojekt pripne različice svojega ogrodja v svoji package.json; če je vaša globalna veriga orodij starejša, pnpm env use --global lts je najhitrejši popravek.

Bralnik zaslona napove napačno ime kontrolnika

Preverite obvezno lastnost label komponente — komponente brez vidnega besedila jo zahtevajo, uporabnikov aria-label / aria-labelledby podan prek rest-props pa namerno zmaga nad vgrajeno povezavo. Vsaka stran kataloga dokumentira pogodbo ARIA komponente.

Pomočnik theme-picker ne preklaplja slogovnih datotek

Potrdite, da themesUrl kaže na mapo, ki jo brskalnik lahko pridobi (postrezite datoteke themes/ kot statične vire) in da se kratka imena tem v vaši lastnosti themes ujemajo z imeni datotek. Pomočnik zamenja href enega upravljanega <link data-lily-theme-picker> — preglejte ga v razvijalskih orodjih, da vidite zahtevani URL.

Pogosta vprašanja

Zakaj brezglavo namesto stilizirano?

Vnaprej stilizirane komponente so priročne — dokler ne ustrezajo vaši znamki. Brezglave komponente zahtevajo na začetku nekoliko več dela, a vam dajo popoln nadzor nad vizualnim oblikovanjem. Vzorčne aplikacije in 57 tem kažejo načine za stiliziranje; lahko jih prevzamete ali v celoti zamenjate. Daljši argument je na Zakaj Lily.

Zakaj toliko komponent?

Lily želi pokriti vzorce, ki jih potrebuje večina aplikacij, ne da bi vas silil, da jih gradite od začetka — vključno z globokimi stvarmi, kot so vnosi nacionalnih identifikatorjev in uredniški scrollytelling. Katalog črpa iz ducata uveljavljenih oblikovalskih sistemov in izvirnega dela — glejte O projektu.

Ali lahko uporabljam Lily s Tailwindom?

Da. Vsaka komponenta izpostavi en koreni razred v kebab-case in uporabnikov className / class. Naložite pripomočke Tailwind čez, kakor želite.

Ali lahko uporabljam Lily s semantičnimi ogrodji CSS, kot je DaisyUI?

Da. Imena razredov v kebab-case na korenskem elementu delujejo kot semantični kavlji CSS. Združite Lily s semantičnim ogrodjem in dobite vnaprej stilizirane komponente, ki vseeno spoštujejo ARIA in i18n.

Ali obstaja paket npm?

Pomočniki za nastavitve se dobavljajo kot paketi s cevovodom za objavo npm/NuGet. Brezglave knjižnice komponent so zasnovane za kloniranje ali vključitev v projekt — izvorna koda je izdelek, zato lahko berete, krajšate in lastite natanko to, kar objavite. Objava brezglavih knjižnic v registre ostaja na načrtu razvoja.

Zakaj več licenc?

Različni projekti imajo različne licenčne potrebe. BSD in MIT sta dovoljujoči, Apache-2.0 ima patentno podelitev, možnosti GPL pa podpirajo copyleft. Izberite, kar ustreza vašemu primeru.
