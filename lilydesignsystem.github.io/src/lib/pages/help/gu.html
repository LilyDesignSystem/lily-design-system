ઇન્સ્ટોલ

Lily એક Git મોનોરેપોમાં રહે છે, જેમાં દરેક ફ્રેમવર્કની હેડલેસ લાઇબ્રેરી, સહાયક પેકેજ અને ઉદાહરણ એપ માટે ડિરેક્ટરી છે. તેને અજમાવવાનો સૌથી ઝડપી રસ્તો મોનોરેપો ક્લોન કરવો અને તમારા સ્ટેક માટે હેડલેસ લાઇબ્રેરી ખોલવી છે: 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-react-headless
pnpm install

એ જ પેટર્ન અન્ય ફ્રેમવર્ક માટે કામ કરે છે:

  • @lilydesignsystem/html-headless — ઇન્સ્ટોલની જરૂર નથી; કૉપિ કરો .html ફાઇલો
  • @lilydesignsystem/svelte-headless — pnpm install
  • @lilydesignsystem/react-headless — pnpm install
  • @lilydesignsystem/vue-headless — pnpm install
  • @lilydesignsystem/angular-headless — pnpm install
  • @lilydesignsystem/nunjucks-headless — pnpm install
  • lily-design-system-blazor-headless — dotnet build

હેડલેસ લાઇબ્રેરીઓ ક્લોન કરવા અથવા વેન્ડર કરવા માટે રચાયેલી છે — સ્રોતને સત્યનો સ્રોત ગણો અને તમને જોઈતું કૉપિ કરો. પસંદગી સહાયકો વધુમાં બિલ્ડ અને પ્રકાશન પાઇપલાઇન (JS ફ્રેમવર્ક માટે npm, Blazor માટે NuGet) સાથે ઇન્સ્ટોલ કરી શકાય તેવા પેકેજ તરીકે આવે છે.

હેડલેસ ઘટકનો ઉપયોગ કરો

હેડલેસ ઘટકો સેમેન્ટિક HTML, ARIA અને પ્રોપ્સ મોકલે છે — પણ CSS નહીં. દરેક ફ્રેમવર્કમાં Button આ રહ્યું:

HTML

<button class="button" type="button" aria-label="Save">
  Save
</button>

Svelte

<script>
  import Button from "lily-design-system-svelte-headless/components/Button/Button.svelte";
</script>

<Button onclick={save}>Save</Button>

React

import Button from "lily-design-system-react-headless/components/Button";

<Button onClick={save}>Save</Button>

Vue

<script setup>
  import Button from "lily-design-system-vue-headless/components/Button.vue";
</script>

<Button @click="save">Save</Button>

Angular

import { Button } from "@lilydesignsystem/angular-headless";

@Component({
  imports: [Button],
  template: `<lily-button (click)="save()">Save</lily-button>`,
})

Blazor

<Button OnClick="Save">Save</Button>

Nunjucks

{% from "components/button/macro.njk" import button %}

{{ button({ text: "Save", type: "button" }) }}

શૈલીબદ્ધ ઉદાહરણનો ઉપયોગ કરો

ઉદાહરણ એપ્સમાં CSS, રૂટ અને સંપૂર્ણ ડેમો પૃષ્ઠો શામેલ છે. પ્રયોગ કરવાનો સૌથી ઝડપી રસ્તો SvelteKit, Next, Nuxt, Analog અથવા Eleventy ઉદાહરણ એપ શરૂ કરવી અને અહીં ડેમો જોવો છે /components. 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-sveltekit-examples
pnpm install
pnpm run dev

પછી ખોલો http://localhost:5173 અને અહીં બ્રાઉઝ કરો /components.

શૈલી અને ડિઝાઇન ટોકન

દરેક ઘટક તેના રૂટ એલિમેન્ટ પર એક કબાબ-કેસ ક્લાસ સાથે રેન્ડર થાય છે. ઉદાહરણ તરીકે, <Button> આ રીતે રેન્ડર થાય છે <button class="button">। તમને ગમે તેમ શૈલી આપો: 

.button {
  background: var(--my-primary);
  color: #fff;
  padding: 0.75rem 1.5rem;
  border-radius: 0.5rem;
}
.button:hover { background: var(--my-primary-hover); }

Lily ની ડિફોલ્ટ રંગ પેલેટ (ઉદાહરણ એપ્સમાં વપરાયેલી) આ છે:

  • પ્રાથમિક: #2563eb
  • જોખમ: #dc2626
  • ચેતવણી: #f59e0b
  • સફળતા: #16a34a
  • પૃષ્ઠ પૃષ્ઠભૂમિ: #f9fafb
  • કાર્ડ પૃષ્ઠભૂમિ: #ffffff

આ સૂચનો છે, જરૂરિયાતો નથી. તેમને તમારી પોતાની બ્રાન્ડ પેલેટથી બદલો અને Lily ખુશીથી સાથે આવે છે.

તૈયાર થીમ

CSS શૂન્યથી લખવું નથી? Lily આપે છે 57 સ્વતંત્ર સંદર્ભ થીમ આ ડિરેક્ટરીમાં themes/ । દરેક એક સ્ટાઇલશીટ છે જે Lily ક્લાસ હૂકને લક્ષ્ય બનાવે છે — તેને જોડો અને તમે શૈલીબદ્ધ છો: 

<link rel="stylesheet" href="/assets/themes/united-kingdom-government-digital-service.css" />

સમૂહ આને આવરે છે:

  • જાહેર ક્ષેત્ર — NHS England, NHS Scotland અને NHS Wales (દરેક દર્દી-લક્ષી અને વ્યવસાયી-લક્ષી પ્રકારોમાં), GOV.UK GDS, અને U.S. Web Design System.
  • વિક્રેતાઓથી પ્રેરિત — Adobe Spectrum, Mozilla Protocol.
  • સામાન્ય હેતુ — light, dark, nord, dracula, wireframe, અને ત્રીસેક વધુ.

થીમ પસંદગીકારો વાપરે છે :where(...), તેથી તમારું પોતાનું CSS હંમેશા વિશિષ્ટતામાં જીતે છે. રનટાઇમ બદલવા માટે તેમને નીચેના theme-picker સહાયક સાથે જોડો, અથવા અનુસરો થીમિંગ ટ્યુટોરિયલ.

પસંદગી સહાયકો

દરેક ફ્રેમવર્કમાં આઠ નાના પસંદગીકારો છે, દરેક પોતાનું lily-design-system-{framework}-{package} પેકેજ છે (અને તેમને ભેગા કરતું એક picker-bar ). દરેક એક હેડલેસ આઇકન બટન છે જે પોપઅપ ખોલે છે — લિસ્ટબોક્સ, લિંકોની યાદી, શોધ ફોર્મ, અથવા (date-time-picker માટે) તારીખ-પસંદગી સંવાદ — મૂળ <select>નહીં; SSR-સુરક્ષિત છે; અને CSS મોકલતું નથી:

  • theme-picker — વ્યવસ્થાપિત <link>બદલીને રનટાઇમ પર થીમ સ્ટાઇલશીટ લોડ કરે છે, દસ્તાવેજ પર data-theme સેટ કરે છે, અને વૈકલ્પિક રીતે આમાં ટકાવી રાખે છે localStorage.
  • locale-picker — સેટ કરે છે lang અને dir (સ્વચાલિત RTL શોધ સાથે) જેથી તમારી i18n લાઇબ્રેરી અનુસરી શકે; પોતે કંઈ અનુવાદ કરતું નથી.
  • text-size-picker — સેટ કરે છે data-text-size દસ્તાવેજ પર; તમારું CSS દરેક મૂલ્યને ફોન્ટ કદ સાથે જોડે છે.
  • motion-picker — સેટ કરે છે data-motion દસ્તાવેજ પર, મુલાકાતીની ઘટાડેલી-ગતિ સેટિંગથી શરૂ કરીને; તમારું CSS અને સ્ક્રિપ્ટ નક્કી કરે છે કે શું દબાવવું.
  • search-picker — શોધ ક્ષેત્ર ખોલતું આઇકન બટન; સબમિટ કરવાથી શોધ પૃષ્ઠ પર જવાય છે. ક્રિયાનું માલિક છે, પસંદગીનું નહીં.
  • link-picker — તમારી એપ વ્યાખ્યાયિત કરે તે પૃષ્ઠ લિંકો (હોમ, અમારા વિશે, અમારો સંપર્ક કરો, ગોપનીયતા નીતિ, …) નું મેનુ ખોલતું ઘરનું આઇકન. ક્રિયાનું માલિક છે, પસંદગીનું નહીં.
  • share-picker — મૂળ શેર શીટ અથવા ગ્રાહકે આપેલી ગંતવ્ય યાદી ખોલે છે, ઉપરાંત URL કૉપિ. ક્રિયાનું માલિક છે, પસંદગીનું નહીં: કંઈ લાગુ કરતું નથી, કંઈ સાચવતું નથી.
  • date-time-picker — તારીખ, સમય, અથવા બંને માટે ટેક્સ્ટ ક્ષેત્ર ઉપરાંત APG તારીખ-પસંદગી સંવાદ. ફોર્મ મૂલ્યનું માલિક છે, પસંદગીનું નહીં: ISO સ્ટ્રિંગ આમાં અને આમાંથી રૂપાંતરિત થાય છે <input type="date">. 
git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-theme-picker

Svelte કેટલોગ પ્રમાણભૂત સંદર્ભ છે; React, Vue, Angular, HTML, Nunjucks, Web Components અને Blazor પોર્ટ તેની સાથે કરાર-દર-કરાર મેળ ખાય છે. જુઓ સહાયક ટ્યુટોરિયલ.

સુલભતા

ઘટકો લક્ષ્ય બનાવે છે WCAG 2.2 AAA। તે આ પેટર્નને અનુસરે છે:

  • સામાન્ય <div>s.
  • <label for="id"> ને બદલે સેમેન્ટિક HTML એલિમેન્ટ, લેબલને ઇનપુટ સાથે જોડતા.
  • aria-labelledby / aria-describedby પરસ્પર સંદર્ભો માટે.
  • aria-invalid + aria-errormessage ભૂલ સ્થિતિઓ માટે.
  • role="alert" અને aria-live ગતિશીલ સામગ્રી માટે.
  • aria-pressed, aria-expanded, aria-current સ્થિતિ માટે.
  • ગ્રિડ માટે રોવિંગ tabindex ।

ફોકસ સૂચકો જાણી જોઈને ગ્રાહક દ્વારા આપવામાં આવે છે — Lily ક્યારેય તમારી ડિઝાઇન સાથે ટકરાતી ડિફોલ્ટ ફોકસ રિંગ દોરતી નથી. ઉદાહરણ એપ્સ તેમના બધા રૂટ પર સ્વચ્છ axe-core બેઝલાઇન જાળવે છે.

આંતરરાષ્ટ્રીયકરણ

દરેક લેબલ, પ્લેસહોલ્ડર, ભૂલ સંદેશ અને બટન ટેક્સ્ટ એક પ્રોપ છે. પાકી લખેલી સ્ટ્રિંગ નથી. તમારી પસંદગીનું અનુવાદ ફ્રેમવર્ક જોડો — Paraglide, i18next, vue-i18n, react-intl, .resx ફાઇલો, કંઈપણ.

તારીખો, સંખ્યાઓ અને ચલણો માટે, ઘટકો પૂર્વ-ફોર્મેટ કરેલી સ્ટ્રિંગ સ્વીકારે છે: તમે આનાથી ફોર્મેટ કરો છો Intl.DateTimeFormat / Intl.NumberFormat / તમારી પસંદગીની લાઇબ્રેરી અને પરિણામ પસાર કરો છો.

locale-picker સહાયક પસંદ કરેલા લોકેલને તમારી i18n લાઇબ્રેરીને આ રીતે સેટ કરીને જણાવે છે lang અને dir દસ્તાવેજ રૂટ પર.

પરીક્ષણ

દરેક ફ્રેમવર્ક ઉપ-પ્રોજેક્ટ તેના રૂઢ સ્ટેકનો ઉપયોગ કરીને પોતાના પરીક્ષણો મોકલે છે:

  • HTML: વાસ્તવિક બ્રાઉઝર ચલાવતું WebDriverIO.
  • Svelte: Vitest + @testing-library/svelte.
  • React: Vitest + @testing-library/react.
  • Vue: Vitest + @testing-library/vue.
  • Angular: Vitest + TestBed (Analog Vite પ્લગઇન દ્વારા).
  • Nunjucks: રેન્ડર સહાયક સાથે Vitest.
  • Blazor: bUnit.

પરીક્ષણો વાપરે છે ફક્ત Vitest ના બિલ્ટ-ઇન મેચર — ક્યારેય નહીં jest-dom મેચર. આ ટેસ્ટ સ્યુટ્સને પોર્ટેબલ રાખે છે. ઉદાહરણ એપ્સ Playwright એન્ડ-ટુ-એન્ડ સ્યુટ્સ, axe-core સુલભતા બેઝલાઇન અને પ્રતિભાવશીલ વ્યૂપોર્ટ સ્વીપ ઉમેરે છે.

AI એજન્ટ

આ સાઇટ તેના રૂટ પર પ્રકાશિત કરે છે llms.txt અને llms.json — તેના સૌથી મહત્ત્વના પૃષ્ઠોનો પસંદ કરેલો નકશો, અનુસરતા કોઈપણ સાધન માટે llms.txt સંમેલન.

પ્રમાણભૂત મોનોરેપો વધુમાં બે મોકલે છે Claude Skills: lily-design-system-skill: સિસ્ટમ સાથે બનાવતા દરેક માટે Lily ના ખ્યાલો, પરિભાષા અને રચના પેટર્નને આવરતી સામાન્ય-હેતુ કુશળતા, અને lily-design-system-maintainer-skill, તેના પર કામ કરતા દરેક માટે મોનોરેપોના જરૂરી-ફાઇલ લેઆઉટ અને સાધનોને આવરતી તકનીકી કુશળતા. બંને આના રૂટ પર છે પ્રમાણભૂત મોનોરેપો.

મુશ્કેલી નિવારણ

ઘટક રેન્ડર થાય છે પણ શૈલી વિનાનો દેખાય છે

તે હેડલેસ ઇરાદા મુજબ કામ કરે છે — ઘટક સાથે કોઈ CSS આવતું નથી. કાં તો ઘટકના કબાબ-કેસ ક્લાસ માટે CSS લખો (દરેક કેટલોગ પૃષ્ઠ પર બતાવેલ)અથવા આમાંથી એક જોડો 57 તૈયાર થીમ.

મારું CSS થીમ પર લાગુ થતું દેખાતું નથી

થવું જોઈએ — થીમ પસંદગીકારો આમાં લપેટાયેલા છે :where(...), જેની વિશિષ્ટતા શૂન્ય છે. જો નિયમ હજુ હારે, તો તપાસો કે તમારી સ્ટાઇલશીટ થીમના <link> પછી લોડ થાય છે અને પસંદગીકાર ખરેખર ઘટકના ક્લાસ હૂક સાથે મેળ ખાય છે.

pnpm install પીઅર અથવા આવૃત્તિ ભૂલ સાથે નિષ્ફળ જાય છે

વર્તમાન pnpm (v10+) અને Node 22+ વાપરો. દરેક ઉપ-પ્રોજેક્ટ તેની ફ્રેમવર્ક આવૃત્તિઓ પોતાના package.jsonમાં પિન કરે છે; જો તમારી વૈશ્વિક ટૂલચેન જૂની હોય, તો pnpm env use --global lts સૌથી ઝડપી ઉકેલ છે.

સ્ક્રીન રીડર નિયંત્રણનું ખોટું નામ જાહેર કરે છે

ઘટકનું જરૂરી label પ્રોપ તપાસો — દૃશ્ય ટેક્સ્ટ વિનાના ઘટકોને એકની જરૂર હોય છે, અને ગ્રાહકે આપેલ aria-label / aria-labelledby જે rest-props દ્વારા પસાર થાય છે, જાણી જોઈને બિલ્ટ-ઇન વાયરિંગ પર જીતે છે. દરેક કેટલોગ પૃષ્ઠ ઘટકના ARIA કરારને દસ્તાવેજીકૃત કરે છે.

theme-picker સહાયક સ્ટાઇલશીટ બદલતો નથી

ખાતરી કરો કે themesUrl બ્રાઉઝર મેળવી શકે તેવી ડિરેક્ટરી તરફ નિર્દેશ કરે છે ( themes/ ફાઇલોને સ્થિર અસ્કયામતો તરીકે પીરસો) અને તમારા themes પ્રોપમાંના થીમ સ્લગ ફાઇલ નામો સાથે મેળ ખાય છે. સહાયક બદલે છે href એક વ્યવસ્થાપિત <link data-lily-theme-picker> નું — માંગાતું URL જોવા devtools માં તપાસો.

બીજું કંઈક તૂટેલું છે

ઓછામાં ઓછા પુનરુત્પાદન સાથે અહીં issue ખોલો github.com/LilyDesignSystem/lily-design-system — અથવા જુઓ સમુદાય અને સપોર્ટ.

  • વધુ સારી ઉદાહરણ શૈલી — શું શક્ય છે તે બતાવો.

  • ઓછામાં ઓછા પુનરુત્પાદન સાથે બગ અહેવાલો.
  • સ્ક્રીન રીડર અને સહાયક તકનીક સાથે સુલભતા ઓડિટ.

FAQ

શૈલીબદ્ધને બદલે હેડલેસ કેમ?

પૂર્વ-શૈલીબદ્ધ ઘટકો અનુકૂળ છે — જ્યાં સુધી તે તમારી બ્રાન્ડ સાથે મેળ ખાતા નથી. હેડલેસ ઘટકોને શરૂઆતમાં થોડું વધુ કામ જોઈએ છે પણ દૃશ્ય ડિઝાઇન પર સંપૂર્ણ નિયંત્રણ આપે છે. ઉદાહરણ એપ્સ અને 57 થીમ તેમને શૈલી આપવાના માર્ગો બતાવે છે; તમે તેમને લઈ શકો અથવા સંપૂર્ણ બદલી શકો. લાંબી દલીલ અહીં છે Lily શા માટે.

આટલા બધા ઘટકો કેમ?

Lily નો હેતુ મોટાભાગની એપ્સને જોઈતી પેટર્ન તમને તે શૂન્યથી બનાવવા મજબૂર કર્યા વિના આવરવાનો છે — રાષ્ટ્રીય ઓળખકર્તા ઇનપુટ અને સંપાદકીય scrollytelling જેવી ઊંડી બાબતો સહિત. કેટલોગ ડઝન સ્થાપિત ડિઝાઇન સિસ્ટમો અને મૌલિક કામમાંથી લે છે — જુઓ વિશે.

શું હું Lily ને Tailwind સાથે વાપરી શકું?

હા. દરેક ઘટક એક કબાબ-કેસ રૂટ ક્લાસ ઉપરાંત ગ્રાહકે આપેલ className / classખુલ્લું કરે છે. Tailwind યુટિલિટી ઉપર તમને ગમે તેમ સ્તર ચઢાવો.

શું હું Lily ને DaisyUI જેવા સેમેન્ટિક CSS ફ્રેમવર્ક સાથે વાપરી શકું?

હા. રૂટ એલિમેન્ટ પરના કબાબ-કેસ ક્લાસ નામો સેમેન્ટિક CSS હૂક તરીકે કામ કરે છે. Lily ને સેમેન્ટિક ફ્રેમવર્ક સાથે જોડો અને તમને પૂર્વ-શૈલીબદ્ધ ઘટકો મળે છે જે છતાં ARIA અને i18n નો આદર કરે છે.

શું npm પેકેજ છે?

પસંદગી સહાયકો npm/NuGet પ્રકાશન પાઇપલાઇન સાથેના પેકેજ તરીકે આવે છે. હેડલેસ ઘટક લાઇબ્રેરીઓ ક્લોન કરવા અથવા વેન્ડર કરવા માટે રચાયેલી છે — સ્રોત જ ડિલિવરેબલ છે, જેથી તમે જે શિપ કરો છો તે બરાબર વાંચી, કાપી અને માલિકીમાં રાખી શકો. હેડલેસ લાઇબ્રેરીઓનું રજિસ્ટ્રી પર પ્રકાશન રોડમેપ પર જ છે.

બહુ-લાઇસન્સ કેમ?

જુદા જુદા પ્રોજેક્ટ્સની લાઇસન્સ જરૂરિયાતો જુદી હોય છે. BSD અને MIT ઉદાર છે, Apache-2.0 માં પેટન્ટ અનુદાન છે, અને GPL વિકલ્પો કૉપીલેફ્ટને ટેકો આપે છે. તમારી પરિસ્થિતિને બંધ બેસે તે પસંદ કરો.
