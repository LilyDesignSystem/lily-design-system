Installatioun

Lily lieft an enger eenzeger Git-Monorepo, mat engem Verzeechnes fir d’Headless-Bibliothéik, d’Helferpakéiten an d’Beispillapplikatioun vun all Framework. Dee schnellste Wee fir et auszeprobéieren ass, d’Monorepo ze klonen an d’Headless-Bibliothéik fir Äre Stack opzemaachen: 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-react-headless
pnpm install

Dat selwecht Muster funktionéiert fir déi aner Frameworken:

  • @lilydesignsystem/html-headless — keng Installatioun néideg; kopéiert d’ .html -Dateien
  • @lilydesignsystem/svelte-headless — pnpm install
  • @lilydesignsystem/react-headless — pnpm install
  • @lilydesignsystem/vue-headless — pnpm install
  • @lilydesignsystem/angular-headless — pnpm install
  • @lilydesignsystem/nunjucks-headless — pnpm install
  • lily-design-system-blazor-headless — dotnet build

D’Headless-Bibliothéike sinn dofir geduecht, gekloont oder agebonnen ze ginn — behandelt de Quellcode als Quell vun der Wourecht a kopéiert, wat Dir braucht. Astellungshelfer ginn zousätzlech als installéierbar Pakéite mat Build- a Verëffentlechungspipeline geliwwert (npm fir d’JS-Frameworken, NuGet fir Blazor).

Eng Headless-Komponent benotzen

Headless-Komponenten liwwere semantescht HTML, ARIA an Eegenschaften — awer kee CSS. Hei ass e Button a jidder Framework:

HTML

<button class="button" type="button" aria-label="Save">
  Save
</button>

Svelte

<script>
  import Button from "lily-design-system-svelte-headless/components/Button/Button.svelte";
</script>

<Button onclick={save}>Save</Button>

React

import Button from "lily-design-system-react-headless/components/Button";

<Button onClick={save}>Save</Button>

Vue

<script setup>
  import Button from "lily-design-system-vue-headless/components/Button.vue";
</script>

<Button @click="save">Save</Button>

Angular

import { Button } from "@lilydesignsystem/angular-headless";

@Component({
  imports: [Button],
  template: `<lily-button (click)="save()">Save</lily-button>`,
})

Blazor

<Button OnClick="Save">Save</Button>

Nunjucks

{% from "components/button/macro.njk" import button %}

{{ button({ text: "Save", type: "button" }) }}

E gestylt Beispill benotzen

D’Beispillapplikatioune enthalen CSS, Routen a voll Demosäiten. Dee schnellste Wee fir ze experimentéieren ass, d’SvelteKit-, Next-, Nuxt-, Analog- oder Eleventy-Beispillapplikatioun ze starten an d’Demo ze kucken op /components. 

git clone https://github.com/LilyDesignSystem/lily-design-system
cd lily-design-system/lily-design-system-svelte-sveltekit-examples
pnpm install
pnpm run dev

Dann maacht http://localhost:5173 op a stéiert duerch /components.

Stylung an Design-Tokens

All Komponent gëtt mat enger eenzeger Kebab-Case-Klass op hirem Wuerzelelement gerendert. Zum Beispill gëtt <Button> gerendert als <button class="button">. Stylt et, wéi Dir wëllt: 

.button {
  background: var(--my-primary);
  color: #fff;
  padding: 0.75rem 1.5rem;
  border-radius: 0.5rem;
}
.button:hover { background: var(--my-primary-hover); }

Dem Lily seng Standardfaarfpalette (a Beispillapplikatiounen benotzt) ass:

  • Primär: #2563eb
  • Gefor: #dc2626
  • Warnung: #f59e0b
  • Erfolleg: #16a34a
  • Säitenhannergrond: #f9fafb
  • Kaartenhannergrond: #ffffff

Dat sinn Virschléi, keng Viraussetzungen. Ersetzt se duerch Är eege Markepalette a Lily kënnt gär mat.

Fäerdeg Themen

Wëllt Dir CSS net vun Null un schreiwen? Lily liwwert 57 eegestänneg Referenzthemen am Verzeechnes themes/ . All ass e Stylesheet, dat op d’Klassenhake vu Lily zielt — verlénkt et an Dir sidd gestylt: 

<link rel="stylesheet" href="/assets/themes/united-kingdom-government-digital-service.css" />

De Set deckt of:

  • Ëffentleche Secteur — NHS England, NHS Scotland an NHS Wales (all a Patienten- a Fachpersounevarianten), GOV.UK GDS an d’U.S. Web Design System.
  • Vun Ubidder inspiréiert — Adobe Spectrum, Mozilla Protocol.
  • Allgemengen Zweck — light, dark, nord, dracula, wireframe an nach drësseg anerer.

Thema-Selektore benotzen :where(...), sou dass Äre eegene CSS ëmmer an der Spezifizitéit gewënnt. Kombinéiert se mam Helfer theme-picker ënnen fir Wiessel während der Lafzäit, oder follegt dem Themen-Tutorial.

Astellungshelfer

All Framework huet aacht kleng Wieler, jiddereen e Pakéit lily-design-system-{framework}-{package} fir sech (an e picker-bar , dee se zesummebaut). All ass en Headless-Ikonknäppchen, dat e Popup opmécht — eng Lëscht, eng Linklëscht, e Sichformulaire oder (bei date-time-picker) en Datumsauswiel-Dialog — net e native <select>; ass SSR-sécher; a liwwert kee CSS:

  • theme-picker — lued Thema-Stylesheets während der Lafzäit, andeems en en geréierte <link>austauscht, setzt data-theme um Dokument an späichert optional persistent an localStorage.
  • locale-picker — setzt lang an dir (mat automatescher RTL-Erkennung), sou dass Är i18n-Bibliothéik nokënnt; iwwersetzt selwer näischt.
  • text-size-picker — setzt data-text-size um Dokument; Äre CSS bilt all Wäert op eng Schrëftgréisst of.
  • motion-picker — setzt data-motion um Dokument, ausgoend vun der Astellung vum Besucher fir reduzéiert Bewegung; Äre CSS an Är Skripte entscheeden, wat ënnerdréckt gëtt.
  • search-picker — e Ikonknäppchen, dat e Sichfeld opmécht; d’Aschécken navigéiert op eng Sichsäit. Besëtzt eng Aktioun, keng Astellung.
  • link-picker — eng Haus-Ikon, déi e Menü mat de Säitelénken opmécht, déi Är Applikatioun definéiert (Startsäit, Iwwer eis, Kontaktéiert eis, Dateschutzrichtlinn, …). Besëtzt eng Aktioun, keng Astellung.
  • share-picker — mécht d’native Deelen-Blat oder eng vum Konsument geliwwert Zillëscht op, plus URL kopéieren. Besëtzt eng Aktioun, keng Astellung: wend näischt un, späichert näischt.
  • date-time-picker — en Textfeld plus en APG-Datumsauswiel-Dialog fir en Datum, eng Zäit oder béides. Besëtzt e Formulairewäert, keng Astellung: de ISO-String gëtt hin an hier ëmgewandelt an <input type="date">.

Zougänglechkeet

D’Komponente ziilen op WCAG 2.2 AAA. Si follegen dëse Mustere:

  • Semantesch HTML-Elementer amplaz generesch <div>s.
  • <label for="id"> -Elementer, déi Etiketten mat Inputen verbannen.
  • aria-labelledby / aria-describedby fir Quervirweiser.
  • aria-invalid + aria-errormessage fir Feelerzoustänn.
  • role="alert" an aria-live fir dynamesch Inhalter.
  • aria-pressed, aria-expanded, aria-current fir den Zoustand.
  • Roving tabindex fir Gitter.

Fokusindikatore ginn bewosst vum Konsument geliwwert — Lily zeechent ni e Standard-Fokusring, deen mat Ärem Design kollidéiert. D’Beispillapplikatioune halen eng propper axe-core-Basislinn op all hire Routen.

Internationaliséierung

All Etikett, Platzhalter, Feelermeldung an Knäppertext ass eng Eegenschaft. Et ginn keng fest geschriwwe Zeechefolgen. Verbannt de Iwwersetzungs-Framework Ärer Wiel — Paraglide, i18next, vue-i18n, react-intl, .resx-Dateien, alles.

Fir Datumer, Zuelen a Währunge huelen d’Komponenten virformatéiert Zeechefolgen un: Dir formatéiert mat Intl.DateTimeFormat / Intl.NumberFormat / Ärer léifste Bibliothéik a gitt d’Resultat weider.

Den locale-picker -Helfer signaliséiert d’gewielt Lokal un Är i18n-Bibliothéik, andeems en lang an dir op der Dokumentwuerzel setzt.

Testen

All Framework-Ënnerprojet liwwert seng eege Tester mat sengem idiomateschen Stack:

  • HTML: WebDriverIO, dat richteg Browser lafe léisst.
  • Svelte: Vitest + @testing-library/svelte.
  • React: Vitest + @testing-library/react.
  • Vue: Vitest + @testing-library/vue.
  • Angular: Vitest + TestBed (iwwer de Analog-Vite-Plugin).
  • Nunjucks: Vitest mat engem Render-Helfer.
  • Blazor: bUnit.

D’Tester benotzen just déi agebaute Matcher vu Vitest — ni jest-dom -Matcher. Dat hält d’Test-Suiten portabel. D’Beispillapplikatioune füügen Playwright-End-to-End-Suiten, axe-core-Zougänglechkeetsbasislinnen an e Sweep duerch responsiv Viewports derbäi.

Feelersich

Eng Komponent gëtt gerendert, gesäit awer net gestylt aus

Dat ass Headless, wéi geduecht — mat der Komponent kënnt kee CSS. Entweder schreift CSS géint d’Kebab-Case-Klass vun der Komponent (op all Katalogsäitugewisen) oder verlénkt ee vun de 57 fäerdegen Themen.

Mäi CSS schéngt net iwwer engem Thema ze gëllen

Et sollt — Thema-Selektore sinn a :where(...)gepak, wat null Spezifizitéit huet. Wann eng Regel trotzdem verléiert, kontrolléiert, ob Äre Stylesheet no dem <link> vum Thema gelueden gëtt an ob de Selektor wierklech mam Klassenhaken vun der Komponent iwwereneestëmmt.

pnpm install schléit mat engem Peer- oder Versiounsfeeler fehl

Benotzt e rezente pnpm (v10+) a Node 22+. All Ënnerprojet fixéiert seng Framework-Versiounen a sengem eegene package.json; wann Är global Toolchain méi al ass, ass pnpm env use --global lts de schnellste Fix.

Den Écran-Lieser kënnegt de falschen Numm fir e Steierelement un

Kontrolléiert déi néideg label -Eegenschaft vun der Komponent — Komponenten ouni sichtbare Text verlaangen eng, a vum Konsument geliwwert aria-label / aria-labelledby iwwer Rest-Props weidergi gewënnen bewosst iwwer déi agebaute Verdrahtung. All Katalogsäit dokumentéiert den ARIA-Kontrakt vun der Komponent.

Den theme-picker-Helfer wiesselt keng Stylesheets

Bestätegt, dass themesUrl op e Verzeechnes weist, dee de Browser ofruffe kann (stellt d’ themes/ -Dateien als statesch Assets zur Verfügung) an dass d’Thema-Slugs an Ärer themes -Eegenschaft mat den Dateinimm iwwereneestëmmen. Den Helfer tauscht d’ href vun engem geréierten <link data-lily-theme-picker> aus — inspizéiert en an den Entwécklergeschirer, fir déi ugefrote URL ze gesinn.

FAQ

Firwat headless amplaz gestylt?

Virgestylte Komponente sinn praktesch — bis se net méi bei Är Mark passen. Headless-Komponente brauche am Ufank e bëssen méi Aarbecht, ginn Iech awer total Kontroll iwwer dat visuellt Design. D’Beispillapplikatioun an déi 57 Themen weisen Weeër, se ze stylen; Dir kënnt se iwwerhuelen oder komplett ersetzen. Dat méi laangt Argument ass op Firwat Lily.

Firwat sou vill Komponenten?

Lily wëll d’Muster ofdecken, déi déi meescht Applikatioune brauchen, ouni Iech ze zwéngen, se vun Null un ze bauen — dorënner déif Saachen wéi Inputen fir national Identifikateuren a redaktionelle Scrollytelling. De Katalog schöpft aus enger Dose etabléierte Designsystemer plus Eegenaarbecht — kuckt Iwwer.

Kann ech Lily mat Tailwind benotzen?

Jo. All Komponent stellt eng eenzeg Kebab-Case-Wuerzelklass plus e vum Konsument geliwwerte className / classzur Verfügung. Leet Tailwind-Utilities drop, wéi Dir wëllt.

Kann ech Lily mat semanteschen CSS-Frameworken wéi DaisyUI benotzen?

Jo. D’Kebab-Case-Klassennimm um Wuerzelelement funktionéieren als semantesch CSS-Haken. Kombinéiert Lily mat engem semanteschen Framework a Dir kritt virgestylt Komponenten, déi trotzdem ARIA an i18n respektéieren.

Gëtt et e npm-Pakéit?

D’ Astellungshelfer ginn als Pakéite mat enger npm-/NuGet-Verëffentlechungspipeline geliwwert. D’Headless-Komponentebibliothéike sinn dofir geduecht, gekloont oder agebonnen ze ginn — de Quellcode ass d’Liwwerung, sou dass Dir genee dat liese, ofspecke a besëtze kënnt, wat Dir ausliwwert. D’Verëffentlechung vun den Headless-Bibliothéiken a Registries bleift op der Roadmap.

Firwat méi Lizenzen?
