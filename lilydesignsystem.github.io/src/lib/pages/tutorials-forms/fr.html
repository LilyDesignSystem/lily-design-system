Tutoriel des formulaires accessibles

Le modèle que suit chaque formulaire Lily, quel que soit le framework : étiqueter chaque contrôle, vérifier à l'envoi, placer chaque erreur à côté de son champ et récapituler les erreurs là où arrive le focus.

Ce que vous allez construire

Un formulaire à deux champs qui, envoyé avec des erreurs, dit ce qui ne va pas, à côté de chaque champ et dans un récapitulatif en haut, et y déplace le focus, pour qu'une personne au clavier ou avec un lecteur d'écran trouve les erreurs tout de suite. Il est présenté en HTML simple avec les classes Lily ; chaque catalogue de framework produit le même balisage à partir de ses propres composants Field, Hint, ErrorMessage et ErrorSummary . Environ 20 minutes ; le tutoriel HTML aide à commencer.

Étape 1 — Étiqueter chaque contrôle et dire ce qui est attendu

<form class="form" novalidate>
  <div class="field">
    <label class="label" for="name">Full name</label>
    <input class="text-input" type="text" id="name" name="name" autocomplete="name" required />
  </div>
  <div class="field">
    <label class="label" for="email">Email</label>
    <p class="hint" id="email-hint">We only use this to send your appointment.</p>
    <input class="email-input" type="email" id="email" name="email"
      autocomplete="email" aria-describedby="email-hint" required />
  </div>
  <button class="button" type="submit">Continue</button>
</form>
  • Un <label for> visible sur chaque contrôle, jamais un texte indicatif à sa place : celui-ci disparaît dès que l'on tape.
  • Une indication s'ajoute au nom du champ grâce à aria-describedby, si bien qu'un lecteur d'écran la lit avec le champ.
  • autocomplete permet au navigateur de remplir ce qu'il connaît (WCAG 1.3.5).
  • novalidate désactive les bulles du navigateur, car vous afficherez vous-même les erreurs, avec vos mots et dans votre langue. Les attributs required et type restent : votre script les lit.

Étape 2 — Vérifier à l'envoi, pas pendant la saisie

Dire à quelqu'un que son adresse e-mail est fausse après une seule lettre n'est que du bruit. Vérifiez à l'envoi. Les 63 thèmes ne présentent déjà un champ comme invalide qu'après qu'il a été modifié puis quitté (:user-invalid), ou lorsque vous définissez aria-invalid="true", si bien que rien ne devient rouge au chargement de la page.

Ne désactivez jamais le bouton d'envoi tant que le formulaire n'est pas valide : un bouton désactivé ne peut pas dire pourquoi.

Étape 3 — Placer chaque erreur à côté de son champ

<div class="field">
  <label class="label" for="email">Email</label>
  <p class="hint" id="email-hint">We only use this to send your appointment.</p>
  <p class="error-message" id="email-error">Enter an email address in the right format, like name@example.com</p>
  <input class="email-input" type="email" id="email" name="email" autocomplete="email"
    aria-invalid="true" aria-describedby="email-hint email-error" required />
</div>
  • aria-invalid="true" indique que le champ est erroné ; le message dit pourquoi et comment le corriger.
  • Le message figure dans aria-describedby, après l'indication, et il est donc lu quand le champ reçoit le focus.
  • Dites quoi faire, pas seulement ce qui ne va pas : « Saisissez une adresse e-mail au bon format », et non « Invalide ».
  • Jamais la couleur seule : le texte est l'erreur ; la bordure rouge ne fait que le répéter (WCAG 1.4.1).

Étape 4 — Récapituler les erreurs là où arrive le focus

<div class="error-summary" role="alert" tabindex="-1" aria-labelledby="error-summary-title">
  <h2 id="error-summary-title">There is a problem</h2>
  <ul>
    <li><a href="#name">Enter your full name</a></li>
    <li><a href="#email">Enter an email address in the right format, like name@example.com</a></li>
  </ul>
</div>

Placez-le en haut du formulaire et déplacez-y le focus à l'envoi. Chaque lien mène directement à son champ. tabindex="-1" permet au récapitulatif de recevoir le focus sans ajouter d'arrêt de tabulation.

Étape 5 — Le script qui relie le tout

const messages = {
  name: { valueMissing: "Enter your full name" },
  email: {
    valueMissing: "Enter your email address",
    typeMismatch: "Enter an email address in the right format, like name@example.com",
  },
};

const form = document.querySelector("form");
form.addEventListener("submit", (event) => {
  form.querySelector(".error-summary")?.remove();
  const errors = [];
  for (const field of form.querySelectorAll("input")) {
    const old = document.getElementById(field.id + "-error");
    old?.remove();
    const describedBy = (field.getAttribute("aria-describedby") ?? "")
      .split(" ").filter((id) => id && id !== field.id + "-error");
    const problem = Object.keys(messages[field.name] ?? {}).find((key) => field.validity[key]);
    if (!problem) {
      field.removeAttribute("aria-invalid");
      field.setAttribute("aria-describedby", describedBy.join(" "));
      continue;
    }
    const text = messages[field.name][problem];
    const message = document.createElement("p");
    message.className = "error-message";
    message.id = field.id + "-error";
    message.textContent = text;
    field.before(message);
    field.setAttribute("aria-invalid", "true");
    field.setAttribute("aria-describedby", [...describedBy, message.id].join(" "));
    errors.push({ id: field.id, text });
  }
  if (errors.length === 0) return; // valid: let it submit
  event.preventDefault();
  const summary = document.createElement("div");
  summary.className = "error-summary";
  summary.setAttribute("role", "alert");
  summary.tabIndex = -1;
  summary.setAttribute("aria-labelledby", "error-summary-title");
  summary.innerHTML = '<h2 id="error-summary-title">There is a problem</h2><ul></ul>';
  for (const { id, text } of errors) {
    const link = document.createElement("a");
    link.href = "#" + id;
    link.textContent = text;
    const item = document.createElement("li");
    item.append(link);
    summary.querySelector("ul").append(item);
  }
  form.prepend(summary);
  summary.focus();
});

Les messages sont les vôtres, dans votre langue : la propriété validity du navigateur indique quelle règle a échoué, et votre table dit quoi annoncer à la personne. Lily ne fournit aucun texte anglais à traduire.

Vérifiez votre travail : envoyez le formulaire vide au clavier. Le focus passe au récapitulatif et un lecteur d'écran lit « There is a problem » et les deux erreurs. Suivez un lien : le focus arrive dans le champ, lu avec son indication et son erreur. Corrigez les deux et envoyez : le formulaire passe, sans erreur résiduelle.

À éviter

  • Limiter ou corriger ce que quelqu'un a saisi sans le dire ; dites-le-lui plutôt.
  • Vider un formulaire en cas d'erreur : conservez tout ce qui a été saisi.
  • Une erreur qui n'apparaît qu'au survol, ou seulement dans une infobulle.
  • Faire expirer un formulaire sans prévenir ; utilisez timeout-dialog pour avertir et prolonger.
