প্রবেশযোগ্য ফর্ম টিউটোরিয়াল

ফ্রেমওয়ার্ক যা-ই হোক, প্রতিটি Lily ফর্ম এই নকশা মেনে চলে: প্রতিটি নিয়ন্ত্রণে লেবেল দিন, জমা দেওয়ার সময় যাচাই করুন, প্রতিটি ত্রুটি তার ঘরের পাশে রাখুন, আর যেখানে ফোকাস পৌঁছায় সেখানে ত্রুটিগুলোর সারাংশ দিন।

আপনি কী বানাবেন

দুটি ঘরের একটি ফর্ম, যা ভুলসহ জমা দিলে বলে কী ভুল হয়েছে, প্রতিটি ঘরের পাশে এবং ওপরে একটি সারাংশে, আর ফোকাস সেখানে নিয়ে যায়, যাতে কীবোর্ড বা স্ক্রিন রিডার ব্যবহারকারী সঙ্গে সঙ্গে ত্রুটিগুলো খুঁজে পান। এটি Lily ক্লাস হুকসহ সাধারণ HTML-এ দেখানো হয়েছে; প্রতিটি ফ্রেমওয়ার্কের ক্যাটালগ নিজের Field, Hint, ErrorMessage এবং ErrorSummary কম্পোনেন্ট থেকে একই মার্কআপ তৈরি করে। প্রায় ২০ মিনিট; আগে HTML টিউটোরিয়াল করে নিলে সুবিধা হয়।

ধাপ ১ — প্রতিটি নিয়ন্ত্রণে লেবেল দিন, আর বলুন কী আশা করছেন

<form class="form" novalidate>
  <div class="field">
    <label class="label" for="name">Full name</label>
    <input class="text-input" type="text" id="name" name="name" autocomplete="name" required />
  </div>
  <div class="field">
    <label class="label" for="email">Email</label>
    <p class="hint" id="email-hint">We only use this to send your appointment.</p>
    <input class="email-input" type="email" id="email" name="email"
      autocomplete="email" aria-describedby="email-hint" required />
  </div>
  <button class="button" type="submit">Continue</button>
</form>
  • প্রতিটি নিয়ন্ত্রণে একটি দৃশ্যমান <label for> , তার জায়গায় কখনো প্লেসহোল্ডার নয়: টাইপ করলেই প্লেসহোল্ডার মুছে যায়।
  • ইঙ্গিত ঘরের নামের সঙ্গে যুক্ত হয় aria-describedbyদিয়ে, তাই স্ক্রিন রিডার ঘরের সঙ্গে সেটিও পড়ে।
  • autocomplete ব্রাউজারকে তার জানা তথ্য পূরণ করতে দেয় (WCAG 1.3.5)।
  • novalidate ব্রাউজারের নিজস্ব বুদবুদ বন্ধ করে, কারণ ত্রুটিগুলো আপনি নিজেই দেখাবেন, নিজের ভাষায় ও শব্দে। required এবং type থেকে যায়: আপনার স্ক্রিপ্ট সেগুলো পড়ে।

ধাপ ২ — জমা দেওয়ার সময় যাচাই করুন, টাইপ করার সময় নয়

একটি অক্ষর লেখার পরই কাউকে বলা যে তার ইমেল ভুল, শুধুই বিরক্তি। জমা দেওয়ার সময় যাচাই করুন। ৬৩টি থিমই কোনো ঘরকে অবৈধ দেখায় শুধু সেটি সম্পাদনা করে ছেড়ে যাওয়ার পর (:user-invalid), অথবা যখন আপনি aria-invalid="true"সেট করেন, তাই পাতা খোলার সময় কিছুই লাল হয় না।

ফর্ম বৈধ না হওয়া পর্যন্ত জমা দেওয়ার বোতাম কখনো নিষ্ক্রিয় করবেন না: নিষ্ক্রিয় বোতাম কারণ বলতে পারে না।

ধাপ ৩ — প্রতিটি ত্রুটি তার ঘরের পাশে রাখুন

<div class="field">
  <label class="label" for="email">Email</label>
  <p class="hint" id="email-hint">We only use this to send your appointment.</p>
  <p class="error-message" id="email-error">Enter an email address in the right format, like name@example.com</p>
  <input class="email-input" type="email" id="email" name="email" autocomplete="email"
    aria-invalid="true" aria-describedby="email-hint email-error" required />
</div>
  • aria-invalid="true" জানায় যে ঘরটি ভুল; বার্তা জানায় কেন এবং কীভাবে ঠিক করতে হবে।
  • বার্তাটি আছে aria-describedby-এ, ইঙ্গিতের পরে, তাই ঘরে ফোকাস এলে তা পড়া হয়।
  • কী করতে হবে তা বলুন, শুধু কী ভুল তা নয়: "সঠিক বিন্যাসে একটি ইমেল ঠিকানা দিন", "অবৈধ" নয়।
  • কখনো শুধু রং নয়: লেখাই ত্রুটি; লাল সীমানা কেবল তা পুনরাবৃত্তি করে (WCAG 1.4.1)।

ধাপ ৪ — যেখানে ফোকাস পৌঁছায় সেখানে ত্রুটির সারাংশ দিন

<div class="error-summary" role="alert" tabindex="-1" aria-labelledby="error-summary-title">
  <h2 id="error-summary-title">There is a problem</h2>
  <ul>
    <li><a href="#name">Enter your full name</a></li>
    <li><a href="#email">Enter an email address in the right format, like name@example.com</a></li>
  </ul>
</div>

এটি ফর্মের ওপরে রাখুন এবং জমা দেওয়ার সময় ফোকাস এখানে আনুন। প্রতিটি লিঙ্ক সরাসরি তার ঘরে যায়। tabindex="-1" নতুন ট্যাব-থামা যোগ না করেই সারাংশকে ফোকাস নিতে দেয়।

ধাপ ৫ — সব কিছু জুড়ে দেওয়া স্ক্রিপ্ট

const messages = {
  name: { valueMissing: "Enter your full name" },
  email: {
    valueMissing: "Enter your email address",
    typeMismatch: "Enter an email address in the right format, like name@example.com",
  },
};

const form = document.querySelector("form");
form.addEventListener("submit", (event) => {
  form.querySelector(".error-summary")?.remove();
  const errors = [];
  for (const field of form.querySelectorAll("input")) {
    const old = document.getElementById(field.id + "-error");
    old?.remove();
    const describedBy = (field.getAttribute("aria-describedby") ?? "")
      .split(" ").filter((id) => id && id !== field.id + "-error");
    const problem = Object.keys(messages[field.name] ?? {}).find((key) => field.validity[key]);
    if (!problem) {
      field.removeAttribute("aria-invalid");
      field.setAttribute("aria-describedby", describedBy.join(" "));
      continue;
    }
    const text = messages[field.name][problem];
    const message = document.createElement("p");
    message.className = "error-message";
    message.id = field.id + "-error";
    message.textContent = text;
    field.before(message);
    field.setAttribute("aria-invalid", "true");
    field.setAttribute("aria-describedby", [...describedBy, message.id].join(" "));
    errors.push({ id: field.id, text });
  }
  if (errors.length === 0) return; // valid: let it submit
  event.preventDefault();
  const summary = document.createElement("div");
  summary.className = "error-summary";
  summary.setAttribute("role", "alert");
  summary.tabIndex = -1;
  summary.setAttribute("aria-labelledby", "error-summary-title");
  summary.innerHTML = '<h2 id="error-summary-title">There is a problem</h2><ul></ul>';
  for (const { id, text } of errors) {
    const link = document.createElement("a");
    link.href = "#" + id;
    link.textContent = text;
    const item = document.createElement("li");
    item.append(link);
    summary.querySelector("ul").append(item);
  }
  form.prepend(summary);
  summary.focus();
});

বার্তাগুলো আপনার, আপনার ভাষায়: ব্রাউজারের validity জানায় কোন নিয়ম ব্যর্থ হয়েছে, আর আপনার তালিকা জানায় মানুষটিকে কী বলতে হবে। Lily অনুবাদ করার মতো কোনো ইংরেজি লেখা দেয় না।

আপনার কাজ যাচাই করুন: খালি ফর্মটি কীবোর্ড দিয়ে জমা দিন। ফোকাস সারাংশে যায় এবং স্ক্রিন রিডার "There is a problem" ও দুটি ত্রুটি পড়ে। একটি লিঙ্ক অনুসরণ করুন: ফোকাস ঘরে পৌঁছায়, যা তার ইঙ্গিত ও ত্রুটিসহ পড়া হয়। দুটোই ঠিক করে জমা দিন: ফর্ম চলে যায়, কোনো ত্রুটি থাকে না।

যা এড়িয়ে চলবেন

  • কেউ যা টাইপ করেছে তা না জানিয়ে সীমিত বা সংশোধন করা; বরং তাকে জানান।
  • ত্রুটি হলে ফর্ম মুছে ফেলা: যা লেখা হয়েছে সব রেখে দিন।
  • এমন ত্রুটি যা শুধু হোভারে বা শুধু টুলটিপে দেখা যায়।
  • সতর্ক না করে ফর্মের সময় শেষ করা; সতর্ক করতে ও সময় বাড়াতে timeout-dialog ব্যবহার করুন।

পরবর্তী ধাপ

  • প্রশিক্ষণ — আটটি মডিউল, প্রতিটিতে একটি অনুশীলন ও আত্মমূল্যায়ন।
  • ErrorSummary, Field এবং ErrorMessage ক্যাটালগে।
  • সারা বিশ্বে কাজ করে এমন ফর্ম — নাম, ঠিকানা, তারিখ ও লেখার দিক।
  • থিমিং — প্রতিটি থিম যে অবৈধ অবস্থা আঁকে।
