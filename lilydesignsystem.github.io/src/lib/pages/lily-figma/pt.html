Nenhuma biblioteca Figma mantida — eis o que existe em vez disso

Esta página dizia «em breve». Já não diz, porque ninguém a estava a construir. Eis o estado honesto, e um caminho real que funciona hoje.

O que não existe

Não existe uma biblioteca oficial de componentes Lily no Figma, nem um plugin do Figma mantido. Construir e manter bem uma biblioteca para uma ferramenta de design é um compromisso real e contínuo — estrutura de componentes do Figma, nomenclatura de variantes, auto-layout, um pipeline de publicação próprio — distinto de manter código, e este projeto não o assumiu.

O que existe hoje

Cada um dos 57 temas de referência tem as suas primitivas de tokens de design — cor, raio, tamanho, contorno — publicadas no formato DTCG 2025.10 em themes/tokens/*.json. Esse formato é exatamente o que as ferramentas modernas de tokens leem. Pode trazer a paleta de um tema Lily para o Figma por si, agora mesmo, sem qualquer plugin deste projeto:

  1. Instale o plugin comunitário Tokens Studio for Figma (ou a importação de Variables do próprio Figma, onde o seu plano suporte a importação DTCG).
  2. Importe themes/tokens/{theme-slug}.json para o tema que quiser — por exemplo united-kingdom-national-health-service-england-for-patients.json.
  3. O Tokens Studio cria variáveis do Figma a partir dos valores DTCG, que pode depois aplicar aos seus próprios componentes.

Isto dá-lhe os tokens de cor e forma da Lily no Figma. Não lhe dá os componentes reais da Lily como componentes do Figma — ninguém os construiu, e esta página não vai fingir o contrário.

Está planeada uma biblioteca Figma real?

Atualmente não, e prometê-la não é gratuito: veja RFC 6 para a questão em aberto e o que mudaria a opinião do projeto — o mais útil é um designer dizer especificamente o que precisa desta camada. Se for o seu caso, diga-nos ou abra um issue.
