# Framework helpers design principle rules

Each framework ships a `*-helpers` catalog of small, opinionated packages that sit alongside the headless library. Where a headless component is a pure container, a helper owns one complete interaction end to end. Most own a **user preference** — selection + DOM application + optional persistence. `share-picker` owns an **action** instead, and `date-time-picker` owns a **form value**: neither applies anything to the document and neither persists anything. They are all helpers because they ship the same headless contract and own the whole interaction, not because they share a lifecycle.

Full contracts: [spec/helpers/index.md](../spec/helpers/index.md).

## The helpers

Every catalog (html, svelte, react, vue, angular, blazor, nunjucks, and — since 2026-09-03 — web-components) ships all six. `lily-design-system-web-components-helpers` is a maintainer-directed **independent copy** of `lily-design-system-html-helpers` (which is itself already six vanilla custom elements) differing in tag prefix (`<lily-theme-picker>` rather than `<theme-picker>`, matching the Web Components headless catalog) and package naming; the two must be kept in step deliberately, since nothing ports between them automatically. As of 2026-09-03:

`date-time-picker` is listed after the table because it does not fit
its columns: it is a form control, not a page-header control.

| ------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| `theme-picker`     | Icon button (bundled contrast/half-circle SVG) + listbox, rooted on `<div class="theme-picker {class}">`  | Swaps a managed `<link rel="stylesheet" data-lily-theme-picker>` href and sets `data-theme` on the document root; pairs with the root `themes/` stylesheets. | Optional `localStorage`.                                                     |

| `text-size-picker` | Icon button (bundled "A" SVG) + listbox, rooted on `<div class="text-size-picker {class}">`               | Sets `data-text-size` on the document root; consumer CSS maps values to sizing.                                                                              | Optional `localStorage`.                                                     |
| `motion-picker`    | Icon button (bundled pause-bars SVG) + listbox, rooted on `<div class="motion-picker {class}">`            | Sets `data-motion` on the document root; consumer CSS/JS maps values to what gets suppressed. Initial value defers to `(prefers-reduced-motion: reduce)` **unconditionally**, not behind an opt-in flag. | Optional `localStorage`.                                                     |
| `share-picker`     | Icon button (bundled outline-arrow SVG) + disclosure list of real links, rooted on `<div class="share-picker {class}">` | Nothing — opens the native share sheet where available, else a list of consumer-supplied destinations plus copy-to-clipboard.                                | None.                                                                        |

| `date-time-picker` | Text field + icon button (📅 U+1F4C5 + U+FE0E) opening an APG date-picker dialog, rooted on `<div class="date-time-picker {class}">` | Nothing — it holds a form value. | None. |

## picker-bar (a composition, not a seventh preference/action/form-value)

`picker-bar` (added 2026-09-15, shipped first in `svelte-helpers` then
ported to all seven other catalogs the same day) is a
`<div class="picker-bar {class}">` that renders `theme-picker`,
`locale-picker`, `text-size-picker`, and `share-picker` — each
depended on as a real npm package, not vendored — in that order, with
two defaults pre-wired: `themes` defaults to all 45 root `themes/`
slugs (alphabetical, UK & US government themes moved to their own
alphabetical group at the bottom), and `sizes` defaults to the
seven-step scale `largest`, `larger`, `large`, `normal`, `small`,
`smaller`, `smallest`, starting on `normal`. It excludes `motion-picker`
(no natural spot in this row) and `date-time-picker` (a form control,
not a page-header control). Its four accessible names arrive as one
required `labels` object (`{ theme, locale, textSize, share }`), no
English default — same reasoning as `date-time-picker`'s `labels`.
Full contract: [spec/helpers/index.md § picker-bar contract](../spec/helpers/index.md).

## Rules

- **One shape, across the five page-header helpers.** Each is an **icon button that opens a popup**, because a single icon is the smallest possible footprint for a control that sits in a page header. The four preference helpers open a listbox; `share-picker` opens a disclosure of links. None may use the radio-group markup the June 2026 migration removed — do not reintroduce it. `date-time-picker` is exempt and only its trigger follows the rule: the reasoning behind "one icon" is page-header footprint, which does not apply to a field in a form, and a date field that cannot be typed into is hostile to anyone who knows the date already.
- **Icon button + listbox contract (the four preference helpers).** Root `<div class="{helper} {class}">` containing a hidden input (form participation, carries `name`), a `<button class="{helper}-button" type="button" aria-label aria-haspopup="listbox" aria-expanded aria-controls>` whose only content is an `aria-hidden` icon (an inline `<svg>` for the five page-header helpers; still a Unicode glyph span for `date-time-picker`'s trigger), and a `<ul class="{helper}-list" role="listbox" tabindex="-1" hidden>` of `<li class="{helper}-option" role="option" aria-selected>`. Keyboard follows the WAI-ARIA APG listbox pattern: the open keys are ArrowDown / ArrowUp / Enter / Space, focus moves to the list, the cursor is `aria-activedescendant` (mirrored to `data-active` for CSS), arrows clamp rather than wrap, Home / End jump, printable characters typeahead over labels, Enter / Space select and return focus to the button, Escape closes without changing the value, Tab closes and moves on. A pointer selection does exactly what Enter does — selects, applies, **and closes** — so `aria-expanded` never survives the choice; a select-without-close leaves a stale `aria-expanded="true"` over a hidden list, and every later click misses the options. The consumer's `children` slot replaces the **icon**, not the options.
- **Composed from headless, not hand-rolled, in Svelte (2026-09-21).** The markup/keyboard contract above is unchanged, but in the canonical `svelte-helpers` catalog it is now implemented by composing `@lilydesignsystem/svelte-headless`'s `IconButton` (all six page-header/dialog helpers) and `Listbox` in its `navigation="active-descendant"` mode (the four preference helpers only — `share-picker`'s list is real navigation links, not a listbox, and `date-time-picker`'s dialog/grid are bespoke), rather than each package re-implementing the same button/listbox logic seven times over. Full reasoning, what was extended on the headless side, and what stayed self-built (and why): [spec/helpers/index.md § "Composition with the headless layer"](../spec/helpers/index.md). Not yet ported to the other seven catalogs.
- **`motion-picker`'s default differs from its three preference siblings.** `theme-picker` and `text-size-picker` resolve an unset value to a fixed slug (no OS signal exists for either). `motion-picker` instead checks the platform's own `(prefers-reduced-motion: reduce)` media query as one step of initial-value resolution — mapped to `"reduce"` / `"no-preference"` when the consumer offers those slugs — and does so **unconditionally**, not behind an opt-in flag like `theme-picker`'s `detectFromSystem`. Motion has a real accessibility signal (WCAG 2.3.3); deferring to it is the correct default, not an enhancement. In the Nunjucks port specifically, the check is unavailable at template-render time (no `matchMedia` on the server), so the macro marks `motions[0]` selected server-side and the client corrects it on init — documented as that catalog's one deviation from the canonical contract.
- **`share-picker` is a disclosure, not a listbox.** Its destinations are navigation, so they are real `<a>` elements: `role="menuitem"` would strip middle-click, open-in-new-tab and copy-link-address, and the APG itself suggests a disclosure when the items are links. Copy is a real `<button>`. Its list holds `{helper}-target` and `{helper}-copy` items rather than `role="option"` ones, and it carries a `{helper}-status` live region for the copy outcome. (Before the July 2026 rename it was `share-button`, and its trigger had to be `share-button-trigger` because `.share-button-button` read badly; the new name removes that exception, so the trigger is now plain `share-picker-button`.)
- **`share-picker` ships no endpoints.** No social-network URLs are bundled: which networks belong in a product is an editorial and privacy decision, and share URLs change. The consumer passes `targets`, each with its own `href(url, title, text)`.
- **Icons are bundled SVGs, not Unicode glyphs.** Reversed 2026-09-16 (maintainer-directed) from the "bare literal character" rule above: each of the five page-header helpers now ships an inline `<svg class="{helper}-icon" viewBox="0 0 16 16" aria-hidden="true" fill="none" stroke="currentColor" stroke-width="1.6" stroke-linecap="round" stroke-linejoin="round" width="1.05rem" height="1.05rem">…</svg>` instead of a text glyph in a `<span>`. A bundled icon renders identically on every platform and font stack — no colour-emoji fallback risk (locale's old globe), no "does this font even have a glyph for this codepoint" risk (motion's old pause sign), no per-glyph optical-scale correction to measure and maintain (see the removed rule below). The exported glyph constants (`CIRCLE_WITH_RIGHT_HALF_BLACK`, `GLOBE_WITH_MERIDIANS`, `LATIN_CAPITAL_LETTER_A`, `PAUSE_SIGN`, `BLACK_RIGHTWARDS_ARROWHEAD`) were **removed, not renamed** — there is no longer a single swappable character value to export. `date-time-picker`'s calendar trigger is unaffected by this reversal and keeps its Unicode glyph (📅︎, U+1F4C5 + U+FE0E) and the bare-literal-character rule for it: `bin/test` still enforces bareness on `CALENDAR` and on any `date-time-picker-icon` markup.
- **The icon is decorative.** It is wrapped in `aria-hidden="true"`; the accessible name comes from the button's `aria-label`. Never let an icon be the accessible name. The five bundled SVGs, one per helper: `theme-picker` a contrast/half-circle (outline circle plus a filled right half), `locale-picker` a globe (outline circle plus an equator line and one meridian curve), `text-size-picker` a stroke-drawn "A", `motion-picker` two vertical pause bars, `share-picker` an outline right arrow (`M2.5 8h11M9 3.5 13.5 8 9 12.5`, matching the icon at https://testingexamples.github.io/). All five share one `viewBox="0 0 16 16"` grid and stroke style (`stroke-width="1.6"`, round caps/joins) so they read as one family.
- **No per-icon optical scale to maintain.** The pre-2026-09-16 rule below is preserved as history, not current practice: Unicode glyphs ink different fractions of their em box at equal `font-size` (measured 2026-09-03, plan P8-T10: ◑ 0.850, 🌐 1.000, "A" 0.675, ⏸ 0.495, ➤ 0.850 — max ink extent, "A" taken on width), which the 45 `themes/*.css` corrected via a `--lily-picker-icon-scale` custom property per glyph (1, 0.845, 1.25, 1.72, 1). A bundled SVG's ink fills a `viewBox` its own author controls, so all five now already ink the same visual size by construction — the theme CSS just centers the icon in its button (`display: inline-flex; align-items: center; justify-content: center;`), no `font-size`/scale math involved. `date-time-picker`'s calendar icon still uses the old scheme (`--lily-picker-icon-scale: 0.845`, inherited from the pre-reversal globe measurement, since colour-emoji fonts paint every glyph into one identical em square) — it is the one remaining Unicode glyph in this family.
- **Applying is idempotent.** A preference already applied is a no-op: no DOM write, no `localStorage` write, no change callback. Every framework reaches the apply step more often than the value actually changes — Svelte's `$effect` re-runs, the HTML element's `attributeChangedCallback` fires on any `setAttribute("value", …)` including an unchanged one, React applies once in controlled mode and again when the consumer writes the value back — and firing the callback each time invites the consumer to write state in it, which loops straight back in. In Svelte that loop ends in `effect_update_depth_exceeded`: the component stops updating its DOM entirely and the listbox freezes mid-open with a stale `aria-expanded`, which is not a symptom anyone reads back to a re-entrant apply. The callback contract is **once per applied change**, and the guard is what makes it true.
- **Headless still.** No bundled CSS, fonts, or images; kebab-case class hook + consumer `class` pass-through; rest-props spread on the root. The one deliberate exception is the default button icon for the five page-header helpers: a bundled SVG (reversed 2026-09-16 from a Unicode glyph — see above), always overridable via `children`.
- **SSR-safe.** DOM writes only inside the framework's mount/effect lifecycle.
- **i18n-clean.** Every user-facing string is a prop; labels default to title-cased slugs with an override map (`themeLabels` / `localeLabels` / `sizeLabels` / `motionLabels`). `date-time-picker` takes one `labels` object instead of a dozen flat props — ten flat `*Label` props is a call site nobody can read — and takes month and weekday names from `Intl` rather than from a table. Its six structural labels are **required**, with no English default, because a nav button we named ourselves is exactly the defect the rule exists to prevent.
- **Spec-driven.** Each helper has a numbered `spec/index.md`; one test per acceptance clause.
- **Svelte is canonical.** Port contracts from `lily-design-system-svelte-helpers`; when catalogs disagree, the Svelte side wins.
- **Publishing.** Each helper is an npm package (`package.json`, `dist/` via the catalog `build.js`) — NuGet `.csproj` for Blazor — released with `bin/publish-helpers`. Each catalog and each helper is its own git subtree.
