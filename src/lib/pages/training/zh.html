培训

面向采用 Lily 的团队的自学课程：八个单元，每个都有目标、阅读材料、在真实浏览器中完成的练习，以及附答案的自测。总共约一天；每次学习一个单元效果最好。

开始之前

先选一个框架 教程 并完成它。练习时可在本地运行一个示例应用，或使用本站的 组件页面 。你需要一个键盘；第 8 单元还需要读屏软件：macOS 和 iOS 上的 VoiceOver、Windows 上的 NVDA 或 Android 上的 TalkBack，全部免费。

第 1 单元 — 无头是什么意思

目标： 了解哪些由 Lily 决定，哪些由你决定。

阅读： 关于页面，以及一个组件页面，例如 Button，从头读到尾。

动手： 在没有样式表的情况下渲染一个 Button 和一个 TextInput 。然后链接一个主题，再换另一个。记下哪些变了，哪些没变。

自测：Lily 组件从不附带什么？总是附带什么？

从不附带：CSS、字体、图标或图片（选择器图标除外）、英文文字、数据获取、默认语言区域或货币。总是附带：最贴切的 HTML 元素、排在第一位的 kebab-case 类名、HTML 不足之处的 ARIA、键盘行为，以及透传你的其他属性。

自测：你想给一个按钮加红色边框。应该写在哪里？

写在你的 CSS 里，针对类名（.button）或你添加的类。绝不写在组件里。

第 2 单元 — 键盘与焦点

目标： 不用鼠标使用和测试每个组件。

阅读： 以下组件的键盘交互表： TabBar、 Listbox 和 Dialog。

动手： 拔掉鼠标。在这三个页面上，用 Tab 到达演示，并完成表中列出的所有操作。打开对话框，按 Escape，记下焦点落在哪里。

自测：为什么标签栏只占一个 Tab 停靠点，而不是每个标签一个？

APG 组合模式： Tab 在控件之间移动，方向键在控件内部移动（漫游 tabindex）。有十个停靠点的标签栏会让键盘用户按十次 Tab 才能越过它。

自测：模态对话框关闭后，焦点应在哪里？

在打开它的控件上。Lily 的模态对话框使用 showModal()，它还会在对话框打开时把 Tab 限制在对话框内。

第 3 单元 — 名称、角色和状态

目标： 用你自己的措辞，为每个控件提供读屏软件可以朗读的名称。

阅读： 以下组件的 ARIA 部分： IconButton 和 SwitchButton。

动手： 在你自己的应用中运行开发服务器，渲染一个 IconButton ，但不提供它的 label。打开浏览器控制台：Lily 会警告该控件没有无障碍名称。加上标签，确认警告消失。（警告只存在于开发构建中，所以生产页面，例如本站，不会显示。）

自测：什么时候用 aria-label，什么时候用可见文字？

尽可能使用可见文字：每个人都能看到，语音输入用户也能说出来。 aria-label 只用于没有可见文字的地方，例如图标。如果两者都有，名称必须包含可见的文字（WCAG 2.5.3）。

自测：一个只用红色显示的状态。缺少什么？

文字。颜色可以重复含义，但绝不能单独承载含义（WCAG 1.4.1）；状态需要文字。

第 4 单元 — 表单

目标： 构建一个任何人都能找到并改正错误的表单。

阅读并动手： 无障碍表单教程，全部五步。

自测：表单验证失败。焦点去哪里，朗读什么？

去错误摘要，朗读其标题和链接列表，每个错误一个链接，各自通向对应字段。

自测：为什么不在表单有效前禁用提交按钮？

禁用的按钮无法说明哪里有误，很多人也不明白它为什么没有反应。

第 5 单元 — 主题与对比度

目标： 在不破坏对比度和焦点的前提下重新设计 Lily 的样式。

阅读： 主题教程 和 主题对比度 表。

动手： 用你的品牌色覆盖 --color-primary 。检查它的配对色 --color-primary-content是否达到 4.5:1，以及焦点环在页面上是否仍然清晰。

自测：你的品牌色太浅，不适合放白色文字。还能用吗？

可以，用作装饰（--lily-brand：页眉色带、分隔线、标志背景），但绝不用于文字或控件边框。文字和边框使用主题的内容配色。

第 6 单元 — 全球化

目标： 不把任何国家设为默认。

阅读并动手： 在全世界都能用的表单。

自测：为什么 CurrencyInput 没有默认货币？

任何默认值都只会是某一国的货币，在其他地方默默出错。缺少 currencyCode 是调用方的缺陷。

自测：一个阿拉伯语页面。你要设置什么，你的 CSS 又必须做什么？

lang="ar" 和 dir="rtl" （语言选择器会同时设置两者）；你的 CSS 使用逻辑属性，让布局自动镜像。

第 7 单元 — 动效

目标： 制作动画而不伤害任何人。

阅读： 动效方案。

动手： 在操作系统中开启“减少动态效果”，然后重新加载带跑马灯方案的页面。它应当静止并换行。然后用键盘到达它的暂停按钮。

自测：某个东西自动移动超过五秒。它必须具备什么？

可以暂停、停止或隐藏它的方式（WCAG 2.2.2），并且能用键盘操作，而不只是悬停。

第 8 单元 — 检查你的成果

目标： 像 Lily 测试自己的页面那样测试一个页面。

动手： 选一个你在本课程中构建的页面，做四项检查：

  1. axe（浏览器扩展，或在测试中使用 @axe-core/playwright ）：没有违规。
  2. 仅用键盘：完成每项任务，焦点始终可见，从不被困住。
  3. 缩放到 400%，并把窗口缩窄到 320 像素：没有横向滚动，没有内容被截断。
  4. 读屏软件：每个控件都有名称、角色和状态，错误会被朗读。
自测：axe 没有报告违规。页面就无障碍了吗？

尚未证明。自动检查也许能发现三分之一的问题；键盘、缩放和读屏检查能发现其余的大部分。请参阅 质量页面 ，了解 Lily 自身已验证和未验证的内容。
