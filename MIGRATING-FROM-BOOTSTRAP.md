# Migrating from Bootstrap to Lily

This guide maps common Bootstrap 5 component and class names to Lily Design System™. It is a migration plan, not a compatibility
layer: changing a class name is not enough when the component's semantics or behaviour also changes.

## Before converting markup

- Lily's headless packages ship no CSS. Pick a reference stylesheet in [`themes/`](themes/) or provide your own styles.
- Lily has no spacing, colour, display, breakpoint, or layout utilities. Replace them with product CSS.
- Visible text is content or a component prop supplied by your application. Lily does not build English labels.
- Start with the library for your framework, then follow the shared contract in [`components/`](components/).

## Worked conversion: sign-in card

Bootstrap markup often combines component and utility classes:

```html
<div class="card shadow-sm p-3">
  <div class="card-body">
    <h1 class="h4">Sign in</h1>
    <div class="mb-3">
      <label
        class="form-label"
        for="email"
        >Email</label
      >
      <input
        class="form-control"
        id="email"
        name="email"
        type="email"
        required
      />
    </div>
    <button
      class="btn btn-primary w-100"
      type="submit"
    >
      Continue
    </button>
  </div>
</div>
```

In Lily the card stays a `div.card`, the field and its button sit in a `form` named by the heading, and the visual
utilities become product CSS:

```html
<div class="card sign-in-card">
  <h1 id="sign-in-title">Sign in</h1>
  <form
    class="form"
    aria-labelledby="sign-in-title"
    method="post"
  >
    <div class="field">
      <label
        class="label"
        for="email"
        >Email</label
      >
      <p
        class="hint"
        id="email-hint"
      >
        Use the address your account was registered with.
      </p>
      <input
        class="text-input"
        id="email"
        name="email"
        type="email"
        autocomplete="email"
        aria-describedby="email-hint"
        required
      />
    </div>
    <button
      class="button sign-in-card-submit"
      type="submit"
    >
      Continue
    </button>
  </form>
</div>
```

The product stylesheet now owns `.sign-in-card` spacing and `.sign-in-card-submit` width. A Lily theme can provide
the baseline appearance without becoming a dependency of the headless library.

## Accessibility gains to preserve

- The target contract fixes the semantic element, accessible relationships, and keyboard interaction.
- Dialogs, tabs, menus, carousels, and disclosures carry explicit focus and keyboard contracts across framework ports.
- Form recipes keep visible labels and connect hints and errors with `aria-describedby`; messages remain translatable.
- Lily has not been independently audited. Test the converted journey with keyboard, screen reader, zoom, forced
  colours, and supported browsers.

## Migration order

1. Inventory Bootstrap component, `data-bs-*`, and utility classes.
2. Replace interactive components first and test their focus and keyboard behaviour.
3. Choose a theme or introduce product CSS for layout and visual utilities.
4. Replace forms as complete field compositions, including hints and errors.
5. Remove Bootstrap JavaScript and CSS only after no Bootstrap behaviour or utility remains.
