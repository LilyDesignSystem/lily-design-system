## IMPORTANT component architecture

- A component is `components/{slug}.html`: semantic HTML with ARIA, the kebab-case base class **first** in the class list, and Alpine directives (`x-data`, `x-bind`) that name a behaviour.
- Behaviour lives in `lily-alpine.js`, one `Alpine.data("lily{Name}")` per behavioural component; it exposes `x-bind` objects. Snippets contain no inline logic and no `<script>`.
- Static components (no behaviour) are the same markup as the html-headless snippet.
- Headless: no CSS, no inline styles, no text, no icons. Consumer text is slots/attributes.
- ES modules, plain JavaScript, no build step. Alpine is a peer dependency.
- Tests are vitest + jsdom: `test/mount.js` mounts the shipped snippet under real Alpine and each test drives it with DOM events. jsdom has no layout, so do not use Alpine's `.outside` modifier (it skips boxless elements); use `@click.document`.
- The pilot slice is generated by `generate-components.mjs`; edit the generator, not the output.

## Component file structure

Each component has `components/{slug}.html`, `{slug}.test.js` and `{slug}.stories.ts`.

## NO

- No CSS or styles, no images, icons or fonts, no CSS framework.
- No hardcoded user-facing strings.
- No TypeScript outside Storybook stories.

## Verify

`pnpm test`, then `bin/test` from the repository root.
