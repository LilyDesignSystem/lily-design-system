# Lily Design System™ project and healthcare audit

25 November 2026 · Repository revision `391834f044f81b6473cc75e1731ec4b8645e5d74`

**Prioritize the clinical display contracts and the examples adopters copy.** Lily already has the pieces for an accessible patient summary, medicines chart and handover. Its most consequential gaps appear when information is incomplete, withdrawn, withheld or still in transit. A year-only birth date produces an exact-looking age. A withdrawn result can still look current. The handover example announces delivery after a local state change. Each can be addressed within the existing headless architecture.

## What to build on

- **One catalog gives maintainers leverage.** The catalog has 661 entries. The generated comparison distinguishes 473 general components from 188 national identifier components and shows implementation coverage across ten web catalogs. Shared formatters, framework-specific tests and package smoke checks provide places to fix a rule once, exercise its ports and check what adopters install. Coverage varies by framework, so an adopter needs evidence for the package and version they use. [Catalog](../../../components.tsv) · [Framework comparison](../../framework-comparison.md) · [Consumer smoke check](../../../bin/smoke-packages)
- **Several clinical decisions are already well modeled.** The summary distinguishes missing allergy information from an affirmative history of no known allergies. The observation chart supplies a data table. The ward board summarizes changes in one status line. The examples have browser assertions for these behaviors. Preserve those contracts when adding new workflows, and keep interpretation, prescribing decisions and escalation policy with the adopting service. [Healthcare guide](../../patterns/healthcare/index.md) · [Clinical page tests](../../../lily-design-system-svelte-sveltekit-examples/e2e/healthcare-pages.spec.ts)
- **The project gives reviewers something to inspect.** Stable healthcare requirement IDs, a table of patient-bearing HTML attributes, an accessibility conformance report and an explicit record of missing human evidence all help a team evaluate a release. The next improvement is to show the limits of each check alongside the claim it supports. ## Findings to address first

### 1. A partial birth date becomes an exact age

**Observed in the shared TypeScript helper.** With a birth date of `"2025"` and an assessment date of `"2026-06-01"`, `ageParts` returned **17 months, 0 days**. Its string conversion accepts JavaScript's implicit January 1. A child born late that year could still be under one. The same module's `formatPartialDate` correctly displays just the year. This matters wherever a patient banner repeats a derived age as if the source supplied a complete date. FHIR R4 explicitly permits reduced date precision. [Formatter](../../../shared/clinical-format.ts) · [Age display](../../../lily-design-system-svelte-headless/components/AgeView/AgeView.svelte) · [HL7 R4 date datatype](https://hl7.org/fhir/R4/datatypes.html#date)

**Change and acceptance.** Require sufficient precision for the age being displayed. Give adopters a documented path to show the recorded birth year or month and their localized explanation when age is indeterminate. Distinguish a date-only birth record from a timestamp before displaying neonatal hours or minutes. Add shared cases for year only, year and month, date only and a timestamp with offset. A year-only fixture must never yield a precise age in the patient summary.

### 2. Withdrawal and masking need stronger observation defaults

**Observed in the Svelte and React render paths.** Both components accept `entered-in-error` and an optional `statusLabel`. With a value and no label, the ordinary value branch renders the number. A development warning calls attention to the omission, but the visible text can read like a usable result. Conversely, `masked` suppresses the value while the root still binds any supplied interpretation to `data-interpretation`. An upstream mapping that retains the flag can therefore reveal information about a restricted result in markup. The guide also describes FHIR status codes as directly mappable, although R4 includes `registered` and `unknown`, absent from the Svelte status union. [Svelte component](../../../lily-design-system-svelte-headless/components/ObservationView/ObservationView.svelte) · [React component](../../../lily-design-system-react-headless/components/ObservationView.tsx) · [FHIR mapping guide](../../patterns/healthcare/index.md#from-fhir-to-lily) · [HL7 R4 observation statuses](https://hl7.org/fhir/R4/codesystem-observation-status.html)

**Change and acceptance.** Publish an explicit mapping for every R4 status and specify how masking interacts with lifecycle status. Require localized status text in the non-final API. In a current-results view, show a withdrawal notice for an erroneous entry. An authorized history view can show the former value with a persistent explanation. Suppress record-derived flag attributes for masked results and have the service withhold restricted fields before rendering. Test text and attributes with a stale flag, a missing translation, and transitions from final to withdrawn and from visible to masked. Confirm the spoken order with a screen-reader user.

### 3. The handover example reports success before delivery

**Observed in the reference page.** Submitting the SBAR form sets a local boolean and announces “Handover sent.” There is no recipient or delivery acknowledgement. The form also has named clinical text areas and omits the submission method. If the rendered form is usable before its handler attaches, native submission defaults to GET, which can put the narrative in the URL. This second consequence follows from the markup and HTML specification. No disclosure or failed clinical handover was observed. [Handover example](../../../lily-design-system-svelte-sveltekit-examples/src/routes/handover/+page.svelte) · [Keyboard test](../../../lily-design-system-svelte-sveltekit-examples/e2e/healthcare-pages.spec.ts) · [HTML form submission methods](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#attr-fs-method)

**Change and acceptance.** Make the public demo a clearly labeled local rehearsal with synthetic text. Ensure its initial HTML cannot submit a narrative. For teams implementing delivery, illustrate pending, delivery confirmed, failed and outcome unknown, with an explicit destination and the draft retained on failure. Reserve receipt or acceptance wording for the corresponding service event. Check keyboard operation, delayed hydration, retry and a switch of patient while a draft is open. No demo path should put a field value in a URL or announce delivery.

### 4. A formatter error includes caller-supplied text

**Reproduced with synthetic strings.** The unit-mismatch branch of `meterScale` interpolates both unit strings into its error message. Supplying `SYNTHETIC-A` and `SYNTHETIC-B` returned both verbatim. Ordinary units need not identify anyone, but these parameters accept arbitrary text and an error tracker could capture a mis-mapped field. The existing mismatch test checks the error class. The privacy sentinel cases cover several other branches. The categorical assurance about formatter errors is consequently too broad. [Formatter](../../../shared/clinical-format.ts) · [Tests](../../../shared/clinical-format.test.ts) · [PHI assurance](../../../PHI.md)

**Change and acceptance.** Keep the structured reason `units` and use a constant message. Apply the existing sentinel test to every free-text error path, starting with both sides of this comparison, and check each runtime that implements it. Give reviewers a versioned test reference for HC-F8. For the separate browser-storage assurance, describe the identifier input attributes Lily sets and distinguish that verifiable behavior from what a browser or extension may retain. [Requirements HC-F8 and HC-I1](../../../spec/healthcare-ui/requirements.md)

### 5. A finite nonzero quantity can display as zero

**Reproduced at the precision boundary.** On Node 26.13.1, `formatQuantity(1e-21, "g", "en-GB")` returned `0 g`. The default formatter caps fractional digits at 20, while the API accepts finite numbers below that scale. This is a boundary defect in a general formatter. Its frequency in adopted clinical systems is unknown. It matters because downstream callers are promised preservation of the supplied value. [Implementation and display contract](../../../shared/clinical-format.ts) · [Existing formatter tests](../../../shared/clinical-format.test.ts)

**Change and acceptance.** Define the supported decimal domain and refuse inputs that would silently change magnitude. Give the caller a way to display the original exact representation when appropriate. Exercise positive and negative values on either side of the supported boundary, unequal range endpoints that would display alike, and decimal-comma locales. Verify the corresponding language ports against the same expected outcomes. Keep medication trailing-zero rules separate from a laboratory result's reported precision.

## Project-wide priorities

1. **Make release evidence answer “Which package was tested?”** The register checker validates references and citations. Its success does not execute the cited tests. Close existing tasks P48-T3 and P48-T6 together. For each safety rule publish the runtime, package version, commit, test job and outcome, including skipped checks. Use the existing pack-and-install smoke test for a consumer importing the previous and fixed versions. An adopter should be able to trace one fix from requirement to installed artifact. [Register checker](../../../bin/check-healthcare-requirements) · [Release process](../../releasing.md) · [Existing work](../../../tasks.md)
2. **Make visual and language claims specific to a usable combination.** The contrast report records AA for all 910 measured token pairs and AAA for all pairs in only 5 of 65 themes. A measured text pair tells a team little about a long translated medicine name or a multiline correction at high zoom. Add a clinical example to the theme-selection guidance. Show its ordinary, forced-colours and narrow layouts, with an RTL fixture mixing a name, number and unit. Have a fluent reviewer verify order, wording and legibility. Publish theme, locale and evidence date with the result. [Theme contrast](../../theme-contrast.md) · [Internationalization specification](../../../spec/internationalization/index.md)
3. **Give adopters one short path from example to verified installation.** The framework matrix describes source-tree package versions. The release guide separately contains dated registry observations, and the specification entry still cites 637 components in one architecture description alongside the 661-entry catalog. Generate changing counts and link one dated release matrix from both entry points. For a first clinical pilot, provide the exact package versions, supported framework, synthetic example, outstanding limitations and a traceable fix history. Measure success by having an outside team install and explain one summary without maintainer help. ## Evidence and scope

The review sampled the canonical specification, clinical requirements, Svelte and React observation code, shared formatter, SvelteKit clinical pages and their browser test source, privacy controls, theme measurements, release documentation and previous audit work.
