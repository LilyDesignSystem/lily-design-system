# Lily Design System™ production audit for healthcare

25 November 2026 · Source revision `8f5c981749a8f1cb2186cfd77b9f4379df4f3a67`

**Hold clinical deployment of the affected result, record-list and alert workflows until the adopting team verifies them against its installed packages.** A result remained visibly final after it was masked. An allergy list said “None known” beside a retained entry. An alert submitted an override reason selected on a different card. All three occurred in Chromium, Firefox and WebKit. Each could mislead someone even when the host sends the new state to the component. No patient incident was observed.

Lily is suitable for evaluating a read-only prototype with synthetic records. For a live pilot, choose one workflow, framework, theme and locale, then test the entire task with the people who will use it. The best near-term investment is testing what happens **between two valid screen states**. The repository already tests many of those states in isolation.

## Findings that affect care

The first three findings warrant a hold for the named workflow. Findings 4 and 5 apply when a service accepts translated status text or formats partial clinical dates in another calendar. These priorities reflect the possible consequence and the demonstrated behavior. The frequency in deployed services is unknown.

### 1. A mounted Web Component keeps a masked result on screen

**Observed.** I mounted `lily-observation-view` with a synthetic final value of `7.1 mmol/L` and the flag “Critical”. I set the existing element’s `status-label` to “Withheld” and its `status` to `masked`. After an event-loop turn the host said `masked`, its child still said `data-status="final"`, and the value and flag remained readable. The host retained its value attribute. A freshly mounted masked element from the same source showed only “Withheld” and removed the value attribute. The implementation builds the display in `connectedCallback` and returns if its child already exists. Its 26 existing component tests passed. [Implementation](../../../lily-design-system-web-components-headless/components/observation-view.ts) · [Component tests](../../../lily-design-system-web-components-headless/components/observation-view.test.ts)

**Consequence and fix.** A clinician can continue reading an obsolete critical result. A service that captures the DOM can also retain a value the UI was asked to remove. Make updates to the mounted element apply the same withholding rules as initial rendering. Until verified, a host using this component can replace the entire node with a freshly constructed, redacted one on result changes. The service must withhold restricted data before transmission. [Privacy guidance](../../../PHI.md) · [Worked result-withdrawal hazard](../../assurance/hazard-log-example.md)

**Acceptance.** Test the same mounted instance from final to masked, final to entered-in-error, and preliminary to corrected. Assert visible text, host attributes, rendered attributes, flag, meter and previous-value markup. Restore a permitted result and verify only the new record appears. Run against the packed Web Components library. Update the component’s testing guidance, which still describes a withdrawn value as visible by default. [Component guidance](../../../components/observation-view/index.md) · [Requirements HC-C12–C14](../../../spec/healthcare-ui/requirements.md) · [HL7 observation statuses](https://hl7.org/fhir/R4/valueset-observation-status.html)

### 2. Record lists can make mutually exclusive claims

**Observed.** In React, passing `status="none-known"`, `statusLabel="None known"` and one retained list item produced two visible items, “None known” and “Retained item”. The allergy, medication and problem lists all did this. The canonical allergy contract promises one status item in this state. Svelte also renders its children unconditionally. Its non-known-status tests supply no children. This matters when status and entries come from different requests or a patient switch leaves old children in place. [Allergy contract](../../../components/allergy-record-list/index.md) · [React list](../../../lily-design-system-react-headless/components/AllergyRecordList.tsx) · [Svelte list](../../../lily-design-system-svelte-headless/components/AllergyRecordList/AllergyRecordList.svelte) · [Svelte tests](../../../lily-design-system-svelte-headless/components/AllergyRecordList/AllergyRecordList.test.ts)

**Acceptance.** Give the host one coherent snapshot of patient, status and entries. If the host detects conflicting source information, show an explicit reconciliation state and retain the conflict for clinical review. In Lily, render item children only in the documented `known` branch and warn developers about contradictory props without logging their contents. Exercise patient A → patient B and known → unavailable → known, deliberately leaving a synthetic old child supplied. Verify the old item disappears from both the page and accessible list, and that no empty state is silently relabelled “None known”.

### 3. An alert can submit another alert’s override reason

**Observed.** In React I selected `reason-a` on card A, then rendered card B in the same component instance. B offered only `reason-b`. The selector showed its empty option. Clicking Dismiss called **B’s callback with `reason-a`** in all three browsers. The handler accepts a nonempty stored reason without checking that the current card offers it. A host trusting that callback could dismiss a warning and write an inaccurate explanation to the clinical audit trail. [React handler and form](../../../lily-design-system-react-headless/components/DecisionSupportCard.tsx) · [Requirement HC-C8](../../../spec/healthcare-ui/requirements.md) · [HL7 CDS Hooks feedback](https://cds-hooks.hl7.org/2.0/#feedback)

**Acceptance.** Key the card and its form state to the patient and card instance. Clear the selection on replacement and validate it against the active options at submission. The receiving service should verify the card, patient and reason again. Test replacement with both disjoint and identical reason codes, and removal of a selected option while a card is open. B’s callback must remain untouched until the user makes a selection on B. Check other stateful framework ports with the same sequence.

### 4. Whitespace lets a preliminary result appear without its qualification

**Observed.** React withheld the value for `status="preliminary"` with an empty label. With three spaces as the label, the same component displayed `7.1 mmol/L` and no visible status words. “Preliminary” as the label produced the expected qualified result. A blank translation can therefore make an interim result read like a final one. The withholding condition uses string truthiness. [React observation display](../../../lily-design-system-react-headless/components/ObservationView.tsx) · [Requirement HC-C14](../../../spec/healthcare-ui/requirements.md)

**Acceptance.** Check for readable text before permitting a non-final value. Test an empty string, spaces, a nonbreaking space and a meaningful translated label in each supported renderer. Verify that a host with a missing translation shows its localized unavailable-state message and still identifies which observation is affected.

### 5. A calendar conversion assigns a partial date to the wrong interval

**Observed.** The shared TypeScript formatter turns missing date fields into an internal first day or month before invoking the locale formatter. With `en-US-u-ca-hebrew`, `formatPartialDate("2026-01", locale)` returned **Tevet 5786**. The same function put 1 January in Tevet and 31 January in Shevat. The source records only January, so either month is possible. Likewise, the year-only input `2026` displayed as `5786`, although 31 December falls in `5787`. This can misstate birth or onset history in a localized summary. FHIR explicitly permits year-only and month-precision dates. [Formatter](../../../shared/clinical-format.ts) · [Requirement HC-F9](../../../spec/healthcare-ui/requirements.md) · [HL7 date datatype](https://hl7.org/fhir/R4/datatypes.html#date)

**Acceptance.** Preserve the source calendar and precision for partials, localize the wording and digits, and identify the calendar where readers could assume another. A service needing a converted interval can label both ends explicitly. Add year and month vectors spanning calendar boundaries, check full dates still localize correctly, and run equivalent cases through the C# formatter. [C# formatter](../../../lily-design-system-blazor-headless/src/LilyBlazorHeadless/Components/ClinicalFormat.cs)

## Order of work

1. **Before using an affected workflow with patients**, the adopting engineering lead should identify the installed package and exercise the matching cases above. Record the exposed screens and any temporary controls. The library maintainer should publish affected and fixed versions after checking the actual distributed artifacts.
2. **For the next clinical release**, maintainers should add the regression cases, correct the contradictory observation guidance and attach the package-level results. Reuse the existing withdrawal hazard and add the conflicting allergy list and stale override reason to the worked log. The host owns record identity, authorization, acknowledgement and follow-up. [Worked hazard log](../../assurance/hazard-log-example.md) · [ONC test-results guide](https://healthit.gov/resources/2025-safer-guide-test-results-reporting-and-follow-up/)
3. **Before widening a pilot**, the clinical safety lead and deployment owner should review residual risks, observe representative users, rehearse rollback to a verified version and assign responsibility for reviewing affected records if the display was wrong. In England, assess applicability of DCB0129 for manufacture and DCB0160 for deployment and use. The Lily assurance pack supplies inputs to that decision. [Assurance pack](../../assurance/index.md) · [NHS England clinical risk management standards](https://digital.nhs.uk/services/clinical-safety/clinical-risk-management-standards)
