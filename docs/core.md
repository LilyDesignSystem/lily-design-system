## Entry criteria

A candidate enters Core only when all three hold:

- **(a) Keyboard and ARIA-state tests in all eight libraries** (Svelte, React, Vue, Angular, HTML, Web Components, Nunjucks, Blazor). Heuristic: the component's own test file(s) in that library send a key event (a `KeyboardEvent`, `fireEvent.keyDown`, `user.keyboard`, `trigger("keydown")`, `browser.keys`, Playwright `press`, or bUnit `KeyDown`) **and** contain a line that names an `aria-*` attribute together with an assertion or query. In Blazor the key half is also waived for a component with no key handler or `.razor.js` of its own, because bUnit runs no browser, and for Nunjucks `dialog` and `alert-dialog`, which are bare native dialogs with no script. The ARIA half is waived when `AGENTS.md` says the native element needs none. The key half is waived when the component's `AGENTS.md` says it has no keyboard interactions. File level, not test level, so it is a floor, not proof.
- **(b) e2e in Chromium, Firefox and WebKit.** A Playwright spec that covers the component (its `e2e/components/<slug>.spec.ts`, or a spec naming its route or class hook) runs in an app whose config has a project for each browser.
- **(c) Its row of the [screen-reader matrix](screen-reader-matrix.md) filled** with `pass` or `minor` in all six combinations: NVDA + Firefox, NVDA + Chrome, JAWS + Chrome, VoiceOver + Safari (macOS), VoiceOver (iOS), TalkBack + Chrome (Android). An empty cell, a `fail`, or no row fails (c).
