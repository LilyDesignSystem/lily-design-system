# Lessons from the DHCW prototype kit

Give someone trying a Lily service example two things up front: a clear invitation to use made-up details and a way to abandon the attempt before submitting. For someone building their first prototype, show how to edit one page and follow both paths of a small decision. Both ideas fit the existing example apps. ## P57-T1 · Let the next participant start with a clean booking

The kit puts the research notice in its shared layout. A footer link opens a reset confirmation, Cancel returns to the originating page, and the confirmed reset regenerates the session. A participant can leave halfway through. In Lily’s SvelteKit booking, the explicit reset is “Book another appointment” on the final screen. The page asks for contact details earlier. Put the existing `PhaseBanner` before the first question and expose the existing reset logic from an unfinished booking. Keep the notice in view at each step and let the participant cancel a reset without losing their place. The booking page owns the wording and lifetime of the answers. [Kit layout](https://github.com/DHCW-Digital-Health-and-Care-Wales/dhcw-prototype-kit/blob/4fe94bca6bb99156459184e1a16778740e1b60b6/src/kit/views/kit/template.html) · [Reset handler](https://github.com/DHCW-Digital-Health-and-Care-Wales/dhcw-prototype-kit/blob/4fe94bca6bb99156459184e1a16778740e1b60b6/src/kit/middleware/reset-data.js) · [Lily booking](../../../lily-design-system-svelte-sveltekit-examples/src/routes/book-an-appointment/+page.svelte) · [PhaseBanner](../../../components/phase-banner/AGENTS.md)

Test with a made-up name and contact detail at the review step. Cancel should restore that step, its values and keyboard focus. Confirm should return focus to the start and clear previous values, validation errors, consent and reference. P54-T3 already covers what the final screen can claim. This task addresses the participant who leaves earlier.

## P57-T2 · Give a first-time author a two-outcome example

DHCW’s author guide maps each kind of edit to a file and shows how a template name becomes a URL. Its example explains exactly which files a designer can copy. Lily’s Eleventy app already provides a dev server, a shared page layout and a loader for the sibling Nunjucks macros. Its README shows a button import. Extend that guide with a small appointment enquiry: one path for making an appointment and another for changing an existing one. Give each path a destination, a heading and a way back. Show the source file, rendered URL, and which text to change. The reader should be able to build the site and follow both outcomes with JavaScript disabled. [DHCW author guide](https://github.com/DHCW-Digital-Health-and-Care-Wales/dhcw-prototype-kit/blob/4fe94bca6bb99156459184e1a16778740e1b60b6/specs/docs/make-pages.md) · [Copy instructions](https://github.com/DHCW-Digital-Health-and-Care-Wales/dhcw-prototype-kit/blob/4fe94bca6bb99156459184e1a16778740e1b60b6/examples/question-journey/README.md) · [Lily Eleventy README](../../../lily-design-system-nunjucks-eleventy-examples/README.md)

Use ordinary links for this static exercise. DHCW’s middleware merges form **and query** values into a session before the author’s routes run. That convenience would change both the hosting and privacy properties of Lily’s static examples. Lily’s booking pattern already explains when a service needs real per-step routes. Keep persistence and production hosting with the adopting service. The kit also reserves the logos from its code licence and identifies separate font terms; Lily can demonstrate the workflow with its own themes and assets.
